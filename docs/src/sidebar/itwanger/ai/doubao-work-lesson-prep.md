> 帮我按照 docs/src/sidebar/itwanger/ai/luoyang-lit-ai-bootcamp.md 这个制作一份 PPT，杂志风。

![](https://cdn.paicoding.com/stutymore/sucai-20261020065417.png)

④、带大家用派简历生成一份可以直接拿去投递的一页 PDF 简历。

## 03、生成科普视频

讲课过程中难免会遇到一些同学们没听过的专业名词，比如 ReAct、RRF、RAG、CLI、Harness 等等。

光靠口头解释很容易枯燥，我干脆让豆包工作帮我整理了一个名叫 `One Minute Remotion` 的本地 Skill，用来把单个技术概念直接生成文稿和一分钟科普视频。

![](https://cdn.paicoding.com/stutymore/sucai-20261020072324.png)

直接拿混合检索里的 RRF（倒数排名融合）来做测试，先在豆包工作里选中该技能，让它只出文案。

> 帮我给第一次接触 RRF 的同学写一分钟口播稿，先只出文案。

![](https://cdn.paicoding.com/stutymore/sucai-20261020072529.png)

不到半分钟，口播稿就出来了，把为什么不能直接加原始分数、RRF 公式怎么算以及适用边界讲得很明白。

```text
当知识库同时使用关键词检索和向量检索时，两路各自返回了一份排名，怎么把它们合并成一份最终榜单？

直接把原始分数相加是行不通的。向量检索的分数通常在 0 到 1 之间，而关键词检索的分数没有固定上限，直接相加会让总分被关键词检索主导。

解决办法是 RRF，全称 Reciprocal Rank Fusion，中文叫倒数排名融合。它不看原始分数，只看名次。一篇文档在某一路排第 rank 名，名次从 1 开始算，就拿到 1 除以 k 加 rank 的分数，常数 k 通常取 60；如果这一路没有命中，就记 0 分。

来看一组示例排名。关键词检索的前三名是文档 A、文档 B、文档 C；向量检索的前两名是文档 B、文档 C，文档 A 没有命中。

文档 A 只在关键词检索排第 1 名，得分是 1 除以 61 加 0，约为 0.0164。文档 B 在两路分别排第 2 名和第 1 名，得分是 1 除以 62 加 1 除以 61，约为 0.0325。文档 C 两路相加约为 0.0320。

最终，被两路共同认可的文档 B 和文档 C 升到前两名，单路第一的文档 A 退到第 3 名。不过 RRF 只看名次、不读正文内容，通常用来做多路检索的快速粗排。
```

把文字稿保存到本地后，我们继续推进，让豆包工作把文字稿变成二哥声音的完整配音，检查有没有漏字、重复或术语读错，并测出实际时长。

> 文字稿已经保存到 docs/src/ai/one-minute/rrf.md，下一步。

![](https://cdn.paicoding.com/stutymore/sucai-20261020082901.png)

配音很快完成，豆包工作调用我本机的二哥音色按 1.1 倍速合成了音频，8 段旁白实测总时长 66.1 秒，每段的精确时长都列在了表格里。

![](https://cdn.paicoding.com/stutymore/sucai-20261020083545.png)

同时它把生成的 `voiceover.wav` 和 `voiceover.mp3` 音频卡片交给我试听，并主动停在当前阶段等待确认。

![](https://cdn.paicoding.com/stutymore/sucai-20261020083713.png)

试听确认读音和节奏都没问题后，我回复“下一步”进入分镜设计。

![](https://cdn.paicoding.com/stutymore/sucai-20261020083906.png)

分镜的主要工作是根据脚本和实测音频的 1984 帧时间轴，把画面主体、连续动作和镜头设定好，生成 `OUTLINE.md` 分镜文档。

豆包工作把整条视频划分为开场问题、原始分数尺度对比、RRF 定义、倒数计分公式、示例排名、文档 A 得分、文档 B 与 C 得分以及最终结果边界共 8 个叙事单元，沿用暖米色底板搭配铁锈橙、蓝色与深色正文，让文档 A、B、C 的代表颜色和排名换位动画逐帧对应，同时标明教学示例排名，避免被误认为真实模型输出。

![](https://cdn.paicoding.com/stutymore/sucai-20261020084147.png)

确认分镜没问题，再点“下一步”进入 Remotion 动画编码与字幕制作。

![](https://cdn.paicoding.com/stutymore/sucai-20261020084451.png)

制作完成后，我让豆包工作启动 Remotion Studio 打开预览画面。

![](https://cdn.paicoding.com/stutymore/sucai-20261020100042.png)

它在检查 3210 端口时发现服务曾随管道退出，自己排查后台日志后改成重定向输出重新启动，确保预览服务持续运行。

![](https://cdn.paicoding.com/stutymore/doubao-work-lesson-prep-20261020101726-88321c5f.png)

我录了个屏，大家看一下效果，感觉还是非常丝滑的。
