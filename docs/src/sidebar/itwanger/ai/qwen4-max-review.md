## 01、露娜守城

先声明一下，四个案例都是我在 Qoder 里让 Qwen4-Max 从零写出来的，没给任何现成的模板代码，也不允许调用外部的生图接口。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117135641.png)

第一个案例，先上点难度，一个规则特别多的塔防游戏。我让 Qwen4-Max 在单个 HTML 文件完成的初版《露娜守城》，不引用外部图片和音频，画面与音效全部用代码生成。

【录屏：露娜守城】

核心提示词就下面这些。

```text
请用一个单独的 index.html 文件写一个「露娜守城」塔防小游戏，不引用外部图片或音频，全部画面和音效用 Canvas 2D 与代码生成。
包含 16×10 网格山道、10 波地面与飞行怪物（含石巨人与影龙两个 Boss）、箭塔与炮塔两种基础塔。
支持消耗月石注入火（无视护甲）、冰（减速）、雷（连锁）三种元素；两座相邻 2 级异元素塔按住 Shift 点击可合成为蒸汽塔、等离子塔或暴风雪塔。
可免费布置骑乘白狼的英雄露娜，支持普攻月刃弹射、大招月蚀天降 10 道月光与全场冰封技能。
```

当然了，需求是我让 Grok bot 整理了一版，然后让 Codex 审查了一版。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117135803.png)

毕竟现在的模型在编码层面已经很强了，但需求和创意需要我们先提供好，否则做出来的就是个垃圾。

第一版的完成度就很高，出怪节奏、基础塔防、元素注入、高阶合成塔、露娜的四连弹射，以及月蚀和冰封两个主动大招全都能正常运行，连攻击音效都是用代码实时合成的。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117140035.png)

玩法很简单。

右侧选箭塔或炮塔，点草地就能建；点已有的塔按 U 升级，按 Z、X、C 分别注入火、冰、雷；两座相邻的二级塔注入不同元素后，按住 Shift 依次点击，就能合成蒸汽塔、等离子塔或暴风雪塔。空格开始下一波，E 放月蚀，W 放冰封。

最爽的是第十波影龙出场的时候，先按 W 把全场冻住，再按 E，天色一暗，十道月光从天上砸下来，那一下真的很有当年的感觉。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-02-boss-battle-v2-20261117142750-de814b93.gif)

这个游戏我打算长期维护下去。灵感来自于 war3 冰封王座中 Dota1 的那个塔防游戏，像我这样的 18 岁小年轻应该印象深刻。

反正我当年上大学的时候，是狠狠玩了。

经典无需多言。

## 02、3D 香蕉越野车

测完二维游戏，接着测三维建模，让 Qwen4-Max 用 Three.js 从零做一辆既好看又能开的香蕉越野车。

【录屏：香蕉越野车】

核心提示词如下。

```text
用 Three.js 从零制作一个可实际驾驶的 3D 香蕉越野车交互网页，所有零件程序化建模，不使用外部模型或贴图。
页面做成暖白复古工业设计图纸风格，整根弯曲香蕉作为船形车身，配单座座舱、黑色钢管底盘、深蓝块状越野胎与橙红螺旋弹簧。
支持展示环绕与 WASD 驾驶双模式，车轮滚动、前轮转向、车身俯仰侧倾与悬挂压缩实时联动。
左下放速度与转速双指针实体仪表盘，右下放线框、车壳透明透视、自动环绕与合成引擎声四个机械拨杆开关，兼容手机竖屏触控。
```

这次 Qwen4-Max 用代码生成了 `23334` 个三角形，弯曲上翘的香蕉船形车身、深褐色的果蒂、果皮上的斑点、黑色的钢管底盘和凸起的越野胎纹全都做出来了，再配上暖白纸纹和黑色描边，很有手绘工程图纸的味道。

切到驾驶模式按住加速键往前冲，左下角速度表和转速表的指针会一起摆动；拨一下右下角的透视拨杆，黄色车壳会变成半透明，底下的转向拉杆和螺旋弹簧看得一清二楚。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-03-banana-structure-v2-20261117142751-306d75c0.gif)

打开声音拨杆，还有一段用代码合成的引擎声，音调会跟着转速一起变高。

一根香蕉开出了“轰轰”的动静，莫名有点喜感。

## 03、鹈鹕骑车穿越九种画风

“鹈鹕骑自行车”是大模型圈子里的老题了，但这次，我把难度提高了，不仅能骑车，还要穿越不同的手绘风背景。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117133424.png)

核心提示词。

```text
用纯 JavaScript 和 Canvas 2D 制作一段约 108 秒无缝循环的连续艺术动画，配 WebAudio 实时合成配乐与环境声。
主角是一只戴蓝围巾的白鹈鹕骑着红橙色自行车向右行进，双腿与脚踏曲柄联动，车轮转速与地面滚动速度严格匹配。
每隔约 12 秒依次穿过童年蜡笔、铅笔速写、金色木刻、炭笔暴风雨、透明水彩、民俗装饰、印象派夕阳、深蓝夜港、星空粉笔九个世界。
转场采用一道从右向左扫过的撕纸分界线，分界两侧执行不同的绘制逻辑，鹈鹕跨过分界线时左右两半同步呈现两种画风。
```

这个作品最考验功力的地方就在转场，给同一套背景换九种滤镜颜色是糊弄不过去的。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-08-pelican-transition-v2-20261117142753-6b643e04.gif)

撕纸边扫过来的那一刻，鹈鹕会被一分为二，前半身已经进了新世界，后半身还留在旧的画风里，但它脚下的节奏一点没乱。

声音也是代码现场合成的，每一章都有自己的旋律，背景里还有风声、雷雨声和车铃声，换章节时音乐会跟着淡入淡出。

九个世界里，我最喜欢的是民俗装饰和深蓝夜港。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117140746.png)

民俗那一章有大花树、大象、人物和鸟鱼纹样；夜港那一章有灯柱、船帆、灯火，水面上还有反光，鹈鹕骑着车从港口穿过去，安静得让人想多看几遍。

## 04、纯代码绘画

前三个案例偏动态，第四个案例专门测它用纯代码作画时，在构图和笔触质感上能做到什么水平。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117133938.png)

提示词如下所示。

```text
用纯 JavaScript 在 Canvas 上实现一个三联作代码画廊，不调用生图服务、不读取任何外部图片，所有云朵、花瓣、人物和纸纹全部由代码逐笔绘制。
统一采用彩铅颗粒加厚涂短笔触质感，输出 960×1920 竖版分辨率，支持输入固定随机种子复现与无水印 PNG 原图导出。
三幅画作分别为《风筝与夏天》（钴蓝天空积云、红橙菱形风筝与雏菊草地）、《流星经过花田》（靛蓝银河、金色流星与树林剪影）、《旷野中的旅人》（草原土路与戴斗笠持剑红围巾旅人背影）。
采用每帧分批绘制防止阻塞页面，实时显示绘制进度与笔触数量。
```

模型没有拿几块扁平的渐变色块应付，而是老老实实在竖版画布上画了 `3.7` 万到 `5.6` 万道带方向的短笔触。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117134100.png)

打开全屏预览放大看，能看清天空里横向的擦痕、银河里细碎的星尘、草地上的白色雏菊，还有旷野旅人斗笠下飘起的红围巾。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-20261117140844.png)

平心而论，程序模拟出来的彩铅颗粒和画师的手绘原稿相比肯定还有差距，人物也只是风格化的背影，但靠 JavaScript 代码就能画出三幅构图干净的作品，审美水平确实让我刮目相看。

## 05、跑分

案例看爽了，再简单瞄一眼跑分。

在考察 Agent 工程编码的 DeepSWE v1.1 上，Qwen4-Max 拿到 `75.7` 分排第一，比 GPT-6.1 Sol 和 Opus 5.5 都高一点；在考察长周期复杂任务的 Agents' Last Exam v1.1 上同样排第一；在全球前端盲测榜 CodeArena WebDev 里排到第六，刷新了国产模型的最好名次。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-04-official-benchmarks-20261117142053-9da352e7.gif)

激活参数少了四分之一，能力反而更强，秘密主要在三处改动：

- 长上下文更省算力：大部分层用线性注意力，把读过的内容压缩成一份固定大小的摘要，少数层再回头精读最相关的片段，一百万的上下文窗口里注意力仍然能集中。
- 常见的词组直接查表：遇到常见的句式和函数写法直接查表，省下来的算力留给真正难的推理。
- 训练更稳：残差通道从一条扩展到了四条。

![](https://cdn.paicoding.com/stutymore/qwen4-max-review-05-architecture-20261117142053-06fae23a.png)
