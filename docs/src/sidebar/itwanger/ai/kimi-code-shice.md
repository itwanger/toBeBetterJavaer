大家好，我是二哥呀。

看到 Kimi Code 桌面版发布的第一时间，我就下载到本地安装起来体验了。之前用过 Kimi 的网页版和命令行版，但桌面版是第一次。

整体干活的能力我还是很认可的，而且给我的感觉和网页版完全不一样。

![](https://cdn.paicoding.com/stutymore/sucai-20260918145847.png)

设计很简洁，没有多余的功能。

现在很多 work 类的桌面 Agent 都设计得太复杂了，乱七八糟的功能一大堆，实际上很多都用不到。Kimi Code 这种极简风反而更符合我的诉求。

打开就是一个对话框，选好模型，输入需求，剩下的交给它。权限模式可以设成「完全自动」，Kimi 会自己规划任务、执行代码、启动预览服务、截图自检，全程不需要一步步确认。

目前可选的模型有 K3 High、K2.7 Code Highspeed 等。K3 是主力，质量高但速度偏慢。K2.7 是高速版，跑得快但出活粗糙一些。

先上一个我用 Kimi Code + K3 制作的赛博朋克像素街区。

【录屏】

感觉这种画质还是挺可爱，挺有水平的。

接下来给大家演示一下我的整个制作过程。

## 01、赛博朋克像素街区

提示词我贴在下面了，大家可以参考一下。

```
我想要的效果像一幅活起来的横向像素电影：深夜旧城区，三四层拥挤建筑，一层有旧机械修理铺、拉面店和自动售货机，楼上有空调、管线、窗户和晾衣架。青蓝、琥珀与少量品红霓虹照亮街道及人物，湿润路面有克制的反光，远处楼群、近处栏杆形成景深。加入蒸汽、少量雨丝、闪烁招牌和行走路人，画面精致、有生活气息，避免只有一排方块楼和几个发光矩形。
```

![](https://cdn.paicoding.com/stutymore/sucai-20260918115618.png)

AI 做前端场景这种活，描述越具体，出来的效果越接近预期。Kimi 拿到提示词之后，花了大概一分钟的时间去思考。

![](https://cdn.paicoding.com/stutymore/sucai-20260918115752.png)

这个我觉得很重要。

肯定要先 plan 计划好，然后再开工，否则容易返工。

等思考清楚了，就开始布置任务、按步骤完成了。先搭建 Vite 项目结构，然后依次写 textures.js 处理贴图、street.js 搭建街景、characters.js 创建人物、particles.js 做雨丝和蒸汽，最后在 main.js 里跑主循环。一共五六个文件，分工很清楚。

![](https://cdn.paicoding.com/stutymore/sucai-20260918115900.png)

Kimi Code 这里有一个挺有意思的设计，可以把一个进行中的任务放到后台，然后点击查看的面板也设计得很合我的心意。

![](https://cdn.paicoding.com/stutymore/sucai-20260918120402.png)

大概等了十来分钟，纯代码版的画面出来了。

![](https://cdn.paicoding.com/stutymore/sucai-20260918131856.png)

用的是 Vite + Three.js，所有建筑、人物、招牌贴图全是程序化生成的，没有用任何外部图片。

深夜街区的氛围有了，霓虹灯的青蓝色和琥珀色也在闪烁，雨丝斜着从天上落下来。

![](https://cdn.paicoding.com/stutymore/sucai-20260918131918.png)

但说实话，离我的预期还是有比较大的差距。

所以我让 Kimi Code 补充了新的美术素材，先从人物开始。

![](https://cdn.paicoding.com/stutymore/sucai-20260918133002.png)

然后是街景环境图。

有了高质量的美术素材之后，画面的层次和质感就完全不一样了。原来纯代码画的盒子楼换成了真正有材质、有污渍、有管线细节的建筑立面，一眼就能看出差距。

![](https://cdn.paicoding.com/stutymore/sucai-20260918133017.png)

素材到位之后，Kimi 很快完成了构图和光照的调整。

技术方案是 Canvas 2D 分层合成，环境图作为背景层铺满画布，角色图集按行走帧裁切后放在中间层，主角有四帧行走动画，四个 NPC 各有独立造型。最巧妙的是前景层处理，Kimi 把环境图里护栏那一条单独裁了出来，盖在角色上面，角色走过护栏的时候脚会被遮住，这个遮挡关系让画面的空间感一下就有了。

![](https://cdn.paicoding.com/stutymore/sucai-20260918132013.png)

有任何细节需要调整，可以立即打断 Kimi Code，它会马上响应。

![](https://cdn.paicoding.com/stutymore/sucai-20260918132210.png)

最终效果出来了，再来看一下。

![](https://cdn.paicoding.com/stutymore/sucai-20260918151244.png)

六家店铺错落排开，从左到右分别是 TOOLS、MECHA、JUNK & GOODS、MEDS、FOOD、RECYCLE，每家都有自己的招牌颜色和灯光。按 A/D 控制角色左右行走，镜头会平滑跟随。靠近店铺按 E 能打开交互面板，里面有商品列表和价格，点击还有对应的反馈。

右上角可以切换雨天模式，开启后会有雨丝和地面冷色调罩层。护栏下面能看到一层透出暖光的地下空间，右侧挂着一面红色的「BEST REPAIR SHOP」旗帜。

从输入提示词到最终交付，大概花了 40 多分钟。其中纯代码版大概 15 分钟就跑出来了，后面大部分时间花在补充素材和调整细节上。

## 02、自定义供应商

不得不说，现在的 Agent 产品为了俘获用户的芳心，是真的很能卷。

这不，Kimi Code 也支持自定义模型了。

打开设置，进入供应商。

![](https://cdn.paicoding.com/stutymore/sucai-20260918113531.png)

找到 DeepSeek，填入 API Key，点击导入。整个过程不需要手动配置 endpoint 地址，Kimi Code 已经内置了主流供应商的 API 地址。

![](https://cdn.paicoding.com/stutymore/sucai-20260918113704.png)

把 DeepSeek 目前能用的模型都弄过来了，但其实只保留 DeepSeek V4.1 Flash 就行了。这个模型目前是我的第一优先级备用模型，速度快，便宜，中文能力也足够好。

![](https://cdn.paicoding.com/stutymore/sucai-20260918113804.png)

OK，删掉其余的，保留这一个。回到输入面板，精选一下 DeepSeek，就可以在模型切换这里看到了。

![](https://cdn.paicoding.com/stutymore/sucai-20260918114542.png)

有时候 K3 太慢了或者在排队，直接切到 DeepSeek V4.1 Flash 继续干活，不耽误事。

对于那些已经习惯了某个模型的小伙伴来说，Kimi Code 不强制你只用 Kimi 自己的模型，这一点我觉得很加分。

## 03、鹈鹕骑自行车

提示词是这样的。

> 用单个 HTML 和 SVG 做一只鹈鹕骑自行车的循环动画。鹈鹕有长喙、喉囊和翅膀，身体坐在车座上，翅膀扶住车把，双脚始终踩着踏板。画面干净、有幽默感，背景移动表现前进。提供速度滑块和暂停按钮，调速后动作仍协调。不要使用外部图片。

我分别用 K2.7 Code Highspeed 和 K3 High 跑了同一个提示词，一个字都没改。

结果差距还挺大的。

### K2.7 高速版

先试的 K2.7。

![](https://cdn.paicoding.com/stutymore/kimi-code-shice-20260918163401.png)

视觉效果只能说勉强及格。鹈鹕的身体比例偏机械，红色的车架颜色过于鲜艳，腿部像两根橙色的直棍在那绕圈，整体给人的感觉就是「能跑，但不好看」。

### K3 High

然后换 K3 High。开了一个新的 Kimi Code 会话，同一个提示词一字不改直接发过去，连工作目录都换了个新的，确保没有任何上下文污染。

【视频】

坐垫露在外面，动画流畅运行，功能完整。

画面质量差距肉眼可见。

K3 版本的鹈鹕有圆润的白色身体，优雅的长颈伸向前方，大大的橙色喉囊鼓鼓的，很有辨识度。绿色的自行车架比例协调，轮毂细节清楚。背景有云朵、太阳、绿色山丘和树木在做视差滚动，路面有灰色标线向后移动，前进感很强。

技术实现上也挺讲究的。整个动画只有一个时钟源，就是踏板的曲柄相位角。车轮转角按齿比 22:9 换算，背景滚动速度等于轮子的线速度。所以不管你把速度调到多少，踏板、车轮、背景始终是同步的，不会出现踏板转完了车轮还没跟上的情况。双腿用两段式逆运动学计算膝盖位置，所以脚永远踩在踏板上，腿部的屈伸完全由踩踏相位自然驱动。

最让我乐的是两个幽默细节。

喉囊里露出一截晃动的小鱼尾巴，画面左下角滚过一行文字「鹈鹕通勤中·百公里油耗：两条鱼」。

![](https://cdn.paicoding.com/stutymore/kimi-code-shice-20260918163545.png)

我把速度从 0.2x 拉到 3x 试了一圈，踏板、车轮、背景全部同步。暂停的时候画面完全定格。继续播放后从原来的位置接着走，不瞬移。

当然，K2.7 的优势是快。

K3 跑这个鹈鹕大概花了七八分钟，K2.7 两三分钟就出来了。如果你的任务对视觉质量没那么高的要求，比如做个原型验证一下思路，K2.7 高速版确实能省不少等待时间。只是如果你想一次出成品，还是 K3 靠谱。

## ending

正如我之前说的，今年的模型都是小版本优化。

说实话，从 Opus 4.6 往后，我并没有感觉到 Anthropic 在模型能力上有多大的提升，可能代码能力是提高了，但文本能力拉成了 GPT，再也不会说人话。

而 Harness 成了今年下半年的主角。

不管是 DeepSeek Harness，还是 Kimi Code，都是在做工程上的优化，让模型能发挥出它该有的功力。

Kimi 在前端能力上确实有一手。从赛博朋克和鹈鹕两个 Case 的表现来看，K3 的图形编程和审美水平让我挺惊喜的。整套工作流跑下来确实有点 Codex 的味道了。

但 Kimi 目前的问题也很明显，慢，贵。赛博朋克那个 Case，K3 从输入到出活要等很久。K2.7 高速版虽然快，但从鹈鹕那个测试来看，质量上还差了一截。

总的来说，Kimi Code 桌面版还是挺能干活的。

继续往前冲吧，Kimi。

我们下期见。
