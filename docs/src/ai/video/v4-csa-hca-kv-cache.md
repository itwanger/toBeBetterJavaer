在大模型推理时，KV Cache 的显存占用等于单个 Token 的 KV 体积乘以 Token 数量。

在 V3 时代，为了应对 128K 的上下文，DeepSeek 推出了 MLA（多头潜在注意力） 机制，其核心逻辑是通过低秩投影来压缩单个 Token 的 KV 映射维度。

但到了 V4 时代，上下文窗口直接飙升到了 1M（百万级），Token 数量暴涨了 8 倍。面对如此恐怖的规模效应，单靠 MLA 压缩单份数据的大小已经触及物理极限。

因此，V4 转换了技术路线，从【空间压缩】走向了【拓扑复用】：它引入了全新的 CSA（Cross-Layer Shared Attention，跨层共享注意力） 和 HCA（Hierarchical Compressed Attention，分层压缩注意力）。

这套架构打破了传统 Transformer 每层都必须独立存储 KV 的限制，直接在层与层之间、以及不同层级间共享和复用 KV 份数。这正是 V4 能在有限显卡容量下吞下百万上下文的关键。

先说第一件事，MLA 为什么不够用了。

看过我们之前视频的你应该已经知道了，大模型在推理时要把每个 token 的 KV 向量存到显存里，这就是 KV Cache。

在传统的 MHA（Multi-Head Attention，多头注意力）机制下，假设模型配置了 128 个注意力头，每个头 128 维，这意味着它的总隐藏层维度高达 16384 维。那么在推理时，每个 Token 在每一层都必须记住一套完整的 K 和 V 状态。它们各自对应一个 16384 维的特征向量，两者相加，单层、单 Token 的存储维度就直接飙升到了 32768 维！

![](https://cdn.paicoding.com/stutymore/v4-csa-hca-kv-cache-20260821105221.png)

MLA（多头潜在注意力）的核心原理是通过低秩压缩，将原本每层高达 32768 维的 KV 特征动态投影到一个 576 维的低维潜在向量（Latent Vector） 中。显存不再死板地存储海量的 KV，只存这个精简的小向量。等到实际计算注意力时，再通过矩阵乘法把它解压还原。

![](https://cdn.paicoding.com/stutymore/v4-csa-hca-kv-cache-20260821105441.png)

但问题是——每个 token 还是要存一份数据。上下文 100 万个 token，就是 100 万份。V3 在 100 万上下文下，KV Cache 大约要 84 GB 显存。什么概念？一张顶配的 H100 显卡也就 80 GB，一个请求就把一整张卡吃满了。

MLA 把每份数据压小了，但份数没变。

【截图：MLA 压缩瓶颈；风格：whiteboard；截图目标：左边一列 100 万个窄条（代表 576 维的 latent 向量），右边标注"条数没变，显存还是 84 GB"；关键词：维度压缩 57 倍、token 数不变、显存随上下文线性增长】

那聪明的你肯定想到了：单份数据已经压到头了，再压，模型回看前文就看不清了，回答质量会掉。那能不能换个方向，减少要存的份数？

V4 的答案是——能。靠两个新机制：CSA 和 HCA。

CSA，Compressed Sparse Attention，压缩稀疏注意力。做两件事。

第一件，压缩。每 4 个相邻的 token 合并成 1 份。100 万份变成 25 万份。

第二件，稀疏。加了一个索引器，你可以把它理解成书的目录，算注意力的时候不是 25 万条全看，而是给每条打分，只挑最相关的 512 条来计算。

HCA，Heavily Compressed Attention，重度压缩注意力。压得更狠——每 128 个 token 合并成 1 份。100 万份变成不到 8000 份。因为数量已经很少了，不用挑了，全部保留，每份都看。

【截图：CSA vs HCA 压缩流程；风格：swimlane；截图目标：两条泳道分别展示 CSA（100万→25万→512条）和 HCA（100万→8000条→全看）的压缩路径；关键词：4合1、索引器 top-512、128合1、全量注意力】

听到这你可能会问：CSA 只挑 512 条，不怕漏掉关键信息吗？HCA 把 128 个 token 揉成一份，细节不都糊没了吗？

恰恰相反。HCA 的每一份，单看确实不细，但每一份都装着一小段原文的大意，8000 份全拼起来，整篇文档的骨架就在了。CSA 的每一份细，量太大看不过来，才需要挑着看。所以两种层在模型里交替排列——CSA 层看细节，HCA 层看全局。

打个比方。CSA 是你的课堂笔记——每 4 分钟记一段，复习的时候只翻跟考题相关的几页。HCA 是课程大纲——一节课浓缩成一句话，随时能纵览整学期讲了什么。

两套机制一叠加，V4 Flash 的 KV Cache 只有 V3 的 7%。100 万 token 的上下文，从 84 GB 压到不到 6 GB。

那聪明的你肯定又要问了：7% 对我们开发者有什么用？

同一张 GPU 卡，显存是固定的，同时跑的每个请求都要占一块。以前一个百万 token 的请求就吃掉一整张卡，现在只占零头，一张卡能同时服务十几个请求。这也是 V4 敢把上下文窗口默认开到 100 万的底气——不是技术上做不到，是以前存不起。

哪怕涨了价，V4 Flash 高峰期未命中输入 3 元每百万 token，在百万上下文这个量级，行业里依然非常有竞争力。

上期讲的 Prompt Cache 省的是重复计算的钱，这期的 CSA 和 HCA 省的是存储空间的钱——两招叠加，才撑得住百万上下文的商业化。另外，选模型别光看上下文窗口长度，看注意力架构——窗口开到 100 万不难，用得起才难。
