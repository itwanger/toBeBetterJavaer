# Vibe 知识大赏：1至2分钟科普视频

从主题或现成文字稿生成完整的1至2分钟科普视频，覆盖文字稿、配音、分镜、动画、字幕和出片。内容是小学、初中、高中的数学、物理、化学、生物知识点，以及 RRF、RAG、ReAct 这类 AI 概念。一条视频让第一次接触的人看懂一个知识点。Skill 名称沿用 `one-minute-remotion`，文字稿目录和共享入口不变，制作项目集中在 `script/one-minute/`。文字由用户决定，声音沿用二哥现有配置，画面实际接入花叔动画库，采用适合概念的连续运动。用户一次列出多个知识点（如 RRF、RAG、ReAct，或勾股定理、相似三角形），默认分别制作，每条独立，不把几个知识点塞进同一条。

## 触发与分工

用户提到“Vibe 知识大赏”“知识点短视频”“一分钟或两分钟科普视频”“课堂插播的概念短片”，或明确调用 `one-minute-remotion` 时使用本 Skill，最终目标是完整视频，默认分阶段推进。文字稿是制作过程中的一个环节，支持当前 Agent 起草、润色或接收外部稿件。

本系列稿件（`docs/src/ai/one-minute/` 下的文件，或要做成本系列视频的稿子）的新写和润色都由本 Skill 负责，按 [写稿风格](references/narration.md) 执行。AI 长视频的口播稿仍使用 `video-script`。已明确属于本 Skill 的视频项目，用户要求先做文字稿、分镜或其他阶段时，只完成指定阶段。普通长视频沿用 `ergo-remotion-video`。

## 阶段推进规则

**“下一步”只推进一个阶段；动画阶段每次只推进当前章，交付后立即停下。** “继续”“接着做”未指明范围时，也受当前阶段与逐章确认停点约束；不能因最终目标是视频、历史上授权过整片制作或创建了全流程任务清单，就继续执行余下阶段。用户最新的阶段限制优先。

五个阶段依次为：①文字稿保存；②配音生成与实测时长；③按实际配音设计分镜并分章；④逐章有声预览、返修与确认，再整片有声预览；⑤最终导出与验收。读取源稿、现有产物和进度，完成下一个未完成阶段；当前阶段未完成或正在返修时，先续完当前阶段，不跳过问题或重做已验收内容。任务清单只包含本轮阶段及其必要准备，后续阶段可注明待用户继续，不能自行启动后台任务。

用户说“文字稿已经保存到 docs/src/ai/one-minute/rrf.md，下一步”时，文字稿阶段视为已完成；读取并检查文件后直接进入②。项目初始化、源稿快照、口播提取、文字锁定、读音处理、完整配音、对齐及量时都属于②的必要准备和执行，不单独耗掉一次“下一步”。**配音完成后交付可试听的完整音频、文件路径、实测时长与待核对项，然后结束本轮，等待用户试听；不写分镜、不制作动画、不预览或导出MP4。** 不把生成成功说成用户已试听通过。

配音已试听确认后，用户再说“下一步”进入③，只交付 `OUTLINE.md` 分镜：按完整语义分为约30秒一章，通常25～35秒，尾章可以短一些，不硬切句子或因果动作。分镜确认后进入④，**每次只实现当前一章，首轮即交付带对应配音、字幕与动画的 Remotion Studio 有声预览，然后停下。用户确认本章通过并继续后，才制作下一章；提出修改时只返修当前章。** 不一次实现余下各章，不以无声动画或截图代替预览。全部章节通过后，先交付整片有声Studio预览并等待确认；整片通过且用户明确要求“出片”或“导出视频”时才进入⑤。普通“下一步”不自动触发导出。具体分章、音轨偏移、确认与接力规则见[逐章有声预览](references/chapter-preview.md)。只有用户明确要求跳过逐章确认、连续完成指定范围时，才按该范围串联制作。

每次结束时在项目现有进度文件中记录本轮阶段、当前章、已通过章节、实际产物、未完成检查及下一步；没有进度文件时使用 `PROGRESS.md`。分别记录“配音已生成/已认可”“本章有声预览待确认/用户已通过”“整片预览待确认/已通过”，不能用自检代替用户确认，方便其他 Agent 接力。

## 输入与范围

- 用户要求润色、调整现成文稿时，按 [写稿风格](references/narration.md) 的润色规则修改，交付时逐条列出改动；润色完成即为①的交付，停下等用户确认。
- 用户提供现成文稿要求照稿制作时，无论由用户本人、Gemini、豆包工作、Claude Code、DeepSeek Harness 或其他模型编写，都把它作为只读真源。用户说“按这份做视频”即已认可该稿，不再机械地重复确认。保留原文、标点、数字、大小写与例子；技术疑点及依据、实测时长单列，不擅改源文件。**不提供删减建议、可删内容清单、精简稿或缩短文稿方案**，超时只报告实际时长及超出秒数。
- 只有主题时，由当前 Agent 按 [写稿风格](references/narration.md)直接起草，无需先转交 Gemini。动笔前先读范例 `docs/src/ai/one-minute/what-is-pythagorean-theorem.md`。用户指定其他工具写稿时，提供该文件里的通用提示词，或在具备相应工具与授权时调用；只按实际执行记录说明稿件来源。
- 当前只要求创建 Skill，或在本视频流程中先做文字稿、分镜，就完成这一范围；“下一步”按阶段推进规则执行，不自动扩大到整片制作。动画阶段按约30秒的审片章节逐章推进，不要求画面显示长片的多章导航；明确授权连续完成时才串联对应范围。
- 默认 1920×1080、30fps，时长目标1至2分钟，上限120秒（`one_minute.py lock` 默认 `--target-sec 120`）。新写正文通常300至550字，给动作和阅读留出余量。**文字完整优先于时长目标**：实测超过2分钟仍保留全文、完整配音和原语速，报告总时长及超出秒数；后续获准制作的阶段按实际音频长度安排，不为凑时长精简、漏读、截断或加速。用户另行明确要求某个精确时长时，若与完整稿件冲突，只说明实际时长与要求的冲突，保留原稿等待用户指示，不附删减方案。

## 保留什么，替换什么

- **文稿**：以 [写稿风格](references/narration.md) 为准：入口、名词、结论、例子、为什么成立、收尾六段结构，公式写成念法，推理不跳步。不继承 `video-script` 的950至1800字、三层递进、固定自我介绍、闯关和关注收尾。
- **声音与工程**：复用 `ergo-remotion-video` 的项目快照、二哥音色、读音词典、TTS、逐词对齐、字幕及导出验证。配置从本机现有默认或用户指定项目读取，不能换成花叔、系统、商用默认或另一个复刻声音。不要为了赶时长提高当前项目语速。
- **画面**：从 `huashu-art-motion` 选择一套具体动画语法，读取对应语法卡。默认暖米几何画风沿用二哥共享色板 `C`；用户选择[孟菲斯画风](references/style-memphis.md)或[超级玛丽画风](references/style-super-mario.md)时使用各自独立色板加项目内覆盖值，不改共享 `C`。实际调用随包提供的形变、描画、公式和世界相机库，或按对应配方接入上游渲染器。Canvas 画面接到现有 React/Remotion 时间轴，声音、字幕与导出沿用本流程。不能只引用“同例贯穿、连续变化”等原则却仍交付文字卡轮播；不复制作者角色或示范片。
- **本流程的布局优先**：画面只留对象名、公式、数值和必要短标签；字幕已有的整句、问句、结论及其近义改写不再叠到主画面。解释交给旁白与字幕，因果交给动画。不强制长片顶部多章导航、页框、满屏文字卡、进度闯关和推广尾段。保留简短主题标识与字幕安全区；不要为“动态”加无意义的漂浮、抖动、粒子或每镜推近。
- **手机观看优先**：采用[本系列视觉规范](references/visual-style.md)，不直接套用长片的较小字号。1920×1080 起点为对象标签48px、数学符号60px、核心公式84px、字幕48px；标题只写当前知识点，不自动加“Vibe知识大赏”、期数或问句。长字幕按完整语义依次显示，不缩小字号硬塞。
- **画风选择**：提供暖米几何、孟菲斯、超级玛丽三种画风；已有项目沿用已确认画风，新项目默认暖米几何。用户说“孟菲斯”时读[孟菲斯风格卡](references/style-memphis.md)及[已确认案例](references/approved-memphis.md)。用户说“超级玛丽风格”时读[超级玛丽风格卡](references/style-super-mario.md)，采用原创像素角色、横版场景和有因果的动作反馈，在分镜与来源记录写明 `style: super-mario`；研究依据见[参考拆解](references/study-super-mario.md)，尚无已确认样片。三种画风共用手机字号、二哥旁白、字幕与阶段流程；不因增加选项重做已认可视频。仅研究或更新画风时交付规范与资源，不自行制作新片。

融合依据与上游版本见 [来源与取舍](references/sources.md)。画面实施前读 [视觉规范](references/visual-style.md)与[动画方法](references/motion.md)，项目、音频及命令读 [本机制作流程](references/runtime.md)。需要理解已认可的画面取舍时看[勾股定理样例](references/approved-pythagorean.md)。不需要一次读原来两个 Skill 的全部参考资料。

## 跨 Agent 使用

这是标准 `SKILL.md` 技能包，正文、分镜和脚本不依赖某个 Agent 的专有指令。先以当前实际加载的 `SKILL.md` 所在目录解析 `references/` 与 `scripts/`；`agents/openai.yaml` 只是可选界面元数据。视频流程中的文字稿与分镜阶段可单独交付；配音与出片需要本机视频仓库、依赖及现有二哥声音配置，不能把“已发现 Skill”说成“已具备全部出片环境”。

本机版本控制源目录是 `toBeBetterJavaer/.claude/skills/one-minute-remotion/`，共享入口 `~/.agents/skills/one-minute-remotion/` 指向它，其他 Agent 的技能入口指向同一份内容。跨 Agent 接力时以项目内的源稿、`spoken.txt`、锁文件、`OUTLINE.md` 和进度记录为准；继续前读取现状，避免重写已有稿件或重复生成音频。

## 视频制作文件存放

视频素材和制作产物不得直接写入仓库根目录，执行命令的工作目录不是产物目录。

- 开始前确认当前视频项目的绝对路径：`docs/src/ai/script/one-minute/<主题>/<工具>/<版本>/`，本机通过软链接对应 `ai-better/script/one-minute/<主题>/<工具>/<版本>/`。生成、复制、下载、截图和渲染均显式指定项目内输出路径；工具的 `--project` 使用已确认的绝对路径，不依赖当前工作目录或工具的默认输出位置。
- 本系列按 `script/one-minute/<主题>/<工具>/<版本>/` 归档：先分主题，再分制作工具与版本；接力项目保留一份工程并记录各工具参与环节，不复制完整项目冒充各工具独立版本。工具归属不明时用 `unattributed`，不得猜测。历史试作可放 `_archive/<主题>/<工具>/<版本>/`。旧工程的 slug、Composition ID 和成片名保持原值，目录名不作为重新命名它们的理由。
- 相同的动画库和字体通过相对链接复用本系列 `shared/` 中的固定版本，孟菲斯基础色板从 `shared/styles/memphis-v1.ts`、超级玛丽基础色板从 `shared/styles/super-mario-v1.ts` 引用；各期独有覆盖值留在项目内。通用配音、字幕、渲染工具继续复用 `script/shared/`，不复制多套。
- 配音放入项目的 `audio/` 或 `build/`，素材放入 `assets/`，截图、录屏、检查记录与临时文件放入 `preview/`，Remotion 源码放入 `remotion/src/`，成片放入 `output/`；`project.json`、`OUTLINE.md`、`PROGRESS.md` 等也只写在该视频项目内。源稿仍使用本 Skill 原有的稿件目录。
- 额外交付副本放入仓库的 `outputs/<视频项目>/`，保留必要的目录层级；不把音频、JSON、TSX、截图或进度文件拍平复制到仓库根目录。
- 每次阶段交付前检查仓库根目录及 Git 变更。发现误写文件先核对归属、内容和引用，再归档或归位；不覆盖正式项目中的较新版本，不清理其他任务的文件。

## 制作流程

固定顺序：**保存并确认文字稿 → 完整配音试听与量时 → 按实际音频设计约30秒一章的分镜 → 当前章有声预览、返修与确认 → 下一章 → 整片有声预览确认 → 明确要求后导出MP4**。

1. **保存并固定文字**。文字稿统一保存到 `toBeBetterJavaer/docs/src/ai/one-minute/<topic>.md`，例如 `docs/src/ai/one-minute/rrf.md`；新建稿件与外部导入稿件都使用这一入口。按 [写稿风格](references/narration.md) 写或润色，明确本条唯一知识点、观众已知什么、贯穿的一个例子与需要说清的边界。项目中保留源稿快照、纯口播 `spoken.txt` 和 `narration-lock.json`，锁文件的源路径指向统一目录中的文字稿。Markdown 只做明确的口播提取；不猜测代码块、表格或图片中的文字要不要念，不擅自删字。同名文件先读现状，保留用户已有改动。
2. **生成配音并实测时长**。继承原项目音色和语速，按完整意群制作 beats；字幕 `text` 保留原文，`ttsText` 只处理明确读法。先查 RRF、RAG、ReAct 等缩写的现有读音规则，不假定都按同一方式念；数学字母按英文读音处理，不能把中文谐音当作发音验收。用户要求先试听某个读法时，按[短样本与局部替换](references/runtime.md#读音短样本与局部替换)生成并停下，确认后才替换完整意群。沿用旧工具生成完整音频、时间轴和对齐，核对漏字、重复及术语读音。超过2分钟只记录实测时长和超出秒数，保留全文、音频及语速；不建议或执行为赶时长而精简文稿。单阶段模式交付试听后停下。
3. **设计分镜**。先按 [动画方法](references/motion.md) 选择并锁定具体语法、色板、主体及对应的上游函数或渲染模块，写明对象怎样发生变化、为何需要运镜和最终的可见结果。按其中的[关系成组与状态表达](references/motion.md#关系成组与状态表达)组织主体、公式、参数及例外分支，避免零散堆放元素。按实际配音写 `OUTLINE.md`：每个叙事单元记录对应原文、对象、动作、前后状态、短屏幕文字、语音锚点、无声可见的结果及教学假设，不按自然段平均切镜。在 `OUTLINE.md` 中另列每个约30秒审片章节的实际时间范围、对应原文/beat、预览Composition和验收点，允许一章包含多个连续镜头。单阶段模式交付分镜后停下，不实现动画。
4. **逐章制作与有声预览**。按[逐章有声预览](references/chapter-preview.md)只实现当前尚未通过的一章，并按[画面接入](references/huashu-runtime.md)实际调用上游库。先做主体动作，再补标签、字幕和对应原配音；检查起始、运动中间和落定帧，再以正常速度完整播放当前章。复用本项目Studio或按[本机制作流程](references/runtime.md)独立后台启动并核实实际地址，选择当前章节Composition，交付可播放的有声预览后停下。确认后才做下一章；全部章节确认后先提供整片有声Studio预览。逐章审片不导出章节MP4，也不以备用或验证为由导出预览MP4。配音变化后重新对齐并检查受影响章节，不手改 `build/` 生成文件。只有截图、无声画面或编译通过时，该章仍未完成预览；一章完成不代表阶段④完成。
5. **出片与验收**。整片有声预览已通过且用户明确要求导出，或明确授权跳过确认并连续出片时，按现有工具导出含二哥旁白的MP4。运行共享 `verify_export.py`，再运行本 Skill 的 `scripts/one_minute.py check`。检查整条正常速度播放、完整解码、字幕及声音；按上游要求由未参与制作的 Agent 独立审片，记录时间码和可见问题。自动指标不能证明听感和教学效果。

## 最后检查
