## 核心画面：游戏外观，因果动作

### 素材先行（2026-11-06用户返修要求）

按用户最新返修，**仅人物默认使用生成的像素素材**。电池、电阻、电流表、地面和平台恢复简洁纯色图形，统一描边、色板与阴影；不把生成的厚重道具、草地纹理铺满画面。二哥身份从`wanger-image`的认可参考提取，角色使用头大、短身、短肢体的完整轮廓，避免细长四肢和可见拼接关节。需要行走、搬运、拾起、放下时，优先制作同身份、同尺度、脚底对齐的完整动作帧；不要用一张姿势图平移冒充行走，也不要用多张姿势图长时间交叉淡化造成重影。导线、指针、刻度、数值、科学几何和字幕继续由数据与代码控制。

角色应完成与内容有关的动作，例如跑近、接通、搬运、放下、观察、思考、庆祝，不能仅站在角落或整体上下漂浮。允许在知识步骤或实验结果完成后出现闯关得分、星星与成就反馈；奖励计数和科学读数分开。讲解员、物件与结果之间形成可见的事件顺序。

元件需要名称时，把短文字直接附着在对应本体或仪表面板上，不在上方单独排一行脱离对象的“电池／电阻／电流表”栏目标题。图形本身、正负极、表盘字母或可直接数出的数量已经足够明确时，不重复加标签；文字不得遮住动态指针、接线端或关键数据。

本系列此风格右上角可署名`© 沉默王二`，不额外写“像素实验室”。显然属于动画示意的场景不叠加“电荷运动与仪表均为教学示意”这类无助理解的小字；技术简化仍记录在分镜和审片文档中。真实数据与假设数据需要辨别时，保留必要标识。

首个试作工程为`script/one-minute/ohms-law/codex/super-mario-v1`：当前返修改为完整短身人物动作帧与简洁图解。标题、署名/得分、字幕使用紧凑统一的边缘样式，撤掉整宽头部色带，让知识主体占据更多纵向空间。素材来源与prompt见工程`assets/`。当前仍待用户审片，旧六姿态切换和分段骨骼版本均未获认可。

第一帧就有知识主体和可辨认的像素风格。主体置于一个可持续演进的二维场景，角色遇到具体障碍，通过与知识点对应的动作改变结果。参考片的亮点是“同一角色持续承担同一职责”“消息去向可见”“前后对照使用相同任务”，而不是让所有术语变成砖块。

- 主体：原创像素角色、知识对象、平台、容器或工作站。AI题材可用终端与消息；数理化生保留真实图形、比例、物理路径与计数。
- 外观：暖米纸底、深墨描边、阶梯边角、无模糊的偏移阴影，少量金黄、橙、蓝绿的语义色。标题或转折可短暂使用横版天空/地面场景，正文以清楚关系为先。
- 环境：地面和平台可建立空间，问号块表示尚未揭示的对象，门/管道表示确有入口与出口的传递。无教学意义时不用。背景云、砖、树不循环抢动，也不能混入粒子或单位格计数。
- 信息：中文标签与字幕保持清晰黑体；不要把整帧降采样或把中文正文强制换成难读的像素字体。数字和短英文可以用已核对授权及字形的像素字体，缺字体时使用现有字体。
- 层级：主动作最突出，关联标签其次，背景最弱。通常一个主角、两到三个辅助对象足以说清关系；需要更多时分步显露，不能机械限量改变事实。

## 对象与动作的语义合同

| 画面语汇 | 适合解释 | 动作与可见结果 | 避免误导 |
|---|---|---|---|
| 角色携物行进 | 同一任务或数据的传递 | 物件沿路径进入目的地，来源与身份不变 | 不让数据凭空复制或传送到错对象 |
| 触碰/顶起方块 | 触发工具、揭示材料 | 先接触，后改变方块状态并产生结果 | 不把检索画成碰一次就必定正确 |
| 分岔与合流 | 并行检索、任务分发、结果汇总 | 分支分别运行，满足条件后汇合 | 不能用多个角色同步跳动冒充并行机制 |
| 平台或背包容量 | 上下文、缓冲区、资源限制 | 容器边界与所占空间可比较，溢出有去处 | 计数必须来自数据；明确教学示意 |
| 门、管道或传送站 | 系统边界、工具调用、数据通道 | 输入进入，有过程/等待，输出返回 | 别把存储、计算与网络传输混成一个概念 |
| 锁、沙漏、暂停姿态 | 阻塞、等待、权限 | 对象身份保留，相关路径停止，其他路径可继续 | 失败不等于对象消失；“等待”不等于“失败” |
| 旗帜/短反馈 | 机制完成或结果验证 | 结果先成立，再出现短反馈 | 到终点不代表模型答案必然正确 |

颜色只辅助身份；失败/等待/完成同时有短标签或形状变化。相同对象跨镜不换名换色，阴影和粒子不构成额外数据。公式、实验读数、结构关系仍由同一份真值计算。

## 一分钟如何安排

保持现有六段写稿方法、原文锁定和二哥语速，不强迫口播使用“闯关”“打怪”等措辞。游戏化发生在画面。以下为**约60秒新稿的分镜参考**，不是既有稿件的删减或固定计时规则；实际按完整配音编排，1至2分钟或超时规则沿用主Skill。

| 大致范围 | 叙事用途 | 画面任务 |
|---|---|---|
| 0–5秒 | 给出知识对象与具体问题 | 主角与障碍同框，立即发生一次有意义的动作，不播独立长片头 |
| 5–15秒 | 建立一个例子及旧状态 | 显示输入、路径、结果或瓶颈；标签只解释身份 |
| 15–40秒 | 演示核心机制 | 同一场景连续执行两三步，结果由动作产生；必要时短暂进入局部细节 |
| 40–53秒 | 解释为什么有效 | 回到同一例子比较前后状态，保留相同尺度或共同输入 |
| 53–60秒 | 收束知识点 | 结果停稳，保留关键关系；可给一次轻反馈，不加独立关注尾段 |

约30秒审片章是制作边界，不要求画面每30秒弹出关卡页。相邻章节可共享同一世界场景。参考长片的关卡地图、常驻生命值、成就计数和多章节引导不作为一分钟的默认元素；需要计数时只保留有实际语义的一个指标。

## 适配不同知识点

- RAG：同一个问题进入检索站 → 相关文档片段沿路径进入上下文容器 → 生成答案时带着来源标识。道具代表“证据片段”，不要用无名金币代替资料，也不要画成给模型升级训练。
- ReAct：同一个角色在任务、工具、观察点之间推进，工具返回结果使下一条路径改变。循环回到决策点，不能只单向跑到终点。
- RRF：不同检索路线上同名文档保持身份，名次转换成真实贡献值再汇总排序；积分可以游戏化，计算不能改成随意加金币。
- 数学：拼片、面积、长度仍按真实比例。像素背景与平台只是美术表达，不用跳跃替代证明，也不把圆或斜边粗糙化到改变几何意义。
- 物理/化学/生物：被讲解的运动、粒子和结构按知识规律变化；角色若是讲解者，留在过程外，不混入实验主体。重力抛物线不套到所有科学对象。

## 色板与可读性

随包色板为 [super-mario-palette.ts](../assets/styles/super-mario-palette.ts)，本机系列共享版本为 `script/one-minute/shared/styles/super-mario-v1.ts`。新项目从共享版本经项目内出口导入；外部独立工程可复制随包资产。不改共享暖米`C`或孟菲斯色板。版本固定后，单期覆盖留在项目内。

- 1920×1080、30fps；像素精灵建议用统一的4或6像素基本格与整数倍缩放，角色轮廓可阶梯化。数学图形、文字和字幕保留正常分辨率。
- 中文标签48px、数学符号60px、核心公式84px、字幕48px沿用系列规范。深底字幕用本色板`ink`与`paper`；关键信息不只靠高亮色。
- 世界画面截止约y=890，字幕是独立屏幕层。主体含跳跃顶点、标签、阴影与消息路线，距字幕留出48–64px阅读间距；不是只检查站立姿态。
- 少量纯色面配4–6px硬边即可建立风格。不要用高频背景纹理、闪烁描边、满屏砖块和同时跳动的人物制造“丰富”。

## Remotion 实施约定

沿用现有React/Canvas、音轨和字幕管线。此风格未提供完整场景引擎，不能声称角色库已安装；按下列模块职责在具体项目实现。配套色板已提供，其余为实现合同。

| 项目内模块建议 | 输入 | 职责 |
|---|---|---|
| `PixelActor` | identity、pose、position、frame | 原创角色的待命/行动/等待/完成姿态，保持轮廓与身份 |
| `PixelPlatform` / `PixelBlock` | bounds、label、state | 平台、容量或触发方块；外观与状态分离 |
| `MessagePath` | points、progress、payloadId | 同一消息沿路径传递，抵达后才触发目标状态 |
| `StateMeter` | value、max、label | 与教学数据一致的容量或进度，不能填无依据的百分比 |
| `PixelFeedback` | eventFrame、kind | 接触、完成、阻塞的短反馈，只有事件发生才播放 |

时间唯一来源为`useCurrentFrame()/fps`；对象位置、姿态、消息状态均为时间和数据的纯函数，跳帧与连续渲染一致。可实际复用已安装的`MO.smooth`做进出停稳、`DG.drawPartial`画路径、`CAM`做有目的的场景跟随，并在来源记录中写明真实调用。纯像素外观不要求把角色轮廓强行做形变。

自由设计的角色跳跃可用`p=clamp((frame-start)/(end-start),0,1)`、`x=lerp(x0,x1,p)`、`y=lerp(y0,y1,p)-4*h*p*(1-p)`；只适用于表演性角色位移，非科学仿真。镜头保持稳定供阅读，横移只用于路径超出视野或引入下一处有意义的空间。像素精灵内部网格稳定，使用最近邻放大；文字层不要跟着像素化。

先规定事件顺序，再做动效：接近 → 接触/输入 → 处理或等待 → 结果出现 → 停稳。非配音测量的动作时长只能作为试作值；不要写死“每三秒切镜”。反馈以短促、低干扰为目标，音效须在真实试听后调整，不从本次参考抽帧推断原片声音设计。旁白仍为二哥声音，背景音乐不默认增加。

需要生成角色时使用`wanger-image`，只提供当前角色/分镜关键词和用户参考图，不发送整篇文稿或无关页面。参考截图留在研究目录，不充当新片素材。

## 分镜、溯源与验收

在`OUTLINE.md`和`assets/references/visual-provenance.json`记录`style: super-mario`、`styleVersion: v1`、色板、原创素材出处、对象语义、动作前后状态、实际调用的模块，以及何处是教学简化。样例时间只是结构建议，语音锚点来自本条真实对齐。

检查触发前、接触帧、运动中段与落定帧，尤其是物件是否重复、消息是否穿过无关窗口、跳跃顶点是否碰标题、字幕是否被平台或反馈遮住。按390px和740px缩图核对，再正常速度看当前章的有声预览；静帧、编译成功和本风格卡均不能替代该验收。

用户仅要求研究/更新风格时，到规范与资源交付即可，不自行做新稿、配音或样片。后续制作仍按文字稿→配音→分镜→逐章有声预览→整片确认→明确导出执行。当前风格在首条实际样片通过后再沉淀“已确认案例”。
