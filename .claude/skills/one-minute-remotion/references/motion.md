# 一分钟里的概念动画

以下方法改写自花叔的口播动画、3Blue1Brown 式形变和白板语法，具体出处见 [sources.md](sources.md)。借鉴表达机制，不复制示范构图、角色、音频和作者个人素材。

## 先选语法，再写 TSX

| 要讲的内容 | 优先画法 | 观众应该看到 |
|---|---|---|
| RRF、排名融合、权重与计算 | 概念形变与排名重组 | 同一文档在两路中的位置、贡献如何合成、为什么排序变化 |
| RAG、检索、数据流 | 连续白板与信息流 | 问题进入、资料被检索、相关片段进入上下文、依据随回答呈现 |
| ReAct、工具循环 | 同一场景的状态推进 | 决定下一步、调用工具、观察返回值、据此继续或结束 |
| 产品事实或真实实验 | 对应真实截图、原文、录制 + 少量标注 | 来源和事实本身，不能用自画图冒充证据 |

一条通常只用一种主要语法。是否切镜由认知动作决定，不按每句一页、每镜固定秒数，也不把上游8秒示范直接拉长成一分钟。

RRF 优先采用上游 `t1_3b1b` 的细轮廓、大主体、身份连续和同点数轮廓形变；配色改用二哥共享色板 `C`，不继承上游黑底和示范配色。背景 `C.bg`、正文 `C.ink`、主色 `C.blue`、强调/对比 `C.rust`、次要标签 `C.gray`；绿色 `C.green` 只表示正确或通过，不用作任意文档身份。公式可保留 Computer Modern，不能退回卡片式仪表盘。RAG 可用 `y3_whiteboard` 的连续世界画布和累积笔画。其他主题按语法卡锁定对应的造型、空间和动作，再按当前题材重新构图。画风与字幕系统分别设计，全片保持一致。具体库安装与 Remotion 接法见 [huashu-runtime.md](huashu-runtime.md)。

用户点名像素、水墨、拼贴或某种艺术方向时，再从 [huashu-art-motion 的风格卡目录](https://github.com/alchaincyf/huashu-art-motion/tree/8a0d7d72ca65fcce6f8ba82c4a6c8dfe35b8422c/references) 选择对应配方，按需读取。提取笔触、用光、空间和动作规则，按当前术语重新构图，再转成 Remotion 可控的场景；不把艺术史样片的房间、人物或转场原样搬来。不因未安装上游引擎就退回文字卡翻页。

## 镜头表

在项目 `OUTLINE.md` 中记录每个叙事单元：

```text
原文/beat：引用本项目已经固定的文字
语法与实现：具体语法名、实际调用的上游模块/函数
教学问题：观众此时需要看懂什么
主体：具体文档、排名条目、查询、工具等
动作：谁移动、分裂、匹配、合并、返回或变形
状态：进入前 → 动作中 → 完成后
屏幕文字：仅必要术语、短标签、数值
语音锚点：从真实逐词对齐中取，未生成前注明待定
镜头：固定 / 横移 / 推近 / 拉远，写明目的
阅读停留：从所有必要对象显示完整之后开始计算
无声验收：静音播放时应看出的因果关系
边界：教学假设、简化、未体现的真实实现
```

每个核心变化应能指出所用的实际函数，例如 `DG.morph` 将同一文档的排名轮廓变成贡献条，`DG.drawPartial` 画出合并路径，`DG.math` 写出分数，`CAM.track` 推近后再回到全貌。记录在 `assets/references/visual-provenance.json`，区分直接调用与按配方新写的场景代码。

先实现最关键的一次变化，检查对象是否清楚、是否遮挡、数值是否对齐，再复用该视觉语法。用户已给参考或明确方向时直接推进；不强制三套风格候选或逐镜审批。整片完成后按上游要求独立审片。

## 连续性与运动

- 让对象保有身份。RRF 中同一文档始终同色同名，RAG 中被找到的片段直接进入上下文，ReAct 中工具返回值引发下一次选择。
- 一次动画承担一个可解释动作：排名换位、文档高亮、箭头连接、材料进入上下文。动作结束后停住供人看清，不给每个静止对象加呼吸或漂浮。
- 镜头用来带视线，主体已经清楚时不动。不要每镜同样缩放，不连续三镜推近；读公式与比较数值时保持稳定。
- 白板内容随讲解累积，清楚保留上一状态与下一状态的关系；不把多个大段文字轮流写到同一个框里。
- 主画面不复述字幕，连近义改写的问句与结论也不重复。例如字幕“怎么把它们合并成一份最终榜单？”时，画面保留两列排名、汇合动作或问号，不再写“怎么合成一份榜单？”。保留对象名、公式、单位、数值和必要短状态；“关键词检索”“向量检索”是区分对象的标签，应保留。整句解释交给旁白与字幕。底部留给字幕，镜头运动后仍检查安全区。
- 使用 `useCurrentFrame()`、`interpolate()`、`spring()` 或按帧推导的纯函数；不使用墙上时间、浏览器计时器或每次变化的随机数。需要随机质感时固定种子。

## 关系成组与状态表达

构图先表达关系，再摆放元素。同一计算中的输入、运算和结果应沿清楚的阅读顺序成组对齐；参数靠近所属公式，数值靠近对应对象，例外状态作为与主流程有关联的分支。不要把标题、名次、公式、参数、贡献条和例外说明散落在画面各处。减少文字后仍需重新组织布局，不能只留下大片空位；不要求所有题材都套横向三栏或加卡片框。

对象身份与对象状态分开表达。未命中、失败、禁用等状态仍保留原对象的名称或编号、轮廓和可辨认的身份色，再用降低强调程度与相邻短标签表示状态，不能用“未命中”替换文档 A 本身。降低强调程度后仍要读得清。检索未命中的文档没有名次，不把它画成第三名；需要说明贡献时另标0，不能让“无排名”看起来像有排名但分低。

分组括号的开口朝向被归纳的对象，尖端朝向外侧说明。括号位于对象右侧时用 `}`，位于对象左侧时用 `{`；覆盖范围只包含实际分组的行，不误包相邻条目。以实际渲染结果检查方向，不能假定绘图库默认方向正确。需要镜像时只镜像括号图形，恢复画布变换后再写文字，避免连说明一起翻转。

先确定主关系，再检查运动经过的空间。连接线必须连到所属对象；形变轮廓和运动路径不能穿过公式、参数、数值或其他对象。参数与例外状态应在对应语音锚点出现，并留出看清的时间。返修已认可的画面时保留文稿、声音及不受影响的动画，只调整相关构图、状态和运动路径。

## 三个题材的设计提示

### RRF

两列排名中保留同一组文档，将名次转换成贡献值，再合到同一文档上，最后让文档按融合分换位。公式使用 `Σ 1/(k+rank)`，rank 从1开始，某一路缺失贡献0。排序使用完整精度，只在显示时四舍五入；显示精度不足以区分结果时增加有效位数。教学排名显著注明“示例排名”，不要声称是模型跑出的结果。参数调整后的结果必须真的重算，不能只让数字随便滚动。

### RAG

使用同一个问题。资料先被检索，命中的片段成为回答时可用的上下文，回答带回对应来源。原文没有涉及分片、混合检索或重排时不擅自增加这些术语；不把检索画成重新训练模型，也不承诺检索一定保证正确。

### ReAct

使用同一个任务，演示“决定动作 → 使用工具 → 观察结果 → 决定下一步”的循环。工具观察必须对下一步有可见影响。思考用短决策标签表达，不编造模型私密推理文本。工具异常、权限与复杂多 Agent 不属于本条主题时不加入。

## 动态验收

正常速度完整看一遍，检查动作是否与讲解对上、阅读是否来得及。贡献条与轴刻度必须从同一数值和量程计算，变换尺度时同步更新；运动路径及轮廓都要避开其他对象，排序可先侧移、再换位、再归列，不能只检查两个端点没有遮挡。关键动作检查开始、中段、落定帧及相邻转场，同时核对元素成组关系、异常状态下的对象身份、括号方向与覆盖范围；有轨迹交叉、裁切或数值跳变时加密检查。静帧不能证明运镜流畅，运动像素比例不能证明观众看懂。

不套用上游“快运动帧占比”或蓝紫色像素阈值作为技术科普的硬门槛；这里允许有意义的静止与阅读。只要运动能解释概念，画面清楚统一，就不为过分数添加运动。
