# 一分钟科普视频的文字稿

本文件服务于 `one-minute-remotion` 的视频制作流程。单独写改口播稿的请求由 `video-script` 处理；不能因为文稿时长是一分钟就自动接管。用户明确调用本 Skill 或已进入一分钟科普视频项目时，可按要求先完成文字稿阶段。

## 使用现成稿件

用户交来的稿件优先，来源可以是用户本人、Gemini、豆包工作、Claude Code、DeepSeek Harness 或其他工具；来源不影响保留原文的规则。先保存原文件快照，不自动润色、换例子、补介绍、纠正缩写或追加结尾。

新写或收到稿件后，统一保存到 `toBeBetterJavaer/docs/src/ai/one-minute/<topic>.md`，例如 `rrf.md`。外部稿件原样存入，保留原文件；同名文件先读取，不能覆盖用户已有内容。该文件是文字真源，项目中的 `script.md` 仅为制作快照，修改经用户认可后从真源同步，不能形成两份各自改写的稿件。

将真正朗读的部分提取为 `spoken.txt`：只跳过明确非口播的 frontmatter、标题、图片与制作备注，记录提取范围。句子、空格、标点、数字及大小写原样保留；不确定的结构只询问该处。`spoken.txt` 的换行用于排版，合成 beats 时可移除 CR/LF，其他字符不得变。

用项目内的 `narration-lock.json` 记录源文件与口播哈希、声音配置快照。锁文件包含的是当前项目的配置与出处，不复制进本 Skill，也不记录密钥。

发现技术疑点时只说明具体句子和依据，保留原文，由用户决定如何处理；不要在音频中悄悄修正而字幕仍留旧句。用户只要求照稿制作时，不擅自扩展成全面事实调查。不提供删减建议、可删内容清单、精简稿或缩短方案；超时只报告实际时长和超出秒数。

## 只有术语时

当前执行此 Skill 的 Agent 可以直接生成视频文字稿，Gemini 只是可选的写稿工具。默认先保存并交付文字稿阶段，等待用户推进；已有保存的文字稿且用户说“下一步”时，直接进入配音阶段，交付完整音频供试听后停下。只有明确要求连续完成全部剩余阶段时，才继续配音、分镜和出片。后续用户认可或替换的版本优先。

面向第一次见到这个词的人，先确定这一条要解决的具体疑问。已有课堂语境足以判断时直接采用，不重复询问。一个术语只保留一个核心机制和一个具体例子，必要时给一句适用边界。

可以按“观众的问题 → 例子里的动作 → 术语的含义 → 它能解决什么”组织，也可直接从动作开始。不要为了模板凑四段。先用学生认识的对象，再引入术语；不以一串新的缩写解释旧的缩写。术语英文全称只在对理解有帮助时念一次，公式仅在本条重点是计算时加入。

初稿用完整但短的句子，能一次自然念清。参考 `video-script` 的规范用词、具体例子及一手来源原则，不套用长片字数、固定过渡、三层结构、百分比闯关、信任建立长句、自我介绍或关注号召。新写内容涉及算法与产品行为时查原论文或官方文档；不存在的跑测和课堂反馈不写。

文字稿保存后，第二步生成完整配音并实测时长，单阶段模式交付试听后停下；用户再次推进才按音频设计分镜。字数只能作为新稿的篇幅参考，不能当作时长证据。以一分钟为目标，继承既有二哥音色和语速；实测超时保留全文、完整音频及语速，报告超出的秒数，不精简、跳读、截断或压缩音频。不能为了检查通过改写已经保存的稿件。

## 通用写稿提示词

以下提示词可交给 Gemini、豆包工作、Claude Code、DeepSeek Harness 或其他写作 Agent，也可由当前 Agent 直接遵循。

```text
请为一条供课堂插播、以一分钟为目标的中文技术科普视频撰写文字稿。
主题：[一个术语，如 RRF]
观众：第一次看到该术语、基础跨度较大的大学生。
已知基础：[观众已经懂的概念]
必须讲清：[这一条唯一要解决的问题]
可用资料：[原论文、官方文档或老师提供的准确材料]

用一个具体例子贯穿，讲清对象如何变化和变化的原因。
句子完整、指代明确，术语第一次出现时用中文解释。
只讲一个核心机制，必要时加一句边界，少引入新的术语。
不写开场自我介绍、资料领取、点赞关注、三段式目录或重复总结。
不编造实测、课堂效果、模型行为和精确数字；教学数值注明是示例。
以正常且清楚的朗读为前提，围绕一分钟目标留出动作和阅读时间。
不要保证字数必然对应一分钟；新写时控制范围，现成稿件保留全文，实测超时也不删减。
只输出可朗读正文；资料来源放在正文之外，明确分开。
```

收到外部稿件后回到“使用现成稿件”模式。模型出处由用户提供的材料或实际工具调用记录决定，不因提示词提到某个模型就声称已经调用它。
