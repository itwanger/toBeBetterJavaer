# 热点类导演规则

用于产品发布、模型变化、能力比较与实测评论，也承接产品操作和成果展示段落。目标是让观众知道发生了什么变化、证据说明什么，以及变化对任务有什么意义。统一制作流程和视觉参数沿用 [Skill 共享底座](../SKILL.md#共享制作底座)，本文件只维护热点类的叙事与内容验收。

## 用变化组织叙事

先在现有 `OUTLINE.md` 中明确本段的事件或变化、比较基准、对应证据和能得出的判断。常用走向是“事件切入 → 关键变化 → 实测证据 → 使用判断”，按稿件需要取用，不把新闻背景、参数列表和全部功能依次铺满。

尽早让观众看见最有意义的变化，再给必要背景。比较新旧版本或多个产品时，围绕同一个任务或同一项能力组织画面；身份、尺度与输入保持可追踪。失败后换策略要展示失败点、改变的动作及后续结果，避免只用成功成片掩盖过程。

发布片、真实界面、原文和实测承担事实；像素角色与场景组织分工、变化和比较。工坊、跑道、成绩卡只有在能表达本段关系时才使用，不为热闹添加胜负或虚构效果。节奏随信息变化推进，关键操作与结果仍需留出辨认时间。

## 让判断对应证据

区分官方宣称、本期实际观察和制作者的推断。对发布日期、版本、跑分、速度、费用或配额等易变化信息，核对本期使用的来源与适用范围；来源及取材说明记录在项目材料中，画面保留理解结论所需的条件与单位，不自动叠加制作说明。

比较时检查输入、配置、测量范围和统计口径是否可比。结果不同先解释可见条件，证据不足就缩小结论，不把发布演示当作本期实测，不把单次结果扩展为普遍能力。用准确数据驱动画面，不能为戏剧性编造读数、放大差距或省略决定结论的限制。

优先从 [Fable 第一章](FABLE_CH1_LIBRARY.md)取模型出场与工坊交接，从[第三章](FABLE_CH3_LIBRARY.md)取策略改变，从[第四章](FABLE_CH4_LIBRARY.md)取读图与实机叠分，从[第五章](FABLE_CH5_LIBRARY.md)取同题对跑、费用与评测。完整方案均由[共享镜头索引](SHOT_LIBRARY.md)维护；不默认加载全部章节。

## 产品操作段落

插件生态、安装操作与成果展示可以直接从任务进入，不强加发布新闻或新旧对比。明确用户输入、关键操作、状态反馈和交付物，沿同一任务从入口跟到结果；拍法取 [Harness 认可索引](HARNESS_APPROVED_INDEX.md)与[插件实测](PLUGIN_WALKTHROUGH.md)。讲 Agent 产品时，沿用统一入口的整体视角，把模型、工具、执行过程与实际交付的关系讲准确。

热点中需要解释某个机制时，按该段读取[知识类导演规则](KNOWLEDGE_DIRECTOR.md)，解释到足以理解本期变化后再回到事件或证据；不因出现一个术语就扩展成整章原理课。知识视频借用一段实测时，也不必改成新闻叙事。

## 内容验收

在共享流程已经安排的分镜检查和预览中判断，不增加一套审片流程：

- 观众能否指出本期的关键变化或操作结果，而不只是记住产品名与参数？
- 每项比较和判断是否有相应证据，真实操作是否沿同一输入走到结果？
- 事实、官方宣称和推断是否表达清楚，结论是否超出当前版本、条件或样本？

有缺口就修相关证据或判断；沿用共享的技术、声画和导出检查。
