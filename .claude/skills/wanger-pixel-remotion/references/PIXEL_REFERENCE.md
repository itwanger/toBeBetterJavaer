# 小白debug 参考片逐帧拆解

参考为[《DeepSeek Super-agent是什么，跟普通Agent有什么区别》](https://www.bilibili.com/video/BV1Ut4h6BERE/)。播放器标为 7:49。本次读取公开播放接口的 852×480 视频轨，用第一帧为 F0 的顺序解码全轨，共 14,045 帧，30 fps，末帧显示时间 468.133312 秒。以下均为**可见画面**。软件、工程分层、关键帧插值与音效来源不在画面证据范围内。

本机[研究目录](../../../../docs/src/ai/script/what-is-tokenizer/preview/reference/)有原始视频轨、索引和联系表。每一帧记录显示时间，以及 256×144 RGB 缩图相对前帧的平均绝对变化（0–255）。该值对字幕、角色动作与切镜都会有响应。全程按每 120 帧加末帧排成五张总览，另有密采与逐帧条带。人工核看了这些图表；索引覆盖全帧，语义标注集中在下列镜头。历史一分钟系列的 26 张播放器截图仅供对照。

## 屏幕边缘的三个元素

看片头原始 F0，右上还没有状态栏。8 秒、92 秒、245 秒、420 秒抽帧里，右上深色小框都有三颗红心、金币和“小白debug”；金币读数依次为 ×00、×03、×07、×10。画面最上缘另有细进度线，和金币读数各自变化。底部字幕居中、有窄黑底、宽度随句子变化，部分术语用金色。0 秒开场有路面，8 秒终端、92 秒对照、245 秒架构画面底部都没有通栏马路。工程实现分开处理屏幕状态、字幕与场景地形。[抽帧并排对照](../../../../docs/src/ai/script/what-is-tokenizer/preview/reference/hud-subtitle-review.jpg) · [92 秒的右上原图放大](../../../../docs/src/ai/script/what-is-tokenizer/preview/reference/hud-detail.png)

## 图片如何进入镜头

- **27.5、28.5、30 秒**：左侧是 DeepSeek 标识，右侧窗口先容纳仓库首页，再推近仓库名、Stars 与 About 中的说明，用彩框指到讲解对象。到 31.5 秒，窗口让出空间，左侧角色伸手提问，脚下直接是浅色留白；34.5 秒人物换成举手姿势。
- **54、156、279 秒**：公司类比和交互场景可画地面、桌椅；等待操作的角色也会直接站在对照栏的留白里。角色根据动作取得支撑，镜头之间可以改变姿势、位置或是否出场。
- **288、439–445.5 秒**：前一个例子的插图出现在笔记本电脑的屏幕里。后一个例子回到原文页，左边保留发布方标识，右窗移动到当前段落，橙框标关键句。读原文时，人物不需要一直在旁边。

本期采取同图推近与两次聚焦，具体窗口尺寸、动作和署名是本期设计。[参考片取样](../../../../docs/src/ai/script/what-is-tokenizer/preview/reference/image-staging.jpg)

## 点赞与关注

32.5 秒时仓库窗下只有问号方块；33 秒能看到拇指和“点赞”小牌，旁边带手形指针。34 秒右侧增加红心与“关注”，指针转到第二张牌。34.5 秒人物举手，两张牌还留在原处。问号方块早于这句出现。片尾另有“有帮助”和转发等画面，本期按当前口播选择动作。[前后连续取样](../../../../docs/src/ai/script/what-is-tokenizer/preview/reference/like-follow-frames.jpg)

## 四次逐帧核看

- **跨世界切场，F102–120（3.400–4.000 秒）。** F102–104 可读两边的对照题牌；F105–110 深色菱格从左铺进旧画面；F111–115 菱格里已能看见下一幕浅色底；F116–118 遮罩退去，F119 可完整阅读新对象。字幕位和顶部身份条跨过遮罩。约半秒就完成一次空间重置。实现时可把遮罩限定在世界层，转场过半切下层场景。
- **角色增多后重新分工，F1679–1702（55.967–56.733 秒）。** F1682 两名员工与检查勾仍在同一排；F1683 人物与线路重排；F1686、F1689、F1692、F1695、F1698 逐次能看到新员工；F1701–1702 中间位置出现主管和身份牌。前后密采显示 F1824 已经返回架构。对长稿来说，这个类比能成立，因为它最终回到同一个中间层。
- **等待的第一帧，F7449–7469（248.300–248.967 秒）。** F7455 中间窗口下方无锁；F7456 锁与窗口角上的沙漏可见。上下游的窗口位置与连线保持稳定，右上 Worker 的进度和时长标签仍可读。F7530 的更宽取样又出现时钟，到 F7560 新消息受到阻挡。这里“等待”由具体对象的状态承担。
- **逐个检查，F11050–11073（368.333–369.100 秒）。** F11052 第二台窗口上方刚出现浅勾并逐渐变清，F11063 第三台也开始出现，F11073 第四个标记开始显现；同一排窗口保持原位。稍后 F11106 附近出现方形消息标记。依次反馈让观众能判断巡检的范围；同时点亮所有窗口会丢掉这层意思。

## 复核方法

取已获得的视频轨运行随 Skill 的[逐帧索引工具](../scripts/inspect_frames.py)，依赖 ffmpeg、ffprobe、NumPy、Pillow。工作目录选本期 `preview/reference/`，避免把参考画面混入新片素材。当前轨道的 SHA-256 为 `48f875676f6c8d664c59cd44fd8f1cc4f5e0b688af54ad655892bf47782d6d85`。若取得不同清晰度或剪辑版，重新以 PTS 对位。

```bash
python3 "$SKILL/scripts/inspect_frames.py" "$PROJECT/preview/reference/source.m4s" "$PROJECT/preview/reference" \
  --window 0:120:6 --window 1560:1830:12 --window 7350:7560:10 --window 10980:11118:6 \
  --window 102:120:1 --window 1679:1702:1 --window 7449:7469:1 --window 11050:11073:1
```

CSV 供定位，条带供辨认动作；看不清小物件时对原分辨率取指定帧。色板、字号、动作时长和音效方案在[制作规范](PIXEL_STYLE.md)里作为本系列的选择维护，不能从该视频反推作者的工程参数。
