# 协作方式与精简检查

用户会逐画面核对。制作者负责把口播转成准确、可观看的动作，并消除明显故障；不重复搭建昂贵的审片流程，不拿“检查通过”代替设计判断。本文件是两类共用的协作与检查规则；题材叙事按[统一入口](../SKILL.md#导演规则分流)选择，镜头从[共享索引](SHOT_LIBRARY.md)按需取用。

## 只维护当前有效方案

每个项目的 `DIRECTOR.md` 保持为可快速读完的当前制作基准，包含五项：本次目标与章节状态、用户有效视觉要求及代码参数入口、整片各章视觉走向、当前实现/认可参考、下一步与完成条件。详细帧点在 `OUTLINE.md`，素材出处在素材记录，当前进度与下一步在 `PROGRESS.md`，总控只链接它们。不要维护相互冲突的第二份当前规则。

明确区分用户要求、已认可样片与制作者的待审方案。实施不等于认可。字体/字重、有效画布、对象身份/配色、连续性等稳定决定由共享参数或组件承载；一条通用反馈同时修改当前基准和实际维护点，不只修用户指出的一帧。像素系列配色统一复用认可的PixelWorld色板及深描边、硬阴影；具体字号与镜头按当期内容安排。

分镜拿到后先安排整章的视觉过程：口播段落 → 当前对象 → 可见动作 → 下一镜如何接续 → 原图/实测如何用。考虑当前只有一个对象和信息最密时的排布，未来内容不能提前占位。代表镜头服务于这个全章方案，不是把孤立的5秒画面复制铺满整章。已有授权下直接推进，不额外要求用户逐条批准文档。

新一轮制作、换章或压缩恢复时先读总控；局部反馈只展开相关分镜与来源。交付时覆写当前状态，清除被替代的旧方案。Skill 只收录有效规范和已认可素材；待审实现只留在本期，不沉淀为模板。若压缩发生在中途，交接摘要保留项目绝对路径、总控路径、当前授权范围、未完成动作/运行进程；恢复后以文件和现场为准。纯文档维护不触发渲染、配音、全章审片或自动化常驻任务。

## 开始与修改

新题材先判断是操作演示、抽象机制、比较还是故事场景，再选对应认可样片。参考图需落实到主体占比、人物角色、焦点位置和动作方式；不能只继承色板/HUD。先在已有 Studio 中完成一个约 5–8 秒的代表镜头，再扩展本章。这是制作顺序，不是新增用户审批关卡。

每段只写三个决定：这句观众看谁、它发生什么变化、何时交给下个对象。用户发截图或口播原句已足够，制作者自行定位与归纳；不要求用户写分镜或给实现方案。有影响范围不清的反馈，只问会改变结果的那个问题，其余工作继续。

组件的名称与品牌图标优先放在其标题栏，正文空间用于内容与动作。标题栏仍需可读，不把正文大标题与同名栏标题重复显示。

必要文字要保留：对象名称、关键状态、协议字段和必要数值，贴附对应对象并随动作出现。删的是重复口播的解释段落，不是把画面做成全无文字；不能让观众猜符号含义，也不能用标签替代对象本身的动作。具体是否保留按当前镜头语义判断，不能将某章去掉入口/出口或完整提示词的决定扩展成全片禁字。

区分稳定容器与动态内容。应用窗口可以保持大小、位置与接口不变，让内部元素缩放、移动、增长或滚动；“没有提前占位”不等于容器必须跟每行文字伸缩。第二章固定桌面适合持续追踪；第五章双端比较用等宽等高窗口、传输到来才让出中缝。按当前语义选择，不能把某章参数升级为全片硬规则。当前重点获得更多空间，主体与字幕保持紧凑间距。内容行与容器边界一并对齐；不能仅把空背景放大来“撑满画布”。

一次只处理当次反馈涉及的范围。已认可的人物比例、字体、背景、配音和其它镜头保持稳定。反馈涉及通用问题时，修当前镜头并更新对应组件/规则一次；最终认可后再归档素材，不在每次小改后反复制作整套归档短片。

## 以后不能重复的做法

- 口播讲思考，却展示答案；讲生成、刷新、计时，却只放静态图。先检查素材类别和实际动作。
- 只放大一句话，把整屏变成大块空白；或把控件移到无关位置。保留全局，原位附近强调完整控件，四边留出描边与阴影空间。
- 未出现的元素先留空位，或每句都弹新的放大层。当前对象用当前空间，新增信息到来才让位，焦点只随语义变化。
- 连线与传输通道也不能提前占位：没有连接时只留正常组件间距；连接出现时再连续腾出通道，箭头和移动对象共用当前端口坐标。调整容器宽度和内部排布，不拉伸字体、图标。
- 用临时线段拼接角色手臂、桌椅。现有姿势不合适就制作完整动画素材，之后复用。
- 用户已经删除的外框、制作说明或以字号阈值驱动的硬放大再次出现。新指令优先，更新维护中的入口，不让旧参考反向覆盖。
- “自动检查零错误”被当成可读、美观或声画准确的证据。检查只报告它实际覆盖的范围。
- 用术语标签、装饰电脑或数字矩阵代替画面行为；同一内容换一套配色和身份；未定义的符号、绕圈线被当成解释。先修语义和对象动作，再考虑装饰。
- 只用静态帧判断动态线路是否相交。路径绘制与物件运动共用几何，通道留出物件完整尺寸；关注传输、写入、读取的中间过程。

## 默认只保留这些检查

| 触发条件 | 制作者做什么 |
| --- | --- |
| 改了代码 | 做一次类型/编译检查；现有预览若有运行错误就修复。纯文档更改不检查视频。 |
| 换素材或换叙事段落 | 核对素材内容与口播、思考/答案类别、文字和数据。不能只按文件名猜内容。 |
| 新增/调整运动、聚焦或排布 | 在改动片段选 2–3 个最容易暴露问题的状态，或看一段连续预览；线路重叠、缓存写读等动态问题优先连续播放，不能以端点帧代替。检查完整边界、相互遮挡和下一项是否提前占位。 |
| 新章首次交付，或音轨/动作时点改变 | 核对相关配音、字幕、动作与声音；首次交付连播一次，之后只听改动段。 |
| 正式出片 | 检查导出是否成功、音画轨道与时长、封面/接缝/片尾。 |

## 从日常流程中移除

强制最小字号验收；每次修改后的整章上百帧采样；每个镜头自动导出一段短片；静态关键帧、GIF、短片、拼图同时重复交付；局部画面修改后的反复全章连播；没改音轨却重混音/重算时间轴；普通内容修改后的公共组件全量回归；每轮重复做安装、哈希清单与素材归档。

手机端可读性在构图阶段兼顾；重要控件的聚焦图层要足够大、完整且突出，不能只画框而仍读不清内容。允许对本次已取的关键帧做一次实际手机播放比例的快速核对，检查重点是否能辨认；优先减少无关元素、调整主体占比，不把全局裁成孤立的大字，也不另起一轮批量截图。

复杂故障确实需要时，才定向使用密集采样或回归工具，并先说明要查哪个具体问题。素材安装器、公共布局或导出器有代码变更时，运行与改动相关的测试一次即可。

## 工具入口

```bash
# 普通视觉修改：默认无渲染、无音轨重建。
python3 shared/tools/chapter_pipeline.py --project <项目> --chapter ch1
# 有边界疑问时，只取指定状态；一次打包批量渲染。
python3 shared/tools/chapter_pipeline.py --project <项目> --chapter ch1 --still before:595 --still focus:620
# 初次准备或实际改动了配音、时间轴、动作声音。
python3 shared/tools/chapter_pipeline.py --project <项目> --chapter ch1 --update-audio
# 以下为定向诊断，不是每轮交付条件。
python3 shared/tools/chapter_pipeline.py --project <项目> --chapter ch1 --full-review
```

交付优先更新同一个 Studio 预览，简短说明改了哪处、用户从哪句开始看。不用检查数量、文件数量和日志长度表达完成度。
