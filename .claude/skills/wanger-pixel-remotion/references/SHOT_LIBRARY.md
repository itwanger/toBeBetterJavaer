# 认可镜头与素材索引

知识类与热点类共用这一份索引。按当前段落要让观众看见的动作取镜头，不因项目主类型限制素材来源。各章认可方案、样片、源码和素材仍在原路径；复用表现关系与组件，具体事实、尺寸和帧点按本期重定。

| --- | --- |

## 认可方案入口

手机/平板操作、本机引擎与独立模型、三方远程通道、原始工具记录压缩并同步手机，取 [DSH Go 第二章认可方案](DSH_GO_CH2_APPROVED.md)：包含实心字体、依赖原位聚焦、设备动态让位、中继服务器、摘要细节，以及转场和声音事件接法。


历史保留/过滤、跨模型迁移、压缩与摘要回填，使用[CoT 第五章认可方案](COT_CH5_APPROVED.md)：独立主体、签名附件、保存原件与发送副本、按需传输通道、当前内容占当前空间，以及推导行到独立答案的连续总结。素材包保留最终源码与动态样例，不把本期事实和时间轴自动安装到新稿。

软件界面需要为手机观看精简时，取[CoT 第三章认可方案](COT_CH3_APPROVED.md)：当前任务所需的关键组件、必要名称与状态、流式内容、动态分离和连续折叠；保留应用辨识度，省去无关控件。

客户端与模型交换、上下文累积、缓存写读等机制，优先读 [CoT 第二章认可方案](COT_CH2_APPROVED.md)：稳定外窗、内部让位、统一像素语义符号、边界接口与独立线路、真实原图聚焦。先定对象与数据的归属，再做连续动画；沿用可复用关系，不照搬本期尺寸与帧点。

软件输入、模型生成、状态折叠与概念解释交替出现时，优先读 [CoT 第一章认可方案](COT_CH1_APPROVED.md)：角落操作人物、可动画的输入/生成演示、真实证据、原位聚焦和按当前对象动态让位。这里的方案用于此类题材，不替代下面已有的工坊、游戏跑道和知识图解。完整敲键盘 GIF/PNG 与独立组件已归入本 Skill 素材库。

模型与能力依次出场、空文件夹、工坊交接可从 [Fable 第一章定稿组件与动效](FABLE_CH1_LIBRARY.md) 直接取用。分工、验收、硬件全景及拾音剖面从 [Fable 第二章定稿索引](FABLE_CH2_LIBRARY.md) 取用。总览转单项、失败后换策略、HUD 奖励、复杂图取景和跨镜头终端操作，从 [Fable 第三章定稿索引](FABLE_CH3_LIBRARY.md) 选取。坐标轴追光、成绩卡让位与实机持续叠分从 [Fable 第四章定稿索引](FABLE_CH4_LIBRARY.md) 取用。同题对跑、逐项费率、研究复证、真实评测与逐张发券从 [Fable 第五章定稿索引](FABLE_CH5_LIBRARY.md) 取用。插件实测、转场与声音从[五章定稿选用索引：素材、组件、动效、转场、提示音](HARNESS_APPROVED_INDEX.md)按要讲的内容挑镜头。索引给出可安装的实现、认可样片和本期原始素材，末尾可进入各章参数与接法。例如讲实测可从「固定全景 → 输入框原位放大 → 跨栏定位」开始；全期告别可直接取知识蘑菇片尾。

- [开场与安装](APPROVED_PIXEL_CH1.md)、[第二、三章的排版与运镜](APPROVED_PIXEL_CH2_CH3.md)、[完整串片与过关](APPROVED_PIXEL_FINAL.md)。
- 得分段按口播登阶、起跳、上旗杆；问句和告别用独立片尾。使用[知识蘑菇片尾](../assets/PowerUpOutro.tsx)时，固定告别词沿用[Harness 定稿干声](../assets/voice/harness-outro/manifest.json)。安装素材时同步拷贝干声。共享配音入口在请求 TTS 前自动匹配结尾并校验母带。按实际音轨定位收取、按钮和挥手时点。
- 产品证据使用真实屏幕或原文。讲机制时让操作或数据发生在原对象上。演员、视窗、转场、色板、趋势图、声音的细节以[像素规范](PIXEL_STYLE.md)为准。

## 具体口播的选镜与观察点

| 遇到的口播 | 首版怎么拍 | 哪个瞬间值得停下来看 |
| --- | --- | --- |
| 客户端发送、模型生成、上下文累积、缓存写读 | 先定对象归属、两端边界和每条线路的用途。用同一套提示词/Token/纸笔/结果符号贯穿，稳定窗口内按收到内容让位。见 [CoT 第二章认可方案](COT_CH2_APPROVED.md)。 | 稀疏态与密集态都能辨认主体；回传、写入、读取看连续过程，移动块不穿过无关元素，原缓存读取后保留。 |
| “发布了”“在实机上打开” | 从文章配图记录追到原片、原页或实测录屏。看片源像素尺寸和主体在成片中实际占多大。发布片与实机演示承担主要叙事时，把原画面等比铺在主体区底层，把模型名或当前部件放在独立文字层，避开光标、菜单与正在操作的窗口。原片比例与主体区不同时优先保全操作范围。 | 对照原片及样片中同一个操作瞬间，按实际画布检查观众要辨认的细节。这期原稿 GIF 只有 500×282、560×316，首版把它们放大。认可版追到 1920×1080 发布片与 1440×810 实机原片。尺寸用来判断取材，清晰度以实际画面为准。 |
| “一个模型”“另一个模型”“它们共享……” | 先给第一个对象用足画面；第二个词到来时，跟着原对象移动到并排布局。读到共享关系才连接基座；先让当前规格用足主体区；读到第一项能力时让规格上移、收矮，新卡从腾出的位置进入。按新口播定词头、位置、大小。 | 并看「只有第一个对象、第二个进入的中段、全部落定」。若遮住后续对象，第一张还是缩在角落，就先重排初态。在下一个词头的前一帧停住，单看此时已出现的内容是否用足右侧和字幕上方。到词头再让旧对象移动、收小；在移动中段和落定后检查新对象如何获得位置。[认可版连续动作](approved-fable-ch1/model-reflow.webp) |
| “让多个 Agent 写、测、审” | 先找口播里的角色、工具和交付物。像素集市用摊位、摊主和商品表现插件；软件协作可以让编写、测试、审查各有工位，工件随口播从上一站送到下一站。需要比较规模时再加读数。 | 遮住字幕跟随一个工件，看它从哪里出来、由谁接手、完成时是什么状态。数字和点阵适合讲规模；讲分工时，按角色的动作验片。[工坊交接](approved-fable-ch1/workshop.webp) · [集市场景](approved-harness-ch1/market.webp) |

**复用工坊角色。** 安装像素素材包后，从 `remotion/src/WorkshopBot.tsx` 导入 `WorkshopBot`，放在 SVG 舞台内。传入 `job`（`code`、`test` 或 `review`）、局部帧 `f`、脚底坐标 `x` 和 `y`；`scale` 调整尺寸，`walk` 启用步态，移动路线由调用者决定。三种角色的工具和面罩不同。工位可以按新稿重画。[可安装角色](../assets/WorkshopBot.tsx) · [本期工位、镜头与传送带接法](../../../../docs/src/ai/script/claude-fable-5-2/remotion/src/AgentWorkshop.tsx)

**硬件从整机定位到部件。** 选镜时可直接看[第二章定稿的板边、标注与任务交接](FABLE_CH2_LIBRARY.md)。 先用能辨认整机的原图，再切到对应部件的剖面。进声孔、麦克风等容易误认的部件用短名和指引线，尺寸括号贴着实际量测的两端。总览中保留外轮廓、描边和投影；背景原片与示意图层各自取景。在最大放大帧同时检查四边、HUD、字幕和引线。
