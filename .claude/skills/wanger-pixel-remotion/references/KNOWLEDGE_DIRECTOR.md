# 知识类导演规则

用于概念、原理与机制解释，目标是让观众沿着可见变化理解原因。统一制作流程和视觉参数沿用 [Skill 共享底座](../SKILL.md#共享制作底座)，本文件只维护知识类的叙事与内容验收。

## 先设计解释过程

从本段要回答的问题出发，在现有 `OUTLINE.md` 中写清：观众跟随哪个对象、它原来是什么状态、什么动作改变了它、结果怎样说明原因。先安排完整解释，再选素材与运镜。常用走向是“可观察的现象 → 对象与连续变化 → 因果解释 → 回到原图或实测”，按稿件需要取用，不强制每段凑齐固定结构。

尽量延续稿件中的同一个例子，让后一步从前一步已经建立的状态开始。概念首次出现时，给符号明确含义和必要短名称；动作负责解释，名称负责辨认。不能因缺少现成录屏，就退回文字板、装饰电脑、无含义线路或与概念无关的工坊道具。

机制分镜先明确对象归属与边界：谁发出、谁计算、谁接收，每根线的起点终点是什么；缓存写入与读取分别改变什么。屏幕符号全程保持同一含义，不能临时加未解释的编号补救关系。若当前讲输入输出，就把两端交换讲清楚，不额外塞一个看不懂的内部循环。

以产生、传递、累积、读写和状态变化表达因果。保存原件与发送副本、读取与消耗、过程与答案有不同含义，画面要体现实际机制。让观众跟得上关键变化，再交给下一对象；不以频繁切镜代替解释，也不把一个案例的窗口构图推广到所有知识题。

## 证据与镜头选择

优先从 [CoT 五章标杆](COT_APPROVED_INDEX.md)取对象一致性、连续动作、空间安排和证据衔接，按新概念重选符号；不把每道题都套成 DSH 双窗口。输入输出与缓存边界可读 [CoT 第二章](COT_CH2_APPROVED.md)，保留、迁移与摘要回填可读 [CoT 第五章](COT_CH5_APPROVED.md)。Tokenizer 等其他认可方案由[共享镜头索引](SHOT_LIBRARY.md)按画面任务选取。

示意动画解释机制，真实原图或实测支撑具体产品行为，两者在对应语义处衔接。不要用动画模拟出的成功证明实际产品能力。需要演示软件操作时可借 Harness 或 Fable 镜头；只有涉及产品变化、能力比较等叙事决策时，再读[热点类导演规则](HOTSPOT_DIRECTOR.md)。

## 内容验收

在共享流程已经安排的分镜检查和预览中判断，不增加一套审片流程：

- 能否跟随同一对象看见触发、变化与结果，而不是只看到前后两张结论卡？
- 对象、线路与容器是否有明确归属，比喻是否会让观众误解真实机制？
- 结果是否回答本段的问题，必要的原图或实测是否支撑具体事实？

有缺口就修相关解释段落；沿用共享的技术、声画和导出检查。
