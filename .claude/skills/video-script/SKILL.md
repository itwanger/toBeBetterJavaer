## 标准结构与格式

### 1. 开场切入与 30% 进度节点
1. **一句大白话交代场景与目的**：从观众熟悉的日常场景或核心事件切入，一句话讲清楚“是什么、什么情况下会做什么、为了什么”，不堆砌啰嗦的界面细节，配 1 张真实界面截图占位符。
2. **展开核心看点或引出主线**：结合主题自然展开——既可以直接展示具体操作与输出体感（如 `xiaomi-ocr-0.md`），也可以点明前提规则、引出核心问题（如 `context-compaction-vs-kv-cache.md`）。
3. **30% 进度节点**：进入正片第一层前，单独成段写一句：`恭喜看到这里的你，已经成功击败 30% 的学习者。`

### 2. 逐层拆解（3-4 层递进 + 进度节点）
每一层根据当前主题要讲的内容自然推进，按以下节奏展开：
1. **加粗追问句开头（统一采用“聪明的你”递进追问，取消 A/B/C 选择题和弹幕互动词）**：
   - 参照 `docs/src/ai/video/xiaomi-ocr-0.md`，以观众视角自然追问，依次递进：
     - 第一层：`**那聪明的你一定会问，……？**`
     - 第二层：`**那聪明的你肯定会继续问，……？**`
     - 第三层：`**聪明的你可能会继续问，……？**`
     - 最后一层：`**最后聪明的你还会问，……？**`
   - 问句直接切入当前层的核心问题，问句后直接给干货解答，不再列 A/B/C 选项、弹幕引导词和“我的答案是……”。
2. **有体感的白话原理解答（核心味道所在）**：
   - **先铺日常体感，再搭因果桥梁，最后落到源码动作或具体实现**：不要一上来就抛抽象概念。先给一个具体的开发或使用体感，接着用大白话把因果逻辑搭上桥，最后再引出源码设计、训练做法或实操步骤。
   - **技术边界严密，把适用条件、命中范围或工程代价讲完整**：不说“全部未命中”或“100% 命中”这类绝对化的话。讲机制时说明哪段生效、从哪个位置开始变化、有什么前置条件或额外开销。
   - **一段只讲透一个主干，只用公共术语与直观数字**：只保留行业约定俗成的公共概念（如 `KV Cache`、`Prefix Caching`、`Prefill`、`TTL`、`tool_result`、`Sub-agent`、`MCP`、`Skill`、`RAG`）和有体感的代表性数字。源码内部实现全部转化为直白的动作描述，与当前提问主干无关的旁支细节一律不写。
   - **转折提问简洁自然**：段间追问直接写“那什么时候在本地改消息呢？等缓存过期之后。”，不用生硬套模板。
3. **配图与进度播报**：
   - 每层核心内容讲完配一张对应的架构图、流程图或实测截图（生成前使用 `【截图：...】` 占位符）。
   - 每层结束单独成段播报进度：
     - 第一层结束：`恭喜看到这里的你，已经成功击败 50% 的学习者了。`
     - 第二层结束：`恭喜看到这里的你，成功击败 70% 的学习者了。`
     - 第三层结束（若共 4 层）：`恭喜看到这里的你，成功击败 90% 的学习者了。`
     - 最后一层结束：`恭喜你升到王者段位了，成功击败 99% 的学习者。`

### 3. 总结与收尾
1. **口语短分句总结**：用“最后简单总结一下，……”开头，拆成舒展的口语短分句，不要把四五个并列短语硬塞进一个长定语里。
2. **固定收尾词**：`这个知识点你学会了吗？想解锁更多 Agent 硬核知识，点赞关注，我是二哥，咱们下期见！`

## 正向表达规范（与 `ai-article` 共用，详见 `.claude/skills/ai-article/references/human-tone.md`）

1. **主语直接用产品名或组件名，准确把握 Agent 定位**：直接写“Codex 会读取 `title`”“翻开 DeepSeek Harness 的源码”。Claude Code、DeepSeek Harness、Codex 统称为 Agent，既能在终端运行，也能在桌面端运行；除了写代码，还能写教程、做 PPT、做视频、处理各类工作，口播切入时不要把它们局限于“写代码”。
2. **动词干脆直接，一步到位**：用直白的动作词串起执行流程（如“挂载、暴露、读取、折叠、设定、挂起、放行、切换、跑、切到、查、塞进”），讲完动作本身即止（如“拼接到报错末尾”“切换为同步阻塞”“保护 KV Cache”“点错了再撤销”）。
3. **只用约定俗成的公共术语，把底层机制转化为通俗因果逻辑**：只保留观众有概念的公共技术词汇（如 `KV Cache`、`Prefix Caching`、`Prefill`、`TTL`、`tool_result`、`Sub-agent`、`MCP`）和有直观对比意义的代表性数据（如 `80%`、`5` 分钟、`1` 个小时）；技术状态用准确平实的中文表达（如“达到上下文窗口的阈值”“缓存未过期/缓存过期”“消息内容一变”）。重点用通俗清楚的因果逻辑把“为什么这么设计、底层怎么运作”讲明白。
4. **问句短促直接**：只问核心问题（如“Codex 怎么防止大模型被劫持？”“那第二个大招是什么？”），把触发条件和实现细节留给正文回答。
5. **用单一强有力的数据或案例说话**：每次论证只选最有代表性的一个高分或一个实测现象（如“拿到了 60 的高分，反超了自家的 GPT-6.1 Sol，58.6 分”），紧接“为什么？”进入源码拆解。
6. **数字与单位贴合日常听感**：容量写 `8 M`、`16 G`，状态分值写 `0`、`1`。
7. **举例拒绝俗套**：举提问或输入句子例子时，不用“今天天气真好”这类俗套句子，优先结合自身 IP 与开发者场景举例（如“王二讲 Agent 开源了吗？”“王二讲 Agent 开源知识库的地址是什么？”）。
8. **截图占位符格式**（全篇 3-6 张，紧贴对应段落）：
   ```
   【截图：<名称>；风格：<风格>；截图目标：<展示什么>；关键词：<关键词1>、<关键词2>、<关键词3>】
   ```

## 工作流程

### 步骤 1：确认用法与参考标杆
1. **从零创作**：先读取 `docs/src/ai/video/xiaomi-ocr-0.md`、`docs/src/ai/video/context-compaction-vs-kv-cache.md` 以及 `sucai.md` 素材。`sucai.md` 里用户写好的句子、截图和观点原样保留。稿件一旦落盘交付，后续修改前先读取磁盘最新文件内容，保留用户已改过的全部内容。
2. **优化已有稿件**：通读稿件，对照标杆稿件的追问节奏与正向表达标准做局部优化，保留用户校对过的句子。

### 步骤 2：调研与白话转译（强制）
1. 启用 Sub-agent 调研 **Claude Code、Codex、DeepSeek Harness 和 Pi Agent** 的源码、官方文档或一手公告，收到结果后立即停止 Sub-agent。本地源码路径：
   - Claude Code：`/Users/itwanger/Documents/GitHub/claude-code-source-code`
   - Codex：`/Users/itwanger/Documents/GitHub/codex`
   - DeepSeek Harness：`/Users/itwanger/Documents/GitHub/deepseek-harness`
   - Pi Agent：`/Users/itwanger/Documents/GitHub/pi`
2. **源码事实转白话隔离层**：拿到 Sub-agent 调研结果后，只提炼机制原理，把源码里的私有函数名、内部变量名、缓冲常数转化为“日常痛点是什么 → 怎么处理的 → 哪部分受益、哪部分付出什么代价”的白话因果链。

### 步骤 3：列大纲
按标杆结构列出开场切入方式、3-4 层“聪明的你”递进追问与每层对应的白话原理及代价边界，交给用户确认后再写正文。

### 步骤 4：撰写口播稿
按确认后的大纲与标杆稿件的语言节奏撰写，保存到 `docs/src/ai/video/` 目录。

### 步骤 5：自检
1. **六项正向质量过筛**：
   - **技术边界与代价完整**：讲清哪一段生效、从哪个位置开始变化，以及方案的前置条件或额外代价。
   - **因果推理不跳步**：把问题与机制之间的因果逻辑用平实白话讲清楚。
   - **零私有命名与零无感常数**：只留行业公共术语和直观数字，不出现源码私有函数名/变量名和缓冲区常数。
   - **地道中文表达**：确认没有英文注释字面直译词。
   - **一段一主干**：每段只聚焦回答当前提问，砍掉偏离主线的旁支细节。
   - **自然追问与短分句**：每层用“那聪明的你一定会问 / 肯定会继续问 / 可能会继续问 / 最后聪明的你还会问”开头直接作答（不设 A/B/C 选项），总结段用舒展的口语短分句。
2. **运行禁用词检查脚本（与 `ai-article` 共用 `wording_rules.py`，必须为 0）**：

