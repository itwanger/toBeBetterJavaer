# 口播稿生成工作流

## 定位与核心参考标准

面向王二讲Agent的口播稿，主打 AI 技术硬核拆解、源码级原理科普和热点实测。观众是对 AI 感兴趣的开发者和技术爱好者。

**首选标杆稿件**：`docs/src/ai/video/what-is-computer-use.md`，写新稿前必读，结构、格式、段落节奏与表达方式均以这篇为准。

视频封面是制作素材，写回 `docs/src/ai/video/` 时，将末尾封面及其标题放入 `<!-- video-covers:start -->` / `<!-- video-covers:end -->` 注释区；讲解配图保持正常显示。同步和验收使用 `feishu-question-bank-sync` Skill 的封面规则。

## 标准结构与格式

### 1. 开场切入与 30% 进度节点
1. **真实画面或实测切入**：从观众熟悉的产品现象或真实操作切入，配 1-2 张真实操作截图或可复现的实测 Prompt + 动图占位符（如“如果你用过 Codex 或者 Claude，一定见过……”“比如说，我现在正在让 Codex 操控……”）。
2. **提问引出核心原理**：用一句自然提问带出主题（“那聪明的你应该已经注意到了，为什么……呢？”），先点破表层认识，再用“一是……；二是……”概括底层核心解决的问题。
3. **30% 进度节点与知识库引流**：进入正片第一层前，固定接一句：“恭喜看到这里的你，已经成功击败 30% 的学习者，给自己来个关注鼓励一下吧。视频的原稿以及 364 道 Agent 八股已经整理到开源知识库。”

### 2. 逐层拆解（3-4 层递进 + 进度节点）
每一层按以下节奏展开：
1. **加粗短问句开头（参照 `what-is-computer-use.md`）**：
   - `**接下来我问你，Codex 在执行 Computer Use 时，底层是怎么向大模型暴露桌面操作能力的？**`
   - `**接下来继续问你，电脑桌面上同时开着浏览器、编辑器、聊天软件和终端，Codex 底层是怎么控制 Agent 能访问哪些应用的？**`
   - `**继续问你，……，Codex 怎么防止它先斩后奏？**`
   - `**最后再问你，……，Codex 怎么防止大模型被劫持？**`
2. **选项互动**：
   - 紧跟在同一段写出选项与互动引导：“A，……；B，……；C，……。喜欢收藏的你可以把答案打在弹幕或者留言区。”（后续几关依次用“喜欢点赞的你会选哪一个？”“喜欢推荐的你会选哪一个？”“聪明的你会选哪一个？”）。
3. **源码级干脆解答**：
   - 用“我的答案是 B。翻开 Codex 的源码，……”直接给出机制实现。
   - 顺着实际执行流程把核心组件名、关键参数名（如 `cua_repl`、`js`、`title`、`code`、`bundle_ids`、`elicitation/create`、`initial_cua_call`、`LunaSampler`）和运行效果讲清楚。
   - 需要补充设计原因时，用一句“那聪明的你一定想问，为什么……呢？”接“一方面，……；另一方面，……”讲透取舍，或用“也就是说，……”做干脆收束。
4. **配图与进度播报**：
   - 每层核心机制讲完配一张对应的架构图或流程图（生成前使用 `【截图：...】` 占位符）。
   - 每层结束单独成段播报进度：
     - 第一层结束：`恭喜看到这里的你，已经成功击败 50% 的学习者了。`
     - 第二层结束：`恭喜看到这里的你，成功击败 70% 的学习者了。`
     - 第三层结束（若共 4 层）：`恭喜看到这里的你，成功击败 90% 的学习者了。`
     - 最后一层结束：`恭喜你升到王者段位了，成功击败 99% 的学习者。`

### 3. 总结与收尾
1. **一句话总结**：用“最后简单总结下，……”或单独一行 `**最后简单总结下。**` 配合一句干脆的核心概括收尾（如 `最后简单总结下，Browser Use 靠无障碍树引用编号精准操控网页，而 Codex 的 Computer Use 靠 cua_repl 脚本编排桌面动作。`）。
2. **固定收尾词**：`这个知识点你学会了吗？想解锁更多 Agent 硬核知识，点赞关注，我是二哥，咱们下期见！`

## 正向表达规范（与 `ai-article` 共用，详见 `.claude/skills/ai-article/references/human-tone.md`）

1. **主语直接用产品名或组件名**：直接写“Codex 会读取 `title`”“`cua_repl` 会反向给 Codex 发一个 `elicitation/create` 审批请求”“翻开 Codex 的源码”。
2. **动词干脆直接，一步到位**：用直白的动作词串起执行流程（如“挂载、暴露、读取、折叠、设定、挂起、放行、切换、跑、切到、查、塞进”），讲完动作本身即止（如“拼接到报错末尾”“切换为同步阻塞”“保护 KV Cache”“点错了再撤销”）。
3. **技术概念保留核心短标识**：常见术语与承载核心机制的短标识直接用英文（如 `cua_repl`、`js`、`code_mode_only`、`fork_turns`、Sub-agent、Multi-Agent、KV Cache、MCP），配合一句直白的中文动作说明。
4. **问句短促直接**：只问核心问题（如“Codex 怎么防止大模型被劫持？”“那第二个大招是什么？”），把触发条件和实现细节留给正文回答。
5. **用单一强有力的数据或案例说话**：每次论证只选最有代表性的一个高分或一个实测现象（如“拿到了 60 的高分，反超了自家的 GPT-6.1 Sol，58.6 分”），紧接“为什么？”进入源码拆解。
6. **数字与单位贴合日常听感**：容量写 `8 M`、`16 G`，状态分值写 `0`、`1`。
7. **截图占位符格式**（全篇 3-6 张，紧贴对应段落）：
   ```
   【截图：<名称>；风格：<风格>；截图目标：<展示什么>；关键词：<关键词1>、<关键词2>、<关键词3>】
   ```

## 工作流程

### 步骤 1：确认用法与参考标杆
1. **从零创作**：先读取 `docs/src/ai/video/what-is-computer-use.md` 以及 `sucai.md` 素材。`sucai.md` 里用户写好的句子、截图和观点原样保留。稿件一旦落盘交付，后续修改前先读取磁盘最新文件内容，保留用户已改过的全部内容。
2. **优化已有稿件**：通读稿件，对照 `what-is-computer-use.md` 的节奏与表达做局部优化，保留用户校对过的句子。

### 步骤 2：调研（强制）
启用 Sub-agent 调研源码、官方文档或一手公告，收到结果后立即停止 Sub-agent。聚焦提炼核心源码机制（3-4 个关键设计点）和最具代表性的单一数据或案例。

### 步骤 3：列大纲
按 `what-is-computer-use.md` 的结构列出开场切入方式、3-4 层递进提问与每层对应的源码机制点，交给用户确认后再写正文。

### 步骤 4：撰写口播稿
按确认后的大纲与 `what-is-computer-use.md` 的格式撰写，保存到 `docs/src/ai/video/` 目录。
