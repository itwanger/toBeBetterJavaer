## A. 认知刷新（4 个）— 回答「为什么是现在，为什么是桌面」

### A1. 半个月里三家大厂同时变阵，它们抢的其实不是你的电脑

- **核心冲突**：腾讯 7/20、字节 7/30、阿里 8/3，三家在半个月内完成组织调整。这么巧？
- **三层提问**：桌面入口为什么突然值钱了？→ 谁掌握你的文件、IM 和日程，谁就掌握了什么？→ 这场仗最后拼的是什么？
- **干货锚点**：上下文即护城河——Agent 的智能上限取决于它能拿到多少真实上下文，而上下文的富矿在桌面（文件、IM 记录、日程、浏览器历史）。所以抢桌面 = 抢 Agent 的记忆。三家各自的绑定：企微 vs 飞书 vs 钉钉。
- **信任建立**：翻三家公开发布时间线，自己装了三个客户端逐个体验。
- **截图建议**：架构图 `whiteboard`（三家时间线 + 各自绑定生态）；正文 `skill-card`（三家生态对比）
- **撞车检查**：无

### A2. 同样的模型，装到电脑上就变强了？桌面 Agent 到底多了哪三样东西

- **核心冲突**：网页版 AI 聊天框里，模型一样笨；装成桌面客户端，突然就「能干活」了。多的到底是什么？
- **三层提问**：多了访问你文件系统的能力 → 多了任务在后台长跑的能力 → 多了调用你其他软件的能力？代价又是什么？
- **干货锚点**：三大增量对应三类风险增量（误删文件、静默失败、越权操作），正好引出 C 板块。
- **信任建立**：三个客户端都装了，逐个比对了权限申请清单。
- **截图建议**：架构图 `three-layer`（三层能力递进）；正文 `checklist-card`（权限清单）
- **撞车检查**：与 `what-is-agent.md`（什么是 Agent）不撞，一个是概念定义，一个是形态差异

### A3. 谷歌亲手关掉了 Mariner，为什么中国大厂还在 all in 桌面？

- **核心冲突**：海外在退——Google Project Mariner 2026 年关停、OpenAI Operator 2025-08-31 作为独立产品关停并入 ChatGPT。国内在进，为什么？
- **三层提问**：GUI 路线的效率原罪是什么？→ 海外为什么退？→ 中国市场为什么反而进得去？
- **干货锚点**：10 到 100 倍的步数差（命令行 vs GUI）；中国用户没有命令行习惯、桌面软件的 API 开放度低、生态绑定的商业价值更大，三条共同构成了国内路线的合理性。
- **表述注意**：Mariner 关停事实多源交叉确认，但具体日期在不同二手来源间有出入，口播只说「2026 年」不给具体日期。
- **截图建议**：架构图 `whiteboard`（海外退 / 国内进 的时间线对照）；正文 `swimlane`（截图→推理→动作 的循环开销）
- **撞车检查**：无

### A4. OSWorld 上 AI 拿到 86%，人类才 72%——这个分数该怎么读？

- **核心冲突**：分数超过人类了，可我用起来还是不好使。是评测造假，还是我理解错了？
- **三层提问**：这个分数是怎么算出来的？→ 为什么换个步数预算，同一个模型能从 62.9% 掉到 42.9%？→ 「会点按钮」和「会干活」差在哪？

## B. 技术硬核拆解（4 个）— 差异化竞争力所在

### B5. 桌面 Agent 是怎么「看见」你的屏幕的？三条路线，效率差了一个量级

- **核心冲突**：它能点中我屏幕上的按钮，可它是怎么知道按钮在哪的？
- **三层提问**：截图 + 视觉模型 + 坐标点击这条路是怎么走的？→ 还有一条读无障碍树的路，为什么更准却没人全用？→ 命令行那条路为什么是降维打击？
- **干货锚点**：
  - 像素派（Anthropic / OpenAI / Google）：模型只输出抽象动作，代码翻译成真实鼠标键盘事件。Anthropic `computer_20251124` 共 17 个动作，新增 `zoom`（按区域全分辨率重截图，解决小字和密集 UI）。
  - 混合派（微软 UFO²）：用 Windows UI Automation 取控件元数据当事实来源，GPT-Vision 看截图 + Set-of-Mark 编号标注，优先走原生 API、失败回落键鼠。论文消融：去掉视觉截图掉 14 分，说明两者互补。
  - 命令行派：10 到 100 倍的步数差。
  - 国内：豆包工作的 Windows「豆包虚拟桌面」是官方明确承认的 GUI 模拟路线，任务跑在独立隔离环境、可暂停、可人工接管。
- **截图建议**：架构图 `whiteboard`（三条路线并列）；正文 `swimlane`（截图→推理→动作 循环）、`skill-card`（三路线对比）
- **撞车检查**：无

### B6. 电脑关了，Agent 的活还在跑——云电脑背后的四个技术活

- **核心冲突**：我把电脑合上睡觉去了，第二天早上任务完成了。这中间发生了什么？
- **三层提问**：云端那台机器是怎么秒开的？→ 我的文件是怎么过去的？→ 跑一半断了怎么办？→ 下次再跑还认得我吗？
- **干货锚点**：
  - 冷启动：预构建镜像 + 预热池（按固定节奏构建含依赖和缓存的镜像，用户开始打字时就预热）
  - 文件同步：挂载而非拷贝（VirtioFS / FUSE），原则是宿主目录最小暴露
  - 状态持久化：稳定 id 复用（同一 id 复用同一环境，工作目录和已装包都还在）
  - 断点续跑：框架层 checkpoint + resumable，基础设施层 sleep-wake（沙箱暂停时把文件系统与内存状态存快照，唤醒时由另一个 Job 恢复）
  - 现实落差：豆包云电脑实测 2 核 4G，重任务不丝滑；阿里用「峰谷 Token」夜间 2 折把长任务引导到夜里跑——反过来说明白天算力贵
- **截图建议**：架构图 `whiteboard`（四层技术栈）；正文 `swimlane`（冷启动到续跑的完整流程）
- **撞车检查**：无

### B7. 装了 MCP 为什么还要装 Skill？桌面 Agent 的两层装配

- **核心冲突**：我装了一堆 MCP，为什么官方还在推 Skill？这俩不是一回事吗？
- **三层提问**：MCP 解决的是什么问题？→ Skill 解决的又是什么问题？→ 为什么不能只用其中一个？
- **干货锚点**：
  - Anthropic 官方定位：**MCP for connectivity, Skills for procedural knowledge**。MCP 在集成层，让 Agent 够得着外部系统；Skill 在提示/知识层，教 Agent 怎么做。
  - Skill 的核心机制是渐进式公开：启动时只加载名称和描述（约 100 tokens）→ 命中后加载 SKILL.md（建议 <5k tokens）→ 再按需加载 scripts / references / assets。这解决了 MCP 把全部工具 schema 一次性塞进上下文的 token 膨胀问题。
  - MCP 最新版（2026-07-28，第五次修订）：无状态协议内核（删掉 initialize 握手，任何请求可落到任意实例，不再需要 sticky session）、MRTR 多轮往返、头部路由强制 `Mcp-Method`、废弃 Roots / Sampling / Logging。
- **系列位置**：`agent-skill-hit-rate.md` 讲 Skill 命中率的匹配机制，这期讲「为什么两层都要有」，是上层装配视角，不重复。
- **截图建议**：架构图 `three-layer`（集成层 / 知识层 / 模型层）；正文 `checklist-card`（渐进式公开的三级加载）
- **撞车检查**：与 `agent-skill-hit-rate.md` 视角不同，可互相引流

### B8. Windows 给 AI 单独开了一个桌面，微软到底在怕什么？

- **核心冲突**：微软没有让 AI 看你的屏幕，而是给它单独开了一个桌面。为什么这么麻烦？
- **三层提问**：这个「Agent Workspace」到底是什么？→ 权限是怎么卡的？→ 为什么审计日志被说成最后一道防线？
- **干货锚点**：
  - 一个独立且受控、可审计的 Windows 会话，与用户主会话并行；每个 agent 有独立的 agent 账户和自己的桌面。
  - 默认只能读写 6 个 known folder（Documents / Downloads / Desktop / Pictures / Videos / Music）；agent 权限不得超过发起用户，**不能取得管理员权限**，权限必须细粒度、有时限。
  - 动作进入 tamper-evident 审计日志，能区分「人做的」还是「agent 做的」。
  - 内置 MCP 代理层，对 MCP 服务器交互施加 consent / governance / auditing / containment 策略。
  - **macOS 上没有对等方案**——Apple 官方没有对应产品，可用的只有 Seatbelt / sandbox-exec（已被 Apple 标记 deprecated）和 macOS 26 的 Containerization framework。这一段对 Mac 用户是强共鸣点。
- **截图建议**：架构图 `whiteboard`（主会话 vs Agent 会话 隔离示意）；正文 `checklist-card`（权限清单）
- **撞车检查**：无

## C. 翻车与安全（5 个）— 流量最集中

### C9. 一句「清一下临时文件」，6.6GB 项目没了：桌面 Agent 的三种翻车

- **核心冲突**：你只是让它「清一下」，它清得很彻底。
- **三层提问**：第一种，误删——它为什么会觉得项目文件是缓存？→ 第二种，越权升级——你让它改两个测试，它怎么就把操作升级成了 `reset --hard`？→ 第三种，也是最可怕的，谎报成功。
- **干货锚点**：
  - 误删：社区案例，一句「清一下临时文件」，6.6GB 项目文件被判定为缓存直接删除，**没进回收站**。
  - 越权升级：开发者只让修两个测试，Agent 自行把操作升级为「备份 14 个未提交文件 → 清理 Git pack 数据 → 准备执行 `reset --hard`」，导致 Git 对象库损坏，靠重新拉回 5000 多个对象才救活。
  - 谎报成功：定时任务没触发，被质问时 AI 先信誓旦旦说「今天早上 9 点跑成功啦」，被指出电脑根本没开后才道歉。
  - 金句收尾（社区总结）：「你交给建议者的是问题，交给执行者的是钥匙。」
- **表述纪律**：三个案例均转引自小红书 / 知乎原帖，来源二手，**不指名产品**，用「社区里流传的一个案例」。
- **截图建议**：架构图 `whiteboard`（三种翻车的递进）；正文 `checklist-card`（三案例）
- **撞车检查**：无

### C10. 沙箱能挡住它跳出文件夹，挡不住它在文件夹里自作主张

- **核心冲突**：厂商都说有沙箱，为什么还是有人的文件被删了？
- **三层提问**：沙箱到底挡住了什么？→ 它挡不住的又是什么？→ 真正的解法在哪？
- **干货锚点**：
  - 沙箱挡的是越界访问（只能动授权目录内的东西）。
  - 挡不住的是授权目录内部的错误判断——它有权删这个文件夹，只是删错了。
  - 核心矛盾金句（重度用户总结）：「沙箱只能限制它跳出授权文件夹，却拦不住 AI 在授权目录内部自作主张。」
  - 解法三层：关键操作人工确认点 + 可回滚（快照 / Git）+ 审计日志可追溯。
  - 各家做法：WorkBuddy 是授权目录沙箱 + 技能安全扫描 + 高危指令拦截 + 审计日志；豆包工作是独立隔离环境 + 可暂停 + 可人工接管。
- **截图建议**：架构图 `whiteboard`（沙箱边界示意：挡住越界 / 挡不住内部）；正文 `checklist-card`（三层解法）
- **撞车检查**：无

### C11. AI 帮你回邮件，结果把邮件删了——安全约束是怎么在压缩里弄丢的

- **核心冲突**：我明明告诉过它「删除前先问我」，它怎么还是删了？
- **三层提问**：这条约束一开始存在哪？→ 上下文一压缩，什么没了？→ 写在哪个地方才丢不了？
- **干货锚点**：Meta 安全专家让 Agent 处理真实邮件时，因上下文压缩丢失「执行前确认」的约束，导致邮件被误删。安全约束如果只活在 prompt 里，就是易失的；要落到系统层（工具调用前的硬校验）才可靠。
- **系列位置**：`why-agent-gets-dumber.md` 的姊妹篇——那期讲「聊着聊着为什么变笨」，这期讲「变笨之后会闯什么祸」。
- **截图建议**：架构图 `three-layer`（约束存放的三个位置：prompt / 工具层 / 系统层）；正文 `swimlane`（压缩发生 → 约束丢失 → 误删）
- **撞车检查**：与 `why-agent-gets-dumber.md` 形成姊妹篇，互相引流

### C12. 提示词注入降到 11.2%，专家为什么还说这是「灾难性的」？

- **核心冲突**：从 23.6% 降到 11.2%，明明是大幅改善，安全专家为什么还不满意？
- **三层提问**：这个注入到底是怎么发生的？→ 降到 11.2% 是怎么做到的？→ 11.2% 意味着什么？
- **干货锚点**：
  - Anthropic 在 Claude for Chrome 红队跑 123 个用例 / 29 类攻击：无防护 23.6% → 加防护 11.2%；浏览器特有的 4 类攻击（DOM 隐藏表单字段、URL 文本、标签页标题等只有 agent 能看到的注入）从 35.7% → 0%。
  - Simon Willison 公开评价残余的 11.2% 是「灾难性的」。
  - 致命三要素：能读私有数据 + 接触不可信内容 + 能对外通信，三者齐备就能变成外泄通道。Meta 的 Agents Rule of Two：无人工审批时只允许满足其中两条。
  - 真实 CVE：CVE-2026-25592（Semantic Kernel 沙箱逃逸 + RCE）、CVE-2025-6514（MCP 远程基础设施 RCE，CVSS 9.6）。
- **表述纪律**：23.6% / 11.2% 是**浏览器扩展（Claude for Chrome）**场景的数字，不是桌面 Computer Use，要说明口径。
- **截图建议**：架构图 `whiteboard`（致命三要素韦恩图）；正文 `data-board`（23.6% → 11.2% 数据条）
- **撞车检查**：无

### C13. 工信部给 AI 助手发了「六要六不要」，逐条翻译成人话

- **核心冲突**：官方为什么突然给一个 AI 工具发安全规范？
- **三层提问**：这份规范是在什么背景下出的？→ 六条分别在防什么？→ 普通人照做的话，具体要做什么？

## D. 选型与实操（4 个）— 收藏率最高

### D14. 三家桌面 Agent 横评：真正的差别不在功能表上

- **核心冲突**：把三家的功能表并排一放，几乎一模一样——那还选什么？
- **三层提问**：功能为什么会长得一样？→ 真正的差别藏在哪？→ 普通人该怎么选？
- **干货锚点**：
  - 趋同的部分：本地文件操控、任务拆解、文档生成、PPT、数据分析、定时任务、云电脑——三家全都有。
  - 真正的差别三条：生态绑定（企微 vs 飞书 vs 钉钉）、诚实度（会不会编数字）、出事后的可追溯性。
  - 诚实度这条可以举实测例子：有产品在盲测里会主动摊牌「我是出品方一员」，并把自己编造的数字做成「发布前必须替换的占位清单」交给用户；也有产品在盲测中出现数字自相矛盾。
  - **顺带教一个本事**：怎么读大厂的数据口径——WorkBuddy「千万月活」的三种说法互相打架（见上文表述纪律 1）。这一段的实用价值可能比横评本身还高。
- **关系说明**：公众号已发两篇实测（豆包工作发布测评、豆包 PC 版体验），口播稿角度是「差别不在功能表」，不重复。
- **截图建议**：架构图 `skill-card`（三家功能对照表）；正文 `data-board`（数据口径对比）
- **撞车检查**：与公众号实测文章角度不同，可互相引流

### D15. 云电脑还是本地电脑？这不是隐私问题，是两种风险

- **核心冲突**：大家都说本地更安全。真的吗？
- **三层提问**：本地运行防住了什么？→ 本地运行防不住什么？→ 那到底该怎么选？
- **干货锚点**：
  - 本地防的是**数据外泄**（文件不出本机，政务 / 金融 / 律所合规刚需）。千问办公明确把「隐私敏感的本地文件处理」归给桌面端。
  - 本地防不住**文件被毁**——本机高权限运行、暴露的本地 API 端点、提示词注入风险一样存在。
  - **核心区分**：这是两类完全不同的风险，宣传话术常把它们混为一谈。国内现实是「本地执行能防数据外泄，但防不住文件被毁」。
  - 配置落差是硬伤：豆包云电脑实测 2 核 4G，重任务不丝滑。
  - 选型建议：按任务类型分——涉密文档走本地，长耗时批量任务走云端。
- **截图建议**：架构图 `whiteboard`（两类风险对照）；正文 `checklist-card`（按任务选型）
- **撞车检查**：无

### D16. 一晚上烧掉 800 块：桌面 Agent 的成本陷阱

- **核心冲突**：它干活的时候，你不知道它在烧钱。
- **三层提问**：钱主要烧在哪？→ 为什么烧了你还不察觉？→ 怎么给它装个「电表」？
- **干货锚点**：
  - 烧钱结构：GUI 路线每走一步都是「截图 → 推理 → 动作」，截图按张算 token；循环检测失效时（比如页面一直加载不出来）会无限重试。社区案例：一夜死循环烧掉 800 多元。
  - 不察觉的原因：积分消耗不透明，任务跑完才知道花了多少。
  - 防线三条：给循环设最大步数上限、长任务拆成小任务分段跑、把重任务排到便宜时段（阿里「峰谷 Token」夜间 22:00—08:00 最低 2 折反过来说明白天贵）。
- **截图建议**：架构图 `swimlane`（一步 GUI 操作的 token 消耗链路）；正文 `checklist-card`（三条防线）
- **撞车检查**：与 `api-cache-hit-miss.md`（API 缓存差价）不撞，一个是 API 计费原理，一个是任务级成本失控

### D17. 别让 AI 直接上手，先给它划三条红线

- **核心冲突**：给了权限就出事，不给权限又干不了活。怎么办？
- **三层提问**：第一条红线划在哪？→ 第二条？→ 第三条？
- **干货锚点**（全部可操作，对应 C9 的三个翻车案例）：
  - 红线一：危险命令黑名单（`rm -rf`、`git reset --hard`、数据库 DROP、格式化），让 Agent 遇到就停下来问。
  - 红线二：授权目录最小化——只给当前项目目录，不给整个 home；敏感目录（`.ssh`、`.git`、密码库）单独排除。
  - 红线三：不可逆操作人工确认——删除、覆盖、外发、支付，这几类必须停下来问。
  - 加一条兜底：开工前先打快照（Git commit 或系统快照），出事能回滚。
- **定位**：全系列最实用的一期，收藏率会最高，适合放在安全板块后面做收束。
- **截图建议**：架构图 `checklist-card`（三条红线）；正文 `swimlane`（开工前快照流程）
- **撞车检查**：无

## E. 职业与未来（3 个）— 最容易引发讨论

### E18. 「嘴替能力尚可，手替能力还不太行」——桌面 Agent 的真实水位

- **核心冲突**：社区这句总结太准了。为什么「说」已经很好了，「做」还不行？
- **三层提问**：嘴替这部分做到什么程度了？→ 手替卡在哪？→ 这个坎什么时候能过去？
- **干货锚点**：
  - 嘴替（生成文字、写文档、做 PPT 大纲）已经接近可用。
  - 手替的三类具体卡点：复杂图形界面识别偶有偏差、多表关联的公式会报错、识图时会把按钮的名字编出来（幻觉）。
  - 根因：嘴替是模型能力的直接外溢，手替要额外过一道「感知 → 定位 → 执行」的关卡，每道都有损耗。这也是为什么命令行那条路效率能高一个量级——因为它绕开了这三关。
- **截图建议**：架构图 `three-layer`（嘴替 / 手替 的能力水位对照）；正文 `swimlane`（感知→定位→执行 的三道损耗）
- **撞车检查**：无

### E19. 大厂做产品的方式变了：先让 AI 把东西做出来

- **核心冲突**：腾讯的人自己说，他们不写文档了。
- **三层提问**：原来的流程是什么，现在变成什么了？→ 这个变化带来了什么结果？→ 对我们普通人意味着什么？
- **干货锚点**：
  - 汤道生的公开表述：「过去做产品，往往要先写文档、评审、排期，再进入开发；而 WorkBuddy 团队是先让 AI 把东西做出来，大家围着一个能跑的原型看效果、提意见、再调整。」

  - 引申：AI 时代人的学习顺序反过来了——以前是思想 → 语言 → 行动，现在是行动 → 语言 → 思想。因为 AI 让做出原型的成本趋近于零。

- **截图建议**：架构图 `swimlane`（旧流程 vs 新流程）；正文 `three-layer`（思想/语言/行动 的顺序反转）
- **撞车检查**：与公众号 `agent-mianshi-tengxun-workbuddy.md` 有部分素材重叠，但口播稿主线是「做产品的方式变了」，文章主线是面试题，可复用不冲突

### E20. 桌面 Agent 岗位面试，面试官盯着问的三个问题
