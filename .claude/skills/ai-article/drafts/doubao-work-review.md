大家好，我是二哥呀。

前两天豆包出了一个新产品，我体验了一下午，来跟大家聊聊。

豆包工作，一个全新 AI 办公 Agent，能自己拆解任务、操作你的电脑、直接把结果写进飞书云文档。

你说一句话，它干完交活。

跟飞书是原生打通的，企业文档、群聊、会议、任务上下文都能继承。

我在本地已经下载安装了。

![](https://cdn.paicoding.com/stutymore/sucai-20260826192449.png)

首次打开的界面非常清晰，非常简洁，是我喜欢的样子。

>这是豆包工作的官网：https://www.doubao.com/work

让我惊喜的是，豆包工作有一个多端同步功能，值得小吹一下。

它有两种工作模式——本地电脑和云电脑。

本地电脑就是你的本地电脑了（皮。云电脑就是豆包工作在云端帮你开的一台虚拟机，24 小时在线。

什么意思呢？

就是你本地的电脑关机了、睡眠了，任务照样可以切换到云电脑继续跑。

相当于我用了豆包工作，还能额外获得一台云服务器？

对，你没理解错。

![](https://cdn.paicoding.com/stutymore/sucai-20260826200256.png)

用法很简单，工作任务选择本地电脑或者云电脑就行了。

豆包 APP 端也是可以同步的。比如说，你在手机端把工作任务从云电脑切换到本地电脑的时候，上下文也可以共用。

注意看，这是我的手机端。我一开始用的是云电脑，现在切换到了本地电脑。

![](https://cdn.paicoding.com/stutymore/sucai-c07ead3887f426e2d7d69021f3f08bd8.jpg)

我电脑上的豆包工作也跟着从云端自动切换到了本地电脑。

![](https://cdn.paicoding.com/stutymore/sucai-20260826200606.png)

换句话说，你可以在手机端派活，也可以在电脑端派活，豆包工作的执行环境可以选云端，比如说你需要操作飞书文档这种不需要本地环境的任务；也可以选你本地的电脑，如果你的任务是需要操控本地电脑的话，比如说编辑本地文件。

![](https://cdn.paicoding.com/stutymore/sucai-20260826200720.png)

再换句话说，有没有电脑，你都可以随时随地派活给豆包工作，让它为你做牛做马，哈哈。

下面来实际体验一下豆包工作的几个核心能力。

## 01、一句话派活

我最近刚上架了一个产品——派简历（resume.paicoding.com），一个基于 AI 的智能简历优化工具。

【截图：派简历官网首页；风格：skill-card；截图目标：展示派简历的产品界面和核心功能；关键词：派简历、AI简历、智能优化】

产品刚上线，正好需要一篇宣传文档发到群里做推广。再顺手更新一下我的 GitHub 主页，把派简历这个项目加上去。

以前这种活至少得开两个窗口——一个写文档，一个改 GitHub README。写文档之前还得自己整理一遍产品卖点、列出功能清单、想好文案结构，怎么也得花个把小时。

现在一句话丢给豆包工作：

「帮我写一篇派简历的宣传文档，我的产品地址是 resume.paicoding.com，重点突出 AI 智能优化和一键生成这两个卖点。写完输出飞书云文档。然后再帮我更新一下 GitHub 主页的 README，在项目列表里加上派简历。」

【截图：豆包工作对话输入界面；风格：swimlane；截图目标：展示一句话下达两个任务的操作过程；关键词：对话框、任务输入、一句话派活】

豆包工作拿到任务后，自己做了拆解。

第一步，它先去 resume.paicoding.com 浏览了一遍产品页面。我看它把首页的功能介绍、使用流程、技术栈这些信息都扒了下来，还看了一下页面底部的常见问题。信息搜集这一步做得挺细的。

然后开始组织文案。它给文档分了三个板块——产品定位与背景、核心功能详解、快速上手指南。每个板块下面还拉了几条要点，层次很清晰。

【截图：豆包工作自动浏览网站并拆解任务；风格：swimlane；截图目标：展示 Agent 自主浏览网站、提取信息、拆解任务的完整过程；关键词：自主浏览、信息提取、任务拆解】

几分钟后，我打开飞书，文档已经在那了。

标题、正文结构、功能亮点、使用引导，全安排好了。我翻了一遍，产品卖点基本都抓到了，AI 智能优化和一键生成放在了最前面，优先级对的。有些措辞稍微有点官方，这个我后面自己润色一下就行。

但整个框架和内容方向都省了，我只需要在这个基础上改措辞、补细节。

【截图：飞书云文档直接交付；风格：skill-card；截图目标：展示豆包工作直接生成并交付到飞书的宣传文档；关键词：飞书文档、直接交付、自动生成】

接着，豆包工作自动切到了第二个任务——更新 GitHub 主页。

它在我电脑上操作终端，找到了我 GitHub 主页的仓库，打开 README 文件，在项目列表里加上了派简历的名称、一句话介绍和链接，commit message 都帮我写好了。

我看了一下改动，格式和其他项目保持一致，没有乱排版。

【截图：GitHub 主页 README 更新结果；风格：skill-card；截图目标：展示 GitHub 个人主页的 README 被自动更新后的效果；关键词：GitHub主页、README更新、项目列表】

整个过程我就打了一段话，没切过窗口。

这就是我觉得豆包工作和普通 AI 对话工具最大的区别——交付的是成果。飞书文档直接生成好，不用我复制粘贴再排版；GitHub 直接改好，不用我自己开终端敲命令。

一个工具，两件事，干完收工。

## 02、反推 Skill + Seedance 创作

这个玩法是我自己想的，觉得挺好玩。

我之前用 Codex 给公众号文章生成了一些配图，就是那种截图占位符风格的插画。发出去之后，好多小伙伴在后台留言问我怎么做的，想要一个 Skill 或者提示词。

【截图：之前 Codex 生成的文章配图示例；风格：skill-card；截图目标：展示之前用 Codex 生成的配图风格和效果；关键词：Codex配图、截图占位符、文章插画】

这个需求我一直没顾上整理。正好豆包工作到手，我想试试它能不能帮我搞定。

思路很简单——把一张 Codex 配图丢给豆包工作，让它帮我反推出风格描述和可复用的 Skill。

「看看这张图片，帮我拆解它的风格特征——配色方案、构图方式、元素类型、字体风格、背景处理这些，然后整理成一个可复用的 Skill。我希望以后输入不同的主题和关键词，就能生成类似风格的配图。」

【截图：上传配图并要求反推 Skill；风格：swimlane；截图目标：展示上传图片后豆包工作开始分析的交互过程；关键词：图片上传、风格分析、反推 Skill】

豆包工作的图片理解能力给了我一个小惊喜。

它把配图的风格拆得挺细。我摘几条它分析出来的内容：主色调是深蓝到浅蓝的渐变色系，信息层级通过卡片式分区来划分，图标用的是线性描边风格而非填充风格，文字排版左对齐、标题加粗、正文常规，背景有轻微的网格纹理增加层次感。

这些细节我自己看图都未必能条理清楚地说出来。它还总结了一条我没注意到的——配图的整体比例接近 16:9，信息密度控制在每张图三到四个关键信息点以内。

【截图：豆包工作的图片风格分析结果；风格：skill-card；截图目标：展示豆包工作对配图风格的详细拆解；关键词：风格拆解、配色方案、构图分析】

接着它帮我整理了一份完整的 Skill 描述，包含了配色模板、构图规则、元素选用标准、文字排版约束。结构很清晰，我看完觉得以后直接丢给任何一个 AI 绘图工具都能用。

【截图：生成的完整 Skill 模板；风格：skill-card；截图目标：展示反推生成的可复用 Skill 内容；关键词：Skill模板、风格规则、可复用】

下面就是这个玩法最有意思的部分了——用这个 Skill 直接生成新配图。

豆包工作内置了字节自研的 Seedance 和 Seedream 模型。Seedance 生成视频，Seedream 生成图片。不用跳到别的工具，在对话里就能直接调用。

我试着用刚才反推的 Skill，让 Seedream 帮我按截图占位符的规格生成一张新配图：

「用刚才的配图 Skill，帮我生成一张风格为 data-board 的配图，主题是『豆包工作核心能力一览』，关键词：多端同步、云电脑、Skill 调用。尺寸 16:9。」

【截图：Seedream 生成的新配图；风格：data-board；截图目标：展示用反推 Skill 配合 Seedream 生成的配图效果；关键词：Seedream、AI配图、data-board】

效果我给 85 分。

整体风格方向对了，配色也还原了大部分，卡片式布局的感觉出来了。细节上还有改进空间——中文字体的渲染不够精细，有些笔画糊在一起了。但作为文章插图来用，已经完全够了。

我又换了个主题试了一张，这次用 whiteboard 风格，主题换成架构图。出来的效果也还行，风格统一度保持住了。

【截图：第二张 Seedream 配图；风格：whiteboard；截图目标：展示换主题后的配图一致性；关键词：whiteboard风格、架构图、风格一致】

这个工作流以后能省我不少事——上传参考图 → 反推 Skill → 调用 Seedream 批量出图。换个主题、换组关键词就能生成新配图，不用每次都从头描述风格。

Skill 是可以持续迭代的，用几次之后根据实际效果微调参数，越用越顺手。之前小伙伴们想要的提示词，这下也能直接分享 Skill 了。

## 03、数据处理

我手上有一份派简历的用户修改记录，存在飞书文档里。

里面记录了每次简历修改的类型（格式优化、内容润色、项目重写等）、修改耗时、用户评分这些数据。之前一直想拉个报表看看各功能的使用分布，但手动整理太麻烦，就一直搁着。

正好试试豆包工作的数据处理能力。

【截图：飞书文档中的原始修改数据；风格：data-board；截图目标：展示飞书文档里的原始数据表格；关键词：飞书文档、简历修改数据、原始记录】

「帮我分析一下这份简历修改记录。先做一个柱状图，看看各修改类型的数量分布。再来一个饼图，看看用户评分的占比情况。」

豆包工作直接读取了飞书文档里的数据。

这一步的体验让我很舒服。因为飞书和豆包工作是原生打通的，数据直接就能读，我不需要先把飞书文档导出成 CSV，再上传到对话框里。用 ChatGPT 或者其他 AI 工具的话，这个「导出-上传」的流程是省不了的，虽然每次也就多花一两分钟，但积少成多就是效率差距。

【截图：豆包工作直接读取飞书数据；风格：swimlane；截图目标：展示直接读取飞书文档数据的过程和体验；关键词：飞书打通、直接读取、免导出】

柱状图先出来了。各修改类型的数量一目了然——哪种修改需求最多、哪种相对冷门，看一眼就知道了。

【截图：柱状图展示修改类型分布；风格：data-board；截图目标：展示生成的柱状图及数据分布效果；关键词：柱状图、修改类型分布、数据可视化】

饼图跟着就到，用户评分的占比分布也很清楚。

【截图：饼图展示用户评分占比；风格：data-board；截图目标：展示生成的饼图和评分分布；关键词：饼图、用户评分、占比分布】

我又追加了一个需求，「再来一个折线图，看看最近一个月每天的修改量变化趋势。」

豆包工作二话不说又出了一张折线图。三张图前后不到两分钟，速度很快。

【截图：折线图展示修改量趋势；风格：data-board；截图目标：展示生成的折线趋势图和时间维度分析；关键词：折线图、修改量趋势、时间分析】

有一说一，数据处理这块，豆包工作最大的优势就是和飞书的原生打通。

数据就在飞书里，豆包工作直接读取、直接分析、直接出图表，整个流程没有「导出-上传」的断层。对于本来就在用飞书的团队，这个体验差距是肉眼可见的。

## 04、后台运行 + 随时打断

这两个功能放在一起聊，因为它们解决的是同一个痛点——你不用干等着 Agent 跑完。

豆包工作支持小窗模式，把它缩到屏幕角落，Agent 在后台继续跑任务，你该干嘛干嘛。

【截图：豆包工作小窗后台运行；风格：skill-card；截图目标：展示小窗后台运行时的界面效果；关键词：小窗模式、后台运行、不占屏幕】

比如我让它分析数据生成图表的时候，我就切到浏览器继续改文章了。等它跑完会弹一个通知，我再切回去看结果就行。

这里还有一个小细节——因为任务可以选择在云电脑上跑，我本地的 CPU 和内存完全不受影响。这一点对 Mac 用户尤其友好，毕竟一个 AI 工具开着就占掉一两个 G 内存的体验，大家应该都有过。豆包工作在云端跑任务，本地不占资源，这一点确实想得挺周到。

另一个让我觉得很舒服的功能是随时打断。

豆包工作在执行任务的过程中，我可以随时插一嘴补充信息，不用等它跑完再重新来。

比如我让它写宣传文档的时候，它已经开始动笔了，我突然想到还需要加上定价信息。直接在对话框里打「对了，基础版免费，专业版 29 元/月，记得加上。」

豆包工作就自然地把定价信息融进了文档里。我不需要等它写完，然后说「重新来一遍，这次加上价格」。

【截图：随时打断补充信息的交互过程；风格：swimlane；截图目标：展示在 Agent 执行任务过程中随时补充信息的交互体验；关键词：随时打断、补充信息、自然交互】

这个交互体验确实更接近真人协作。你跟一个同事说「帮我写个文档」，写到一半想到一个点，随时补一嘴就行了，不用从头再来。
