### 01、软件 Agent 和具身 Agent 最核心的区别是什么？为什么具身 Agent 的错误成本更高？

“执行介质不一样。软件 Agent 通过 API 调用操作数据，具身 Agent 通过电机和执行器操作物理世界。”

软件 Agent 调一次工具，返回结果是一段 JSON。具身 Agent 执行一次抓取，返回结果是一个杯子被拿起来了——或者碎了。

时间约束也不同。软件 Agent 可以异步处理，等个几秒钟问题不大。

具身 Agent 走路时踩到坑洼，不能等几百毫秒再调整平衡，必须毫秒级响应。

【截图：软件Agent与具身Agent对比；风格：data-board；截图目标：对比两类Agent在执行介质、时间约束、可逆性上的差异；关键词：API调用、物理动作、实时性】

状态可逆性差异最大。软件 Agent 的操作大多能回滚，数据库有事务，文件有版本控制，API 调用可以做补偿。

具身 Agent 碰倒了杯子，没有 undo 按钮。撞到人了，更没法撤销。

所以具身 Agent 的错误成本天然更高。软件 Agent 最严重的后果可能是数据泄露或者服务中断，修复成本主要是时间和金钱。

具身 Agent 可能造成财产损坏甚至人身伤害，有些后果没法用钱解决。

### 02、VLM、VLA 和传统的“LLM+工具调用”架构有什么区别？分别适合哪些机器人任务？

“VLM 能看能说，VLA 能看能说还能动，LLM+工具调用靠 API 调用串起来。”

VLM（Vision-Language Model，视觉语言模型）接收图像和文本输入，输出文本。它能理解场景、回答问题、做高层规划，但不能直接输出关节角度或运动轨迹。

适合做任务分解和场景理解——“桌上有三个杯子，红色的那个离边缘最近”。

VLA（Vision-Language-Action，视觉语言动作模型）是端到端的。输入图像加文本指令，直接输出关节角度或末端执行器的位姿。

拿宇树2026年1月开源的 UnifoLM-VLA-0 来说，在 LIBERO 基准测试上平均分98.7，能直接把“拿起红色杯子”这句话变成一条抓取轨迹。

【截图：VLM/VLA/LLM+工具调用对比；风格：three-layer；截图目标：展示三种架构的输入输出差异和适用场景；关键词：VLM、VLA、工具调用】

LLM+工具调用是软件 Agent 最常见的模式。LLM 做推理和规划，通过 API 调用目标检测工具、路径规划工具、运动控制工具。

调用链长，每多调一次就多一段延迟，但灵活性强，中间步骤可解释、可调试。

拿“把红色杯子放到架子上”这个指令来说，VLA 可以端到端直接输出轨迹。LLM+工具调用要先解析指令，再调目标检测定位杯子，接着算路径规划的轨迹，最后交给运动控制执行，延迟翻了好几倍。

VLA 适合需要低延迟的操作任务——抓取、放置、装配。LLM+工具调用适合复杂多步规划——“帮我收拾房间然后做饭”，需要高层推理和多工具协调。

### 03、为什么机器人不仅需要“大脑模型”，还需要低延迟的运动控制“小脑”？

“控制频率差了几个数量级。大脑模型推理一次几百毫秒，小脑控制周期在毫秒级。”

大脑负责任务规划和决策。理解“帮我把桌子收拾干净”这句话，判断先拿什么后放什么，处理自然语言指令的歧义。

这些事情可以容忍几百毫秒的延迟，用户感知不明显。

小脑负责运动控制。让机器人走路时保持平衡、踩到不平的地面能立刻调整步态、抓东西时力度恰到好处。

控制周期必须在1到5毫秒，超过这个范围机器人的动作就会抖、会晃、会摔。

【截图：大脑与小脑分工架构；风格：three-layer；截图目标：展示大脑模型与小脑控制器的频率差异和职责分工；关键词：任务规划、运动控制、毫秒级】

举个例子，机器人在走路的时候踩到一块石头，脚底受力突变。如果把这个信号交给大脑的 VLA 模型来处理，推理一次差不多要两三百毫秒。

两三百毫秒之后机器人早就失去平衡摔倒了。

小脑的运动控制器用强化学习训练，部署在端侧，1毫秒之内就能输出关节力矩调整。宇树的 G1 能做侧空翻和鲤鱼打挺，靠的就是小脑层的高频控制。

宇树的技术架构就是三层——本体层做硬件驱动和传感器接入，小脑层用强化学习做运动控制，大脑层用 VLA 或 VLM 做任务理解和规划。

### 04、世界模型在具身 Agent 中承担什么作用？它与普通仿真器有什么区别？

“世界模型让机器人在动手之前，先在脑子里模拟一遍动作的后果。”

普通仿真器是工程师手写的物理引擎。把重力加速度、摩擦系数、碰撞弹性这些用数学公式建模，精确但脆弱。

现实世界里物体的变形、打滑、不规则表面这些情况，很难全部用公式描述。换个没建模过的材质，仿真器就可能算不准。

世界模型是从数据里学出来的。喂给它大量真实世界的视频和交互数据，让它学会“推一个杯子，杯子会往哪滑”“抬腿迈过障碍物，重心怎么变化”。

碰到训练时没见过的物体，它也能给出合理的预测，泛化能力比手写仿真器强。

【截图：世界模型与仿真器对比；风格：data-board；截图目标：对比二者在泛化能力、构建方式、适用场景上的差异；关键词：物理引擎、视频扩散、泛化能力】

#### 世界模型怎么训练？

宇树2025年9月开源的 UnifoLM-WMA-0，用的是视频扩散模型作为基础架构。

仿真引擎模块做交互式模拟，为机器人学习提供合成训练数据。策略增强模块和动作头对接，通过预测未来的交互视频来优化决策——机器人在做一个动作之前，先“想象”做完之后会发生什么。

【截图：UnifoLM-WMA-0架构；风格：whiteboard；截图目标：展示WMA的仿真引擎模块和策略增强模块的协作关系；关键词：UnifoLM、视频扩散、策略增强】

实际效果：在坑洼地面的场景里，用 WMA 生成了1000条跌倒和避障的视频来增强 G1 的步态强化学习训练。真实环境下的跌落率从12%降到了3%。

### 05、如何把行走、转身、抓取、放置、充电等机器人能力封装成类似 Skill 或 Tool Calling 的工具？

“每个原子动作封装成一个独立的 Skill，带前置条件、执行逻辑和后置断言。”

拿“抓取”这个 Skill 来说。

前置条件（Preconditions）：机械臂在工作范围内、目标物体已被检测到、夹爪处于张开状态。三个条件有一个不满足，这个 Skill 就不能被调用。

执行逻辑：移动到目标上方→下降到抓取高度→闭合夹爪→抬起。每一步的运动轨迹由小脑的控制器生成。

后置断言（Postconditions）：力传感器检测到夹持力在合理范围内，目标物体的位置和末端执行器位置一致。如果后置断言不满足，说明抓取失败了。

【截图：Skill封装结构；风格：swimlane；截图目标：展示一个原子Skill从前置校验到执行到后置验证的完整流程；关键词：前置条件、执行逻辑、后置断言】

组合能力通过任务图编排。“把杯子从桌子放到柜子里”拆成定位→导航→抓取→导航→放置→释放，每一步的后置断言就是下一步的前置条件，串成一条链。

宇树2025年12月上线了人形机器人的“App Store”，开发者可以上传和下载动作模型。就是这种 Skill 封装思路的产品化——跟软件 Agent 生态里的 MCP 工具市场异曲同工。

### 06、如果自然语言指令是“把桌面收拾干净”，Agent 应该如何将模糊目标拆解成可执行动作？

老王翻了翻手上的题目，继续问。

“收拾干净是个模糊目标，Agent 要自己搞清楚‘干净’是什么意思。”

第一步，视觉感知。调用目标检测模型扫描桌面，识别每个物体的类别、位置和姿态。

一个杯子、两本书、一包纸巾、一个手机充电器——先知道桌上有什么。

第二步，目标推理。根据常识判断哪些东西需要移走，哪些应该留着。

台灯、显示器属于桌面固定物品，不动。用完的餐具、零食包装需要清走，VLM 在这一步很关键——理解“干净”在当前场景里到底是什么标准。

【截图：模糊指令拆解流程；风格：swimlane；截图目标：展示从视觉感知到目标推理到动作生成到校验的完整流程；关键词：视觉感知、目标推理、动作序列】

第三步，动作序列生成。对需要移走的物体排优先级——易碎的先拿、重的后拿。

为每个物体生成抓取和放置的动作序列，确定放到哪里。

第四步，逐步执行加实时校验。每完成一个物体的操作，重新做一次视觉感知，确认物体确实被移走了，桌面状态在往“干净”的方向走。

#### 执行中途失败了怎么办？

比如说抓杯子的时候没夹住，杯子滑到了桌子边缘。

执行器在每个动作结束后检查后置断言。力传感器没有检测到夹持力，说明抓取失败了。

Agent 重新感知当前状态，发现杯子的位置变了。重新规划抓取策略——可能需要换个角度，或者先把杯子推到桌面中间再抓。

【截图：失败恢复与重规划流程；风格：swimlane；截图目标：展示后置断言校验失败后的重新感知和重规划过程；关键词：后置断言、重规划、反馈校验】

如果连续失败超过阈值，上报异常，请求人工介入。物理世界里不能无限重试，每一次失败都有可能让情况变得更复杂。

### 07、训练一个能完成工厂装配任务的 VLA 模型，需要采集哪些数据？

“三种数据同步采集，时间戳必须对齐。”

视觉流：多视角的 RGB 图像加深度图像。至少要有一个第三人称视角看全局，一个手眼相机视角看末端执行器正在操作的画面。

分辨率不低于640×480，帧率至少30fps。

语言标注：每段操作对应的自然语言描述。标注粒度很重要——“拿起螺丝”太粗，“从零件盒第二格拿起 M6 螺丝，拧到左侧面板第三个孔位”这种包含上下文的标注，模型才能学到精细的指令理解。

动作轨迹：机械臂各关节的角度、角速度、力矩，加上末端执行器的六自由度位姿和夹爪开合状态。采样频率至少50Hz，低于这个频率会丢失关键的动作细节。

【截图：VLA训练数据三要素；风格：three-layer；截图目标：展示视觉流、语言标注、动作轨迹三类数据的时间戳同步关系；关键词：视觉流、语言标注、动作轨迹】

数据质量比数量重要。一条高质量的演示轨迹——正确的抓取角度、合适的力度、流畅的路径——抵得上十条粗糙的。

Google 主导的 Open X-Embodiment 数据集汇集了22个机器人平台超过100万条轨迹数据，是目前最大的开源机器人数据集之一，做工厂装配任务的预训练底座可以从这里开始。

### 08、模型 OTA 升级后机器人行为发生退化，应该如何做灰度发布、回滚和版本追踪？

“金丝雀发布。新版本先推给1%的机器人，跑24到72小时。”

监控指标分两层。安全指标包括跌倒率、碰撞频次、急停触发次数。

性能指标包括任务成功率、平均完成时间、动作平滑度。安全指标有一项恶化就立刻回滚，不等其他指标。

版本追踪需要绑定三样东西——模型权重版本、策略配置版本、硬件固件版本。同一个模型在不同固件版本的机器人上行为可能不一样，因为传感器驱动和电机参数有差异。

【截图：OTA灰度发布流程；风格：swimlane；截图目标：展示从1%金丝雀到全量发布再到回滚的完整流程；关键词：金丝雀发布、安全指标、版本绑定】

回滚不能只回滚模型。如果新版本的模型适配了新的传感器驱动，只回滚模型不回滚驱动，接口可能对不上。

版本注册中心要维护完整的兼容性矩阵，回滚的时候按矩阵整体回退。

金丝雀通过之后逐步放量，10%→30%→100%。全量推送之后还要保持旧版本的回滚能力至少两周，出了问题能快速切回去。

### 09、如何设计具身 Agent 的 Memory？

“比软件 Agent 多一个维度——空间信息。”

工作记忆存当前任务的即时状态。正在执行“收拾桌面”，工作记忆里记着已经处理了3个物体，还剩2个，当前手里拿着一个杯子，目标是厨房的碗柜。

更新频率在毫秒级，每完成一个动作就刷新。

情景记忆存最近的交互事件。五分钟前用户说“那个蓝色的杯子别扔，是我的”，十分钟前在厨房门口差点撞到椅子。

这些信息帮助 Agent 避免重复犯错、尊重用户偏好。保留时长从几分钟到几小时。

【截图：具身Agent Memory分层架构；风格：three-layer；截图目标：展示工作记忆、情景记忆、语义记忆、空间记忆四层结构；关键词：工作记忆、情景记忆、空间记忆】

语义记忆存长期积累的环境知识——“这个家庭的垃圾桶在厨房角落”“主人的杯子是蓝色的那个”“客厅的地毯边缘容易绊脚”。通过多次交互逐渐积累，持久化存储，跨任务复用。

空间记忆是具身 Agent 特有的。维护一张动态的环境地图，记录房间布局、家具位置、通行路径。

椅子被挪了位置，空间记忆需要更新。软件 Agent 不需要这个，因为它操作的对象没有空间坐标。

检索方式按记忆类型走不同路径。工作记忆直接读，不用检索。

情景记忆按时间倒序召回最近的相关事件。语义记忆用关键词或语义检索。

空间记忆按当前位置做近邻查询——“我附近一米范围内有什么障碍物”。

### 10、真实机器人数据昂贵，如何结合仿真数据、合成数据和真实数据进行训练？

“仿真数据打底，合成数据补视觉差异，真实数据做最后微调。”

仿真数据在物理引擎里生成，量大、便宜、安全，可以大规模模拟各种极端场景——跌倒、碰撞、负重极限。真实环境里不敢做的实验，在仿真里随便做。

问题是 Sim-to-Real Gap，仿真里的光照、材质、物理特性和真实世界有差距。模型在仿真里训练效果好，到真机上可能不好使。

合成数据做域随机化（Domain Randomization），弥补视觉层面的差异。随机变换光照条件、物体纹理、背景颜色，让模型见过足够多的视觉变体之后，对这些差异不再敏感。

【截图：三类数据混合训练流水线；风格：swimlane；截图目标：展示仿真数据→合成数据→真实数据的训练流程和比例分配；关键词：Sim-to-Real、域随机化、微调】

真实数据最贵但最可靠。用真机采集的轨迹数据做最后一步微调，把仿真和合成数据覆盖不到的物理细节补上。

宇树的做法是用 WMA 世界模型生成合成视频数据。WMA 从真实视频里学到了物理规律，生成的合成数据比纯物理引擎更接近真实世界，成本又远低于真机采集。

在坑洼地面场景里，WMA 生成1000条避障视频增强 G1 的步态训练，跌落率从12%降到3%。

比例上，仿真和合成数据差不多占总量的80%到90%，真实数据占10%到20%。真实数据虽然少，但在微调阶段对最终性能的影响最大。

### 11、给一台人形机器人设计「把桌上的东西收拾好」这个任务的 Agent，你会怎么做？

老王端起茶杯喝了一口。

“这道题串联了前面大部分知识点，我按感知、规划、执行、反馈四个阶段来讲。”

感知阶段。给机器人装多个摄像头——头部广角摄像头看全局，手腕相机看末端执行器正在操作的区域。

用目标检测模型识别桌面上所有物体的类别、位置、尺寸，深度相机提供三维坐标。识别结果送进 VLM 做场景理解，判断哪些需要收走、哪些应该留着。

【截图：收拾桌子Agent完整架构；风格：whiteboard；截图目标：展示感知→规划→执行→反馈四阶段的完整架构和数据流；关键词：VLM、VLA、反馈校验】

规划阶段。VLM 输出一个任务清单——收走用完的餐具，把书放回书架，擦掉水渍。

每个子任务再拆解成原子动作序列，排列优先级，易碎的先处理，大件的后处理，液体先擦再收。

执行阶段。每个原子动作走小脑的运动控制器，VLA 模型接收当前视觉输入和动作指令，输出关节轨迹。

末端执行器的力控很关键——抓鸡蛋和抓铁锅用的力完全不一样，力传感器实时反馈调整夹持力。

反馈阶段。每完成一个物体的操作，重新做一次视觉感知——物体确实被移走了吗？桌面状态在往“干净”的方向走吗？

如果抓取失败了，触发重规划。任务完成后拍一张桌面全景图，和“干净”的参考状态做对比确认。

【截图：任务执行与反馈校验流程；风格：swimlane；截图目标：展示单个物体从感知到抓取到校验的执行循环；关键词：力控、视觉校验、反馈】

Memory 贯穿全程。工作记忆维护当前进度和手里物体的状态，情景记忆记住用户偏好——“蓝色杯子别扔”。

语义记忆知道各类物品应该放在哪里——碗放碗柜，书放书架。空间记忆维护家具布局和通行路径，机器人搬着东西走的时候不会撞到椅子。

### 具身 Agent 怎么写到简历上？

**项目名称**：PaiAgent——具身Agent任务编排与仿真平台 2026.03 – 2026.06

**项目简介**：面向人形机器人的多 Agent 协作平台，支持多层级任务调度、原子能力封装与编排、多模态感知与反馈控制、仿真与真实数据混合训练，集成分层 Memory 管理和灰度发布能力，覆盖从自然语言指令到物理动作执行的完整交互流程。

**技术栈**：Java 21、Spring AI、LangGraph4j、PyTorch、Isaac Sim SDK、MCP 协议、Redis

【截图：简历项目架构图；风格：whiteboard；截图目标：展示PaiAgent具身Agent平台的整体架构；关键词：多Agent调度、Skill封装、仿真训练】

**核心职责**：

- 设计多 Agent 分层调度架构，大脑层 VLM 负责自然语言指令解析和任务规划，小脑层运动控制器执行关节级动作，安全层做风险拦截和操作权限管控；按任务类型和实时性要求路由到对应 Agent，高频控制指令走端侧推理
- 基于 MCP 协议封装机器人原子能力（行走、抓取、放置、旋转），每个 Skill 带前置条件校验和后置断言验证，组合任务通过 DAG 自动编排调度；前置条件不满足时阻塞调用并上报状态，后置断言失败时触发重规划
- 设计四层 Memory 架构（工作记忆、情景记忆、语义记忆、空间记忆），工作记忆维护当前任务进度和执行器状态，情景记忆按时间窗口保留用户偏好和交互事件，语义记忆持久化存储环境知识，空间记忆维护动态环境地图并支持近邻查询
- 构建仿真-真实数据混合训练流水线，Isaac Sim 生成多场景仿真数据，域随机化弥补 Sim-to-Real 视觉差异，真实采集数据做最终微调；仿真与合成数据占训练集80%以上，真实数据做精调
- 实现模型灰度发布和版本追踪机制，通过版本注册中心管理模型权重、策略配置和硬件固件的兼容性矩阵，支持1%金丝雀发布和按安全指标自动回滚，全量推送后保持旧版本两周回滚窗口
