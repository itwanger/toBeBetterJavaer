# 二哥的统一表达标准（口播稿与技术文章共用）

## 1. 正向表达规范

口播稿与技术文章共用一套“短句主谓宾 + 准确技术标识”的干练表达：

- **主语直接用产品名或组件名**：直接写“Codex 会读取 `title`”“`cua_repl` 会反向给 Codex 发一个 `elicitation/create` 审批请求”“翻开 Codex 的源码”。
- **动词干脆直接，一步到位**：用直白的动作词串起执行流程（如“挂载、暴露、读取、折叠、设定、挂起、放行、切换、跑、切到、查、塞进”），讲完动作本身即止（如“拼接到报错末尾”“切换为同步阻塞”“保护 KV Cache”“点错了再撤销”）。
- **技术概念保留核心短标识**：常见术语与承载核心机制的短标识直接用英文（如 `cua_repl`、`js`、`code_mode_only`、`fork_turns`、Sub-agent、Multi-Agent、KV Cache、MCP），配合一句直白的中文动作说明。
- **问句与过渡句短促直接**：只问核心问题（如“Codex 怎么防止大模型被劫持？”“那第二个大招是什么？”），把触发条件和实现细节留给正文回答。
- **用单一强有力的数据或案例说话**：每次论证只选最有代表性的一个高分或一个实测现象（如“拿到了 60 的高分，反超了自家的 GPT-6.1 Sol，58.6 分”），直接进入“为什么？”的源码拆解。
- **数字与单位贴合日常读写**：容量写 `8 M`、`16 G`，状态分值写 `0`、`1`。

## 2. 禁用与替换词表（由 `scripts/wording_rules.py` 自动检查）

→ 左侧禁用，用右侧替换：

- **防多音字与语义歧义**：调（接接口/工具/模型时）→调用（防 TTS 读成 tiáo）｜容易混→容易混淆｜拆成/拆出→拆分
