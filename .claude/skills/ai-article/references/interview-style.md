# 面试类文章写作指南

> 面试八股类文章的完整规范。写之前通读一遍。

## 正文结构

`## content` 包裹所有面试题 → 每题 `### 01、问题`。章节标题是问题加问号；题目含两问的（"怎么做，怎么判断"），第二问拆成 `####` 四级标题。

**面试问答格式（强制）**：

每题由 `###` 标题提出问题，正文直接进入回答。老王的简短动作描写（推了推眼镜、端起茶杯、翻了翻简历）允许出现在题目过渡行（### 标题后的提问段落），用于制造面试推进的时间感。回答段落中禁止出现老王（参见 changxin 定稿）。

**对话体节奏**：

- 问句里术语写全："提示词的 system 层""超出上下文窗口"
- 引号内外交替形成节奏：核心观点和直接回答用引号，支撑细节、例证、原因用叙述展开。长段引号像念稿，交替使用让文章有层次——观点（引号）→ 例证（叙述）→ 观点（引号）→ 解释（叙述）。引号段同样不超过两个句号，超了就把后面的内容拆出来用叙述展开
- why 型追问升级成 `####` 四级标题，读者扫标题就能看到干货点，不埋在引号里自问自答

**回答内容的边界（强制）**：回答内容必须严谨——术语准确、数据具体、有出处。对话框架只负责组织问答节奏，不负责营造叙事氛围。

## 答题手册

**第一性原则：答案的边界就是题目的边界。先判断题型，题型决定答案的结构和项目是否出场。**

| 题型 | 识别特征 | 答法 | 项目出场 |
|------|----------|------|----------|
| 实现题 | 怎么处理 / 怎么做 / 怎么发现 | 手段列表（带锚点数字）+ 1 个 #### why | 出场，报真实数值 |
| 原理题 | 为什么 | 理由列表，答完即收 | 不出场，数字可为零 |
| 概念题 | 是什么 / 区别 | 同层对比定位 + 代表性产品实例 + 真观点 | 可不出场 |
| 理解题 | 怎么看 / 有什么理解 | 一句一个定位，敢下"目前最强"判断，快问快答 | 不出场 |
| 开放题 | 未来 / 趋势 / 判断 | 判断 + 理由，给完即收 | 不出场 |

**通用禁令（所有题型，出现即删）**：

1. 金句规则同 `human-tone.md`「金句用法」一节（遮句测试）。面试类额外补充的烂金句例子："每进来一条都要付租金""模型是引擎，harness 是整车"——遮住什么都不少，删
2. 零收尾（单题答案，不含全文 ending）：不要总结段、不要升华句、不要跨章节叙事（"这就是后面那些题在问的事"），最后一个知识点说完直接结束
3. 不在内容前面贴标签，不宣告规则。两种高频变体：
   - **先行评价**："原因也很直接：""有一个关键的工程细节：""量级决定方案""重点来了"——读者还没看到内容，作者先下了判断或预告了重要性。回答里复述题目也是先行评价（题目问"完整流程"，回答说"走一遍完整流程"）。引号内的附加评价也是先行评价——"工具并行，对用户体感提升最直接""提示词分层管理，对质量稳定性帮助最大"，改成"第二，工具并行。"直接报结论，评价交给读者。**高频变体**："核心是""核心就一条""核心做法是""思路是""本质是""有一个细节很重要""好处是""这样做的好处是"。判断标准：关键词后面紧跟具体内容（同一句话内直接给出做法或结论）可以保留（"思路是'近处保全、远处摘要'"——changxin 定稿）；独立成句充当标签（"核心是这样的："后面另起一段展开）则删掉
   - **分类引出**："设计了三个执行路径——""两层压缩机制，分别是——"——先宣布数量和类别，再用破折号或冒号引出列表。改法：去掉分类标签，直接描述每一项做什么
4. 正面说完不补反面：同一件事只从一个方向讲
5. 不借题发挥：题目没问的（选型建议、行业优势、自家项目的取舍反思）不答；诚实交底全文至多 1 处
6. 零金句不等于零观点：对具体功能的批评性判断欢迎（"说实话，这个命令不该有"），敢喷具体的点

**why 名额**：一题选 1-2 个最值得展开的 why（通常升级成 ####），其余知识点只留规则不留解释。全文 #### 追问控制在 2-3 个，多数题答完即收——changxin 定稿 10 道题只有 2 道用了 ####（07 和 09），节奏干净利落。

**"第一/第二/第三"使用限制**：实现题允许用"第一""第二"编号列举手段（因为实现手段天然是并列的），但概念题、原理题、理解题、开放题不应该用有序编号。全文"第X"出现不要超过 10 次，超了说明在列举而不是在讲道理。

**禁止分类框架（全文适用）**：

- 禁止宣布数量再展开："分三层。第一层是索引层……"→ 直接描述每一层做什么，不报数量不编号
- 禁止分类式开头："防重复下单靠两件事：幂等 key 和状态机。"→ 直接讲做法
- 禁止清单式总结再展开："任务生命周期覆盖五个方面：……"→ 从最重要的方面直接讲起
- 可以用的：描述事实时附带的数量（"保留最近 20 条消息""超时 60 秒"）不算分类框架。判断标准：去掉这个数量词，句子还成立吗？成立就是分类框架，删；不成立就是事实描述，留

## 回答策略

- 开头引号段必须直接回答题目问的问题，不能先报项目经历再答题。项目经验在后续展开段落里自然带出来
  - 正例（直答）："购物这种多步骤的业务流程，我会用 Plan-and-Execute 模式来做。"
  - 正例（直答）："PaiCLI 没有用任何 AI 框架，全部自研。"——虽然提了项目名，但这句本身就是在回答问题
  - 反面（先报简历）："做过一个 RAG 知识库，用的是 ES 混合检索……"——先介绍项目，绕了一圈才碰题目
- 深讲 2 个好过浅讲 3 个：面试时间有限，挑印象最深、能讲出设计细节和权衡取舍的点
- 先给完整利益链，再举项目例子：技术手段 → 机制 → 效果 → 业务价值，然后用"比如说"引出项目实例
- 主动暴露局限 + 对策："当然了，为了避免...信息丢失，我们会...""暂时用关键词匹配"。"暂时"这种词是加分项，说明你知道这不是最优解
- 概念题不铺摊子：挑 2-3 个最重要的点，只展开最值得讲的那个（通过 #### 追问钻深），其余一两句话带过
- Why 型追问先给本质原因：不要用抽象总结开头，先给 because，再给 so
- 引用前文不用引号：前文已讲的内容只是连接，不是新观点

## 调查与证据写法

面试类文章的竞争力不是文笔，是**调查深度**。读者来看这类文章，是因为作者做了他们没时间做的事：读源码、翻 PR、跑实验、拆机制。

**源码证据写法**（需要引用源码时）：

1. 只截取和观点直接相关的片段（5-15 行），标注来源路径
2. 代码前一句说"在做什么"，代码后一句说"意味着什么"——没有解读的代码就是噪音
3. 筛选标准：只保留推翻常见误解、量化模糊概念、暴露设计取舍的代码

**常见失败模式**：

- 堆砌源码不解读：贴了 200 行代码，读者看完依然不知道和自己有什么关系
- 用源码装饰结论：先有结论再找代码来"证明"，即使不贴代码结论也不会变——这种源码是装饰品，不是证据
- 平铺知识点无递进：10 道题各自独立像百科词条合集。好的文章题目之间有递进关系

## 数字纪律

锚点数字按题型出场（实现题 2-4 个、原理题可为零）；同一个数字全文只出现一次，放在最需要它的论证位；估算类数值用约数（"差不多占到 80%"），面试时没人报小数点。量化对比用真实产品定价——"拿 DeepSeek V4 来说，缓存命中百万 Token 0.02 元，未命中 1 元，差了 50 倍"比"缓存命中只收十分之一"可信度高一个档次。

## 语言细则

- 口语缓冲词是加分项："差不多""假如""而已""可能也就""就目前来说"
- 敢下最强判断，带时间限定："就目前来说，Claude Code 就是最牛的终端 Agent"
- 对比用读者熟悉的参照物（"记忆库一千多条，RAG 知识库几十个 G"），参照物一摆结论自现
- 同层对比定位法：定义新概念拉相邻概念并排划边界，一人一句话
- 缩写和术语按受众调整：SKILL.md 要求缩写首次加中文，面试场景下按工程师受众放宽——KNN、BM25、DAG、DFS、OOM 这些工程师都知道的缩写不加括号解释。非工程常识的缩写仍然首次加中文（GQA → GQA（Grouped Query Attention，分组查询注意力）——changxin 定稿）
- 口语转场短语是加分项："举个例子""技术栈层面""简单来说""拿...来说吧"
- 流程描述用顺序连词串成叙事："再把结果发给 LLM""就把输出格式化为 HTML 返回给用户"。同时把数据流交代清楚——谁产出、谁接收、发给谁
- 步骤里嵌入一句原因：非显而易见的设计选择，在步骤描述里直接给理由，不用单开 #### why
- 产品实例绑个人经验："平场我用 Claude Code 也是这么做的"比"Claude Code 就是这么做的"更真实
- 术语用精确的：不存在"小模型"，都是大模型（LLM）。参数规模对比时用"大尺寸模型/小尺寸模型"，泛指 LLM 品类时"大模型"直接用

## 表达纪律

1. **禁止凭空编造量化数据，包括时间估算** — 只用有实测依据的数字，或者用模糊表达。时间估算必须和任务实际难度匹配（一个简单 MCP Server 实现，有 AI 辅助一个多小时就能跑通）
2. **结论句不堆技术名词** — 判断句写清判断即可，技术细节在展开段落里讲
3. **用当下视角回答** — 2026 年 AI Coding 能力已经很强，面试回答要体现当下认知
4. **用常见的书面用语** — "地带"→"地方"，"缩小幻觉的发生面"→"减少幻觉的发生"。自造的术语化短语（"优先级链"）换成平实动词短语（"按照优先级排列"）
5. **动词和形容词写全，名词不加多余后缀** — 该加的加："交"→"交给"。该删的删："重排序层"→"重排序"，"生产化"→"生产"。"层""化"后缀在不增加信息量时一律去掉
6. **不加不必要的修饰词** — "三个核心差异"→"三个差异"。如果去掉修饰词读者不少知道任何信息，就是多余的
7. **不用夸张对比** — 面试场景里夸张对比像在表演，直接陈述结果
8. **举例用面试公司生态产品** — 面试阿里用千问 Embedding，面试小米用小米系产品，面试字节用豆包系产品
9. **称呼用更亲切的** — 阿里内部互称"同学"，面试场景下用更亲切的称呼
10. **回答不溢出候选人身份** — 候选人是工程师就不讲读论文
11. **对话体里不加过渡句** — 对话本身的问答节奏就是最好的过渡
12. **回答深度匹配题目层级** — 项目介绍题停在功能层面，实现细节留给追问题
13. **#### 标题写全主语，用词和正文一致**
14. **不自问自答** — 原因直接给就行
15. **删概括性尾句** — 前面已经讲清楚了，再概括一遍是水分
16. **泛称改具体名词** — "主循环"→"ReAct 循环主体"

## 简历纪律

- 每条直接写"做了什么 + 结果"，不加包装前缀
- 不堆限定词（"三级风险等级的人机审批"→"人机审批"）
- 不重复表达（"保障质量不回退"="保障质量"）
- 名词后缀同表达纪律第 5 条（"生产化架构"→"生产架构"）
- 简历中的数字必须有实测依据，没有实测的用定性描述

## 技术细节尺度

SKILL.md 格式硬规则全部适用。面试类额外强调：回答要像真实面试中的表述，讲原理和设计动机，不是在念源码注释。

## Ending 写法

ending 是读者看完全文后的最后印象，不能每篇都像复制粘贴。**连续两篇不能用同一种路子。**

以下四种路子选一种，也可以自己造新的，但必须满足底线规则。

### 路子一：时代对比感

用本文的具体考点列举，点出"以前面试不会问这些"的时代变化，然后一句判断收尾。参考 changxin、zijie 定稿。适合题目覆盖面广、考点多的文章。

### 路子二：一个判断

从这篇文章里提炼一个关于技术方向或工程师成长的判断，用几段短句展开，像在和读者说心里话。参考 deepseek-harness 定稿——"Harness 将成为未来五年内的主题""信我说的，准没错"。适合文章有明确的技术趋势判断时用。

### 路子三：给读者打气

不列考点，不下判断，就是站在读者的角度说几句鼓励的话。参考 tengxun-3 定稿——"底层还是那么点东西，唯一需要我们去做的，就是给自己信心"。适合文章难度高、读者可能有压力感的时候用。

### 路子四：留个问题

抛出一个和本文相关但没有展开的问题，引导读者自己去想或者留到下一篇。适合系列文章之间有承接关系的时候用。

### 底线规则

1. **ending 必须从当篇文章的内容里长出来**，不能套公式。读者看完 ending 应该知道这是哪篇文章的结尾，而不是随便哪篇都能用
2. **不概括全文**——前面已经讲清楚了，ending 不是摘要
3. **加粗金句至多一句**，且必须通过遮句测试（遮住这句话，读者少知道什么？答案是"什么都不少"就删）
4. **最后一句收干净**——可以是"下期见"，也可以不是，但不能拖泥带水
