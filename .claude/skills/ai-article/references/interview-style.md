# 面试八股类规范

主参考全文见 `agent-mianshi-xiaomi.md`。

## 标题

素材里有现成标题直接用，末尾加“（附Agent面试题）”式括号后缀。公众号标题上限 64 字，超了先砍薪资细节数字，保住冲突和后缀。

## 正文结构

`## content` 包裹所有面试题，每题 `### 01、问题？`。题目里的追问拆成 `####` 四级标题，值得展开的 why 也升级成 `####`，读者扫标题就能看到干货。

- 题目直接问，不写面试官的表情、动作、神态
- 回答默认放在“”引号里；成段的概念讲解可以脱离引号直接叙述
- 问句里的术语写全（“提示词的 system 层”“超出上下文窗口”）

## 按题型答题

答案的边界就是题目的边界，先判断题型。

| 题型 | 识别特征 | 答法 | 项目出场 |
|------|----------|------|----------|
| 实现题 | 怎么处理 / 怎么做 / 怎么发现 | 从问题的根源顺下来，前一个手段解决不了的引出下一个手段 | 出场，报源码里的真实数值 |
| 原理题 | 为什么 | 理由之间有因果或递进，答完即收 | 一般不出场 |
| 概念题 | 是什么 / 区别 | 拉相邻概念并排划清边界，给代表性产品实例和自己的观点 | 可不出场 |
| 理解题 | 怎么看 | 敢下带时间限定的判断（“就目前来说，Claude Code 是最强的终端 Agent”） | 不出场 |
| 开放题 | 未来 / 趋势 | 判断加理由，给完即收 | 不出场 |

## 答案往前走

每段回答上一段留下的问题。检验方法是打乱段落顺序，还能读通就说明是并列罗列，要重写。

反例（每段各讲一个方案，打乱顺序照样能读）：

> “我认为记忆污染有两类，一类是过时的信息，另一类是错误的积累。解决这个问题可以有三个方案。”“第一个是给记忆条目加过期时间……”“第二个是写入前做语义去重……”

正例（用户认可的定稿）：

> “我会先分清楚污染是怎么来的。一种是信息过时，配置已经变了，记忆里还是旧的。另一种是错误累积，Agent 把一次错误的结论写进记忆，后面的决策都建立在这个错误上。”
>
> 过时的问题好办，靠过期时间和去重，新的记忆进来，旧的那条就让位。
>
> 错误累积更麻烦。错的记忆不会自己过期，去重也识别不出来，只能定期抽一批出来人工复核，哪一类错得多就整类清掉重建。

## 禁令

- 单题答案不写总结段、升华句，不跨章节叙事（“这就是后面那些题在问的事”），最后一个知识点说完就结束
- 不写“重点来了”“再写死一条硬规则”这类小总起和规则宣告
- 不借题发挥，题目没问的不答；不承认自家项目的不足，源码没做到的按期望方案作答，差距写进项目升级计划
- 批评具体功能的判断欢迎（“说实话，这个命令不该有”）
- 不用夸张对比（“比读十遍文档都深”），直接陈述结果
- 对话体里不加“但光看不行”这类过渡句

## 面试场景的语境

- 用当下视角回答：现在 AI Coding 能力很强，自研门槛已经很低了，不用两年前的视角
- 举例用面试公司生态的产品，并和候选人项目里实际用的一致（面试阿里用千问 Embedding，派聪明实际用的也是阿里百炼的文本向量模型）
- 称呼用“同学”这类更亲切的说法
- 回答不超出候选人身份：工程师不讲自己读论文
- 结论句写清判断即可，技术栈细节放到展开段落里

## 简历

每条直接写“做了什么 + 结果”，不加包装前缀，不堆限定词，不重复表达。

## Ending

事情讲完就停，一两句话收完，“下期见”可以保留。判断必须来自这篇文章的题目，不能是放进任何一篇面试文都成立的万能句。以下模板禁用：

- “以前拼八股文……现在问的是……”
- “技术栈在变，但……没变，谁能……谁就是稀缺的”
- 前言收尾句逐字复用到 ending
