# 面试类文章写作指南

> 写之前通读一遍。核心只有一件事：像一个真正懂行的人在面试中回答问题。

## 正文结构

`## content` 包裹所有面试题 → 每题 `### 01、问题`。题目含两问的，第二问拆成 `####` 四级标题。

**面试问答格式**：每题由 `###` 标题提出问题，正文直接进入回答。回答段落中不出现面试官的动作描写。

**引号内外交替**：核心观点和直接回答用引号，支撑细节和例证用叙述展开。引号段不超过两个句号。观点（引号）→ 例证（叙述）→ 观点（引号），形成层次感。

**why 追问**：一题选 1 个最值得展开的 why 升级成 `####`，全文 #### 控制在 2-3 个。多数题答完即收。

## 好的面试答案长什么样

**直接。** 开头引号段必须直接回答题目问的问题，不绕弯子不先报项目经历。

**有变化。** 10 道题的答案长度和结构必须不一样。有的题三四段收掉，有的题展开七八段。有的先给结论再解释，有的先讲做法再说原因，有的用反问引出关键点。如果每道题读起来节奏都差不多，说明在用模板。

**知道什么该详、什么该略。** 有源码支撑的项目题可以多展开，讲出设计细节和取舍。没有源码的场景题讲清思路就收，不要编造实现细节和精确数字。

**写完敢砍。** 写完一道题删掉三分之一再读一遍，没有信息损失的部分就是水分。

## 题型判断

先判断题型，题型决定答案的结构和项目是否出场。

| 题型 | 识别特征 | 答法 | 项目出场 |
|------|----------|------|----------|
| 实现题 | 怎么处理 / 怎么做 | 手段 + 1 个 #### why | 出场，报真实数值 |
| 原理题 | 为什么 | 理由，答完即收 | 不出场 |
| 概念题 | 是什么 / 区别 | 对比定位 + 真观点 | 可不出场 |
| 理解题 | 怎么看 / 有什么理解 | 定位 + 判断 | 不出场 |
| 开放题 | 未来 / 趋势 | 判断 + 理由，给完即收 | 不出场 |

## 语言上怎么写好

- 口语缓冲词是加分项："差不多""假如""而已""就目前来说"
- 敢下判断，带时间限定："就目前来说，Claude Code 就是最牛的终端 Agent"
- 对比用读者熟悉的参照物，参照物一摆结论自现
- 产品实例绑个人经验："平场我用 Claude Code 也是这么做的"
- 流程描述把数据流交代清楚：谁产出、谁接收、发给谁
- 数字只用有出处的（源码、文档、实测），没出处就用模糊表达
- 技术术语按工程师受众：KNN、BM25、DAG 不用加括号解释

## Ending 写法

ending 从当篇内容长出来，不套公式。四种路子选一种：

1. **时代对比感** — 点出"以前面试不会问这些"的变化，一句判断收尾
2. **一个判断** — 提炼一个关于技术方向的判断，几段短句展开
3. **给读者打气** — 不列考点不下判断，站在读者角度鼓励
4. **留个问题** — 抛出一个没展开的问题，引向下一篇

底线：不概括全文，不列题目清单回顾，加粗金句至多一句。
