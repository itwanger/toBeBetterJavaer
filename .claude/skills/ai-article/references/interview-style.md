# 面试对话类专属规范

> 仅在步骤 4 选择「面试对话类」时读取本文件。主参考正例全文见 `agent-mianshi-xiaomi.md`。

## 标题（面试类）

素材里有现成标题直接用，末尾加“（附Agent面试题）”式括号后缀标注干货属性。公众号标题上限 64 字，超了优先砍薪资细节数字，保住冲突和后缀。

## 正文结构（覆盖通用规则）

`## content` 包裹所有面试题 → 每题 `### 01、问题`。章节标题是问题的加问号；题目含两问的（“怎么做，怎么判断”），第二问拆成 `####` 四级标题。

**对话体框架**：

- 问句里术语写全：“提示词的 system 层”“超出上下文窗口”
- 回答默认带“”引号；成段的概念讲解可以脱离引号直接叙述（04 定稿），引号留给真正的对话往来
- why 型追问升级成 `####` 四级标题，读者扫标题就能看到干货点，不埋在引号里自问自答

**面试问答格式（强制）**：

题目直接问，不加面试官的表情、动作、神态描写。每题由 `###` 标题提出问题，正文直接进入回答，干净利落。

**对话体的边界（强制）**：回答内容必须严谨——术语准确、数据具体、有出处。对话框架只负责组织问答节奏，不负责营造叙事氛围。

## 答题手册（强制，2026-07-22 系统化定稿）

**第一性原则：答案的边界就是题目的边界。先判断题型，题型决定答案的结构和项目是否出场。真有东西可讲。**

| 题型 | 识别特征 | 答法 | 项目出场 | 定稿参考 |
|------|----------|------|----------|----------|
| 实现题 | 怎么处理 / 怎么做 / 怎么发现 | 手段列表（带锚点数字）+ 1 个 #### why | 出场，报真实数值 | 01、10、15 |
| 原理题 | 为什么 | 理由列表，答完即收 | 不出场，数字可为零 | 05 |
| 概念题 | 是什么 / 区别 | 同层对比定位 + 代表性产品实例 + 真观点 | 可不出场 | 04 |
| 理解题 | 怎么看 / 有什么理解 | 一句一个定位，敢下“目前最强”判断，快问快答 | 不出场 | 07 |
| 开放题 | 未来 / 趋势 / 判断 | 判断 + 理由，给完即收 | 不出场 | 06 |

**通用禁令（所有题型，出现即删）**：

1. 金句规则同 `human-tone.md`「金句用法」一节（遮句测试）。面试类额外补充的烂金句例子：“每进来一条都要付租金”“模型是引擎，harness 是整车”——遮住什么都不少，删
2. 零收尾（单题答案，不含全文 ending）：不要总结段、不要升华句、不要跨章节叙事（“这就是后面那些题在问的事”），最后一个知识点说完直接结束
3. 不在内容前面贴标签，不宣告规则。两种高频变体：
   - **先行评价**：“原因也很直接：”“有一个关键的工程细节：”“量级决定方案”“重点来了”——读者还没看到内容，作者先下了判断或预告了重要性。直接删掉标签，事实自己会说话
   - **分类引出**：“设计了三个执行路径——”“两层压缩机制，分别是——”——先宣布数量和类别，再用破折号或冒号引出列表。改法：去掉分类标签，直接描述每一项做什么（“其中 ReAct 模式用于实时交互的短任务，Plan-and-Execute 模式用于需要分步规划的复杂任务”）
4. 正面说完不补反面：同一件事只从一个方向讲
5. 不借题发挥：题目没问的（选型建议、行业优势、自家项目的取舍反思）不答；诚实交底全文至多 1 处
6. 零金句不等于零观点：对具体功能的批评性判断欢迎（“说实话，这个命令不该有”），敢喷具体的点

**why 名额**：一题选 1-2 个最值得展开的 why（通常升级成 ####），其余知识点只留规则不留解释。旁枝机制（辅助算法、估算方法）宁可不讲。

**数字纪律**：锚点数字按题型出场（实现题 2-4 个、原理题可为零）；同一个数字全文只出现一次，放在最需要它的论证位；估算类数值用约数（“差不多占到 80%”），面试时没人报小数点。

**语言细则**：

- 口语缓冲词是加分项：“差不多”“假如”“而已”“可能也就”“就目前来说”
- 敢下最强判断，带时间限定：“就目前来说，Claude Code 就是最牛的终端 Agent”
- 对比用读者熟悉的参照物（“记忆库一千多条，RAG 知识库几十个 G”），参照物一摆结论自现；比喻看质量不看数量——精准的旧知识锚点（crontab 之于后端读者）是好比喻，通用陈腐比喻（整车/引擎、高射炮打蚊子）是烂比喻
- 自造的术语化短语（“优先级链”）换成平实动词短语（“按照优先级排列”）
- 同层对比定位法：定义新概念拉相邻概念并排划边界，一人一句话（提示词工程管“怎么说”、上下文工程管“知道什么”、Harness 管“能做什么不能做什么”）

## 表达纪律（面试类强制，2026-07-30 定稿）

1. **禁止凭空编造量化数据，包括时间估算** — “60% 以上”“50 行堆栈其中 45 行”这类没有出处的精确数字，面试时说了会被追问来源。只用有实测依据的数字，或者用模糊表达（“大部分”“很多”“差不多”）。时间估算和数量门槛也算编造——“48 小时”“两天写一个简单 MCP Server”“一周涨 2000 星”。在 AI Coding 时代开发速度很快，时间估算必须和任务实际难度匹配（一个简单 MCP Server 实现，有 AI 辅助一个多小时就能跑通）
2. **结论句不堆技术名词** — 判断句写清判断即可（“核心自己写，框架当工具库用”），不要在一句话里罗列具体技术栈（“模型适配层用 Spring AI，向量检索用 Milvus 客户端，但 Agent 的决策循环、状态管理……”）。技术细节在展开段落里讲
3. **不造生造术语** — 同 SKILL.md 格式硬规则。面试场景下尤其注意：自造的术语化短语（“优先级链”）换成平实动词短语（“按照优先级排列”）
4. **缩写和专业术语首次加中文** — 同 SKILL.md 格式硬规则
5. **用当下视角回答** — 2026 年 AI Coding 能力已经很强，“自研代价大，前期投入高”不如说“现在 AI Coding 能力强，自研门槛已经很低了”。面试回答要体现当下认知，不用两年前的视角
6. **用常见的书面用语，不用文绉绉或生造的词** — “地带”→“地方”，“缩小幻觉的发生面”→“减少幻觉的发生”（“发生面”是生造的），“扎实”→“好”（“扎实”太正式）。判断标准：这个词在正常书面表达里常见吗？不常见就换
7. **动词和形容词写全，名词不加多余后缀** — 该加的加：“交”→“交给”，“硬约束”→“硬性约束”。该删的删：“重排序层”→“重排序”，“生产化”→“生产”，“白名单围栏”→“白名单”。“层”“化”后缀和动作后缀（围栏、拦截）在不增加信息量时一律去掉
8. **不加不必要的修饰词** — “三个核心差异”→“三个差异”，“三级风险等级的”→删掉，“五维度”→删掉。如果去掉修饰词读者不少知道任何信息，这个修饰词就是多余的
9. **不用夸张对比** — “对协议的理解比读十遍文档都深”→“对协议的理解更深了”，“他们试新工具的速度比媒体快”→“看他们每天在研究什么新鲜的东西”。面试场景里夸张对比像在表演，直接陈述结果
10. **举例用面试公司生态产品，和候选人项目里实际用的一致** — 面试阿里用千问 Embedding（也是派聪明 RAG 项目实际用的文本向量模型），不用 BGE/M3E。面试小米就用小米系产品，面试字节就用豆包系产品
11. **称呼用更亲切的** — “同学”比“同事”更亲切。阿里内部互称“同学”，面试场景下用更亲切的称呼显得更融入
12. **回答不溢出候选人身份** — 候选人是工程师就不讲读论文，回答的学习方式、思维方式要和岗位身份匹配。“读论文”不是工程师保持技术敏锐度的典型方式
13. **对话体里不加过渡句** — “但光看不行”这类桥接句在对话体里多余。对话本身的问答节奏就是最好的过渡

## 简历纪律（面试类强制，2026-07-30 定稿）

- 每条直接写“做了什么 + 结果”，不加包装前缀（“设计幻觉控制流水线，集成……”→直接写“集成……”）
- 不堆限定词（“三级风险等级的人机审批”→“人机审批”，“五维度评估框架”→“评估框架”）
- 不重复表达（“保障质量不回退”=“保障质量”，“不回退”多余）
- 名词后缀同表达纪律第 7 条（“生产化架构”→“生产架构”）

## 技术细节尺度（面试类强制）

遵守 SKILL.md 格式硬规则（禁止自定义类名，保留标准库和业界术语）。面试类额外强调：

- 讲**原理和思路**，重点是**为什么这样设计**、**解决了什么问题**
- 面试时不可能记自定义类名，用通俗功能描述代替（“工具注册表”“预算管控机制”）
- 回答要像真实面试中的表述，不是在念源码注释

## Ending 写法（面试类强制）

写到事情讲完就停。不要强装升华、首尾呼应或时代意义。

**禁止以下模板**：

1. “以前拼八股文……现在问的是……”——已经用过太多次，读者一眼认出模板
2. “技术栈在变，但……没变——谁能……谁就是稀缺的”——同上
3. 前言收尾句逐字复用到 ending——ending 必须从当篇的内容中自然长出来

**怎么写**：

- ending 里的判断必须从这篇文章的题目中来，不能是放进任何一篇面试文都成立的万能句
- 一两句话收完即可，不用三段式（回顾 + 金句 + 加油）
- “下期见”可以保留，前面的内容不能套公式
