# 二哥风格 Remotion 视频

## 先定位本期风格

- **像素风**：用户说“像素风”“超级玛丽风格”或要求按横版游戏参考片制作时，读[像素风制作规范](references/PIXEL_STYLE.md)。正文独立展示图片或 GIF 时，默认使用分词器同款像素视窗，取景方式见[含图片的镜头](references/PIXEL_STYLE.md#含图片的镜头)。舞台、过关动作与素材安装见[第一章样例](references/APPROVED_PIXEL_CH1.md)。核对左右留白与顶部状态栏对齐，或制作连续编码、动图随口播、角色跳框、全图配局部时，查[第二、三章认可镜头与组件](references/APPROVED_PIXEL_CH2_CH3.md)。制作独立截图特写、区分示例输入与模型、安排角色表情、逐关升旗、原稿 GIF 与数据同步或五章串片时，读[像素风定稿与素材](references/APPROVED_PIXEL_FINAL.md)。需要追溯镜头或分析新参考片时再读[逐帧拆解](references/PIXEL_REFERENCE.md)。
- **小超风格**：此前已认可的二哥视频画风。在下方的章样例、共享组件和用户偏好中查对应镜头。
- **在第一章开工前确认画风。** 项目尚未选定时，问用户“第一章做小超风格，还是像素风格？”，收到选择后写入 `OUTLINE.md`。用户已在本次指令中点名画风时直接开始；续做项目沿用已确认的选择。试镜可作为选择依据。原稿、语音、事实取证、逐章审片与导出流程为两种画风共用。只研究参考片时可先交付拆解；短动作试镜放在项目 `preview/`，独立于正式章和配音进度。

## 共用工作流和小超风格样例

目录、命令、组件清单和素材清单统一在 [共享工作流](../../../docs/src/ai/script/shared/WORKFLOW.md)，画面偏好在 [用户偏好](references/USER_PREFERENCES.md)。

按已有经验直接制作，用户负责审片，提出要调整的地方再改。不额外扩展成逐条审稿；涉及具体公告、报告结论或测试数字的镜头，先找对应的一手证据再制作。交付时只说做了什么、哪里需要用户注意。

制作真实界面标注、输入发送或原图机制动画时，对照[已认可第一章样例](references/APPROVED_CH1.md)的成帧与源码，按[用户偏好](references/USER_PREFERENCES.md)选择载体和布局；样例用于理解视觉取舍，不要求所有视频复刻同一构图。

制作产品发布开场、竖版海报配动态演示、录屏放大镜或多种音效时，参照 [LongCat 第一章样例](references/APPROVED_LONGCAT_CH1.md)。单色框选、素材边界和音效取舍已合并到用户偏好；具体构图与帧号仅作参考。

制作官方原文叠加图标、多个本地动态 Case 或用户指定的 Mac 播放器窗口时，参照 [Hy4 第一章优化](references/HY4_CH1_REFINEMENT.md)。重点检查完整取景、实际内容占屏、同类窗口一致，以及换素材或重配后转场与提示音是否仍对齐；不把本例窗口和蓝色阴影套到所有截图。

优化场景衔接、连续运镜或引入花叔风格转场时，参照[已认可的连续转场](references/APPROVED_MOTION_TRANSITIONS.md)，复用共享 `MotionSceneChain` / `MotionPlane`。选择有内容交接的边界，读数与机制内部动作保持稳定；不把转场升级扩成重做已认可的场景。

制作原文证据接数值对比、截图阅读与连续聚焦镜头时，参照[已认可第二章样例](references/APPROVED_CH2.md)，尤其检查先框原文再展开数据、图文分栏与原文有效字号。

制作上下文、日志裁剪、摘要合并等机制或连续总结镜头时，参照[已认可的上下文压缩样例](references/APPROVED_COMPACTION.md)：用具体内容和对象变化解释机制，并检查变化前后仍应保留的关系。

制作模式对照、内容比对、规则评分或 Agent 接入时，参照 [Xiaomi-OCR-0 迭代样例](references/OCR_ITERATION.md)：让输入粒度、具体差异和处理结果随口播变化，不只切换标签或展示抽象分数条。

## 定位项目

1. 从仓库根目录定位 `docs/src/ai/script/<视频项目>/` 并解析为绝对路径；工具的 `--project` 传该路径，输出位置遵守下方文件存放规则。
2. 继续旧项目先跑 `doctor.py` 看 `progress`，再读 `script.md`、`beats.json`、`OUTLINE.md`。
3. 找不到路径时修正路径，不新增另一套配置、依赖或生成目录。

## 视频制作文件存放

视频素材和制作产物不得直接写入仓库根目录，执行命令的工作目录不是产物目录。

- 开始前确认当前视频项目的绝对路径：`docs/src/ai/script/<视频项目>/`，本机通过软链接对应 `ai-better/script/<视频项目>/`。生成、复制、下载、截图和渲染均显式指定项目内输出路径；工具的 `--project` 使用已确认的绝对路径，不依赖当前工作目录或工具的默认输出位置。
- 配音放入项目的 `audio/` 或 `build/`，素材放入 `assets/`，截图、录屏、检查记录与临时文件放入 `preview/`，Remotion 源码放入 `remotion/src/`，成片放入 `output/`；`project.json`、`OUTLINE.md`、`PROGRESS.md` 等也只写在该视频项目内。源稿仍使用本 Skill 原有的稿件目录。
- 额外交付副本放入仓库的 `outputs/<视频项目>/`，保留必要的目录层级；不把音频、JSON、TSX、截图或进度文件拍平复制到仓库根目录。
- 每次阶段交付前检查仓库根目录及 Git 变更。发现误写文件先核对归属、内容和引用，再归档或归位；不覆盖正式项目中的较新版本，不清理其他任务的文件。

## 流程节点

每个节点得到对应的用户回复后，用 `progress.py --mark` 记录。

1. **整理用稿**。写项目 `article.md`、`script.md`、`beats.json`、`OUTLINE.md`。文末公众号推广尾段连同后面的图片整段删掉，正文里的资料领取（288 道、222）和结尾点赞关注保留，源文章不改。原稿“视频封面”区块里的横版 16:9 封面（标题写“16:9 封面”或“宽屏横版封面”）下载为 `assets/images/cover-16x9.png` 做整片首帧。
2. **用户确认口播稿**，标记 `script`。确认前不合成配音。确认后按稿子制作，画面配合稿子讲。发现稿子和现行版本对不上，一句话告诉用户，由用户决定改不改。
3. **配音**。`pronunciations.py --write` 套用读音词典，再 `gen_audio.py`、`gen_cues.py`、`review_audio.py`（生成逐词对齐）。标记 `audio`。
4. **章节制作与审片**。整期由同一会话逐章制作和审片，见下节。第一章先按上面的规则确认画风。两种画风都保留逐步分镜：在 `OUTLINE.md` 按口播顺序列出每一步的 beat 与触发词、画面原状态、具体动作、落定状态和转入下一步的方式。每一拍先用当前讲到的内容安排主体区。新对象需要位置时，把已有对象如何移动、何时让出位置也写进分镜；未来才会出现的栏位、空框和底槽等到对应触发词再画。见[随口播移动主体](references/PIXEL_STYLE.md#随口播移动主体)。实配后对齐帧号，写入本章 spec 的事件；用户可以先读分镜，再在 Studio 按帧核看。先区分本章的事实证据与原理示意，按下方规则准备素材，并参照用户偏好的[场景构思](references/USER_PREFERENCES.md#场景构思)选择表达方式；再写 `ch<N>-spec.json`、生成时点和 `Chapter<N>.tsx`，跑 `chapter_pipeline.py`。工具报出的开口空画面处理掉，然后把 Studio 中的 `Chapter<N>Preview` 交给用户。逐章审片只用 Studio 预览和必要的静帧检查，不导出章节 MP4，也不以“备用”“验证”或“保险”为由额外导出。用户明确认可某章，或对单一待审章回复“继续”时，标记当前章已认可，再做下一章。
5. **出片**。只有用户明确要求“出片”或“导出视频”时才标记 `render` 并导出 MP4，整片渲染加 `--detach`。
6. **成片检查**。跑 `verify_export.py`，并从最终 MP4 抽帧复查封面、章节衔接、关键状态变化与片尾；检查因果表达和结果停留时间，通过后标记 `verified`。交付的是 `output/<outputName>`。
7. **纳入 Git**。`output/` 顶层只放最终 MP4，规则见 [成片版本管理](../../../docs/src/ai/script/shared/WORKFLOW.md#成片版本管理)。commit 和 push 只按用户明确指令执行。

## 逐章制作

整期由当前会话完成，不调用子 Agent。可以先定全片口播、时间轴和章节边界。画面一次只做当前章，沿用上一章已经认可的取景、字号、节奏和用户反馈。

1. 读本章口播，按触发词在 `OUTLINE.md` 写下观众应当看见的对象和变化。讲实测操作时先找实际界面、输入与产物，明确哪一段需要全景、哪一句需要特写。
2. 按本章 spec 和实配时点制作，接入同一个 Studio。检查手机宽度下的成帧，开声按正常速度连播本章，再交付 `Chapter<N>Preview`。在 `PROGRESS.md` 标为待审。
3. 用户给修改意见时继续修当前章。用户认可或针对当前章说“继续／下一章”后，记录认可，把这次调整带入下一章。要求重做多章时，按章号列入计划，逐章交付。

## 禁令

- 预览用完就关闭本次对应的 `agent-browser` 会话；完成、失败、取消或用户说“不用了”时均执行，并核实会话及其浏览器进程已退出。会话归属、关闭命令与保留条件见 [预览浏览器](../../../docs/src/ai/script/shared/WORKFLOW.md#预览浏览器)。
- 密钥只从 `config.volc.apiKeyEnv` 指定的环境变量读取，不写进项目、Skill、日志或命令参数。
- 不手改 `build/` 下的生成文件，不按字数估算时长。配音变化后重新生成时间轴和混音。
- 用户指定音色或语速只改当前项目配置；修改共享默认值、共享组件或读音词典，不批量重做旧视频。
- **定稿脚本不得擅改**。用户提供的已定稿脚本是制作依据；源稿、项目用稿、`beats.json` 中的口播与字幕均不得自行增删、改写或调整顺序。即使为了事实修正、表达优化、时长或画面节奏，也必须先说明拟修改的原句、改法与原因，取得用户明确同意后再改；“继续”“下一章”或“出片”不代表同意修改脚本。发现证据与脚本不一致时先告知用户，由用户决定。
- 配音按确认稿朗读，不自动加语气词。`text` 是字幕原文；`ttsText` 仅用于读音调整，不得借此改动内容或含义。用户指定的读音修正按其指令执行。
- 没有实际试听，不说读音已验收。
- 使用原稿配图时保持原样，不用简化图形替换，也不重新生成；事实镜头优先采用对应的一手素材。带边框时用 `fitBox` 按整图或完整目标区域的实际比例取景，边框里不露空白。
- 小超风格的自制画面颜色只从共享色板 `C` 取，卡片只用共享 `card` 或 `Card`；真实截图、论文与官方图表保留原色。
- 录制还原的界面文字、顺序和数字只取自录制，没录到的不补，两次录制不拼成一次。录制使用项目 `preview/` 下的临时目录。
- 录制、调用 API、翻安装包或源码核对这类实操验证，先问用户。需要调 API 时用 DeepSeek，不调用 Anthropic API。
- 不伪造品牌标志和硬件产品图，先用共享素材库，见 [品牌素材复用](../../../docs/src/ai/script/shared/WORKFLOW.md#品牌素材复用)。

## 事实证据与原理示意

- 插件或工具实测：从一次真实操作开始，跟着同一条输入走到成品、归档或验证结果。菜单取景、手机读字与证据记录见[插件实测怎么拍](references/PLUGIN_WALKTHROUGH.md)。

- 知乎资料直接用 Codex 内置浏览器访问；需要登录时告知用户，由用户导入 session 后继续。具体做法见 [官方证据素材](../../../docs/src/ai/script/shared/WORKFLOW.md#官方证据素材)。
- 讲“官方发布了什么、报告写了什么、测出了多少”时，主动查对应官网、原论文或官方仓库，展示真实网页、原文页段或官方图表；品牌标志、手绘卡片、箭头和大数字不能充当证据。搜索摘要只用于定位，不能当作出处。
- 通过原始页面或原图建立依据，再按配音放大关键句或标出图中数据；保留原文中的日期、版本、实验条件、“约”“初步结果”和数值区间等限定。出处信息保存项目记录，不另外在截图外加来源行；画面只留辨认对象与数据所需的标注。做法见 [官方证据素材](../../../docs/src/ai/script/shared/WORKFLOW.md#官方证据素材)。
- 解释机制、教学类比和算式时继续用动画；示例概率、容量估算和教学构造的假设与边界写进项目来源及审片记录，不冒充某个模型的真实输出或实测结果，也不因此在画面加“示意”标签。不要把所有原理动画都换成网页截图。
- 找不到支持当前说法的一手证据，或原文与确认稿不一致时，明确告知用户，不用自画图补出“证据”，也不擅改配音。用户明确保留口播时，如实展示原始证据及完整限定，并在项目记录中保存出处和该选择。
- **像素风趋势图**。口播讲折线的增长过程时，默认采用已认可的[手机折线动效](references/PIXEL_STYLE.md#手机折线动效)：展开绘图区，让亮点沿原线推进，逐点显示读数，终点随口播停稳。交付前按手机宽度正常速度回放。
- **证据接原图，英文配对照**。逐项讲解且已有合适原图时，优先用官方原文建立依据，再回原图按口播圈选；英文关键段另配简洁中文对照与关键词划线。具体取舍见[证据与原图衔接](references/USER_PREFERENCES.md#证据与原图衔接)。

## 音画规则

- **配音单元**。beat 按完整句子或自然意群拆分，一个 beat 里可以切换多组字幕和动画。选择题的问句和选项合成一个单元。细节见 [音画对齐](references/AV_SYNC.md)。
- **读音**。上下文容量里的 `1M`（含「1M 上下文窗口」「1M 的长序列」）读「一兆」。配音前检查词典已写入对应 `ttsText`，字幕保留 `1M`。遇到作者名、网名或产品名中的多音字，先查已确认的读法；上下文和词典仍不能确定，就把原词和所在句给用户，直接问“这里怎么读？”。只暂缓受影响的句子。用户给过答案就直接采用，同时查中文名、重复提及和包名在 TTS 中的展开，不动字幕。先查 [读音词典](../../../docs/src/ai/script/shared/config/pronunciations.json)，用户指出的误读和指定的读法直接改并更新词典。Git 统一按单音节 /ɡɪt/；标准读音、已通过试听的完整句子和适用音色分开记录，失败提示从共享候选与自动替换中移除。依据与复检见 [Git 读音规范](references/VOLCENGINE_TTS_GUIDE.md#git-读音规范)。含“地”的句子先按词义区分 dì 和轻声 de，详见[“地”的读音](references/VOLCENGINE_TTS_GUIDE.md#地的读音)。其余方法见 [TTS 使用约定](references/VOLCENGINE_TTS_GUIDE.md)。
- **固定片尾优先复用合适的完整配音**。硬核目标读 **yìng hé**，同时“硬核知识”必须连贯；不默认添加逐字或词级 SSML。先核对已交付样本的完整句子、音色、模型、语速与哈希，再决定复用或重配，不能用 ASR 代替听感验收。见[硬核读音执行](references/VOLCENGINE_TTS_GUIDE.md#硬核读音执行)。
- **画面跟着配音走**。元素按配音提到的先后入场，在术语起音前 4 到 6 帧开始，之后稳定显示。每句话一开口主体区就要有相关内容。讲同一画面的相邻 beat 共用一个场景。
- **按完整意思安排镜头**。同一段机制优先保持连续场景，用高亮与状态变化推进；源码适合直接解释当前要点且能读清时仍可展示，不为每句话强插源码镜头。代码操作优先让变化发生在同一工作区的具体文件上，见[场景构思](references/USER_PREFERENCES.md#场景构思)。
- **字号与字重**。小超风格按已确认的[字号与手机端可读性](references/USER_PREFERENCES.md#字号与手机端可读性)排版：常规对象标签 34px、分组标题 40px / 字重 600，字幕独立保持 39px；不要把全部主体字都放大加粗。制作前核对复用组件的实际字号，放不下时减字、分组或聚焦，不缩小文字硬塞，也不批量重做已交付视频。
- **主体占屏与字幕间距**。插图和自制场景都按可用空间安排主体大小与位置，兼顾下半屏；枚举时按当前数量构图：一项做大，新项出现时已有项移动缩放。四个同级对象优先试两行两列；有方向性的流程或共轴比较可以横排。主体含阴影、标签及运动范围与字幕留出阅读间距。放大后复查密集状态、运动中段和结果，具体取舍见[版式](references/USER_PREFERENCES.md#版式)。
- **框选用单层纯色**。截图、图表和放大镜不叠白色外圈或第二道装饰线；新镜头的 `FocusRing` 显式传 `singleColor`。真实素材不默认套共享卡片，圆角素材不外叠直角框与偏移阴影；具体见[色调与卡片](references/USER_PREFERENCES.md#色调与卡片)。
- **默认不叠加画外小标题**。截图、导航和字幕已说明内容时，直接呈现主体；具体取舍与删标题后的布局见[版式](references/USER_PREFERENCES.md#版式)。用户指出一处时，回看本期全部章节的同类镜头。
- **所有章节都不新增“示意”说明**。不加“机制示意”“通信速度示意”“分片示意”“位宽示意”等标题、角标、窗口内说明或同义替代标签；教学边界留在项目记录中。完整规则见[画面文字取舍](references/USER_PREFERENCES.md#画面文字取舍)，交付前检查本期全部章节，删后重新安排主体位置。
- **不新增画外出处**。截图、录屏、插图之外不再加网站、作者、发布日期、版本或“原文 / 定价例子”等来源行，顶部和底部都不加；不得以“必要身份”为由另造窗口标题。原始素材自带的内容保留，出处与验证信息写入项目记录；只有用户明确要求才另加出处标注。
- **先验收文字取舍，再验收字号**。主体只保留辨认对象、区分选项与读取数据所需的文字。配音已解释的关系、公式和结论，用对象动作表达，不补成短句贴在画面上；逐项检查新增文字及其用途，并把实际删减与保留理由写入审片记录，详见[画面文字取舍](references/USER_PREFERENCES.md#画面文字取舍)。
- **小超风格的段位直接进阶梯**。闯关段落从口播开头就显示阶梯与登阶动作，省略头像加旗帜的闯关提示过渡；同一期各段位统一处理，见[闯关稿](references/USER_PREFERENCES.md#闯关稿)。
- **真实操作与连续对照**。讲 Agent 产品具体操作时，优先采用授权后的真实终端素材；原理讲解继续用动画。双会话比较优先固定两窗同屏，先全貌、再共同推近一次，给结果留出稳定阅读时间，再切换产品；不要在短句中反复切窗和重置镜头。素材与节奏细节见[真实录制演示](references/USER_PREFERENCES.md#真实录制演示)。
- **开源知识库沿用固定展示**。介绍王二讲 Agent 开源知识库时，默认左侧本期主题加二哥，右侧真实知识库录屏；先全貌，再按口播缓慢浏览，相邻自介与资料介绍共用连续场景。版式和共享素材见[开源知识库展示](references/USER_PREFERENCES.md#开源知识库展示)。
- **原稿配图**。按导航、字幕与阴影之间的可用空间等比铺放，不把组件默认尺寸当作上限；对照列退场后回收空间，详见[原稿配图与取景](references/USER_PREFERENCES.md#原稿配图)。在 `OUTLINE.md` 里写清每张图对应的场景、beat 和聚焦顺序。
- **提示音**。默认开启，按选择、数据出现、转场、聚焦和完成等动作选音，不全部使用同一种“滴”，也不每次移动都加声；音量低于配音。像素风换工作区、进出跑道及跨章接缝按[换景与声音同帧](references/PIXEL_STYLE.md#换景与声音同帧)检查：遮罩和提示音引用同一事件；同屏的重排、聚焦保持连续。用户说不要时关闭。见[提示音与转场音](references/USER_PREFERENCES.md#提示音与转场音)。

稿子里有“面试官问你”或面试追问时，读 [面试头像开场](references/INTERVIEW_OPENING.md)。普通科普稿不加面试剧情。

## 组件和素材

- 先用共享组件，清单见 [共享场景组件](../../../docs/src/ai/script/shared/WORKFLOW.md#共享场景组件)，小超章节从 `shared/remotion/examples/Chapter.example.tsx` 复制起步；像素风按风格规范建立世界层与字幕层，仍用相同音轨、章节预览入口和交付工具。
- 同一个场景或图标两期以上重复手写、且不含主题数据时，提升到共享组件并登记。
- 品牌图标、面试头像、提示音在 `shared/assets/`，用前复制到项目 `assets/images/`。
- 组件代码按 JSX 元素换行，单行不超过约 160 个字符，样式常量放在文件顶部。
