# 用户偏好

本文件只记视觉、字幕和人物偏好，Claude Code 与 Codex 共用。流程与禁令见主 Skill，目录与命令见 [共享工作流](../../../../docs/src/ai/script/shared/WORKFLOW.md)，读法见 [读音词典](../../../../docs/src/ai/script/shared/config/pronunciations.json)。

用户于 2026-10-28 明确认可《为什么不能在 System Prompt 里放时间戳？》第一章，作为后续同类镜头的视觉参考。四张成帧、场景映射和源码见[已认可第一章样例](APPROVED_CH1.md)。以下规则已合并这轮反馈；样例中的具体品牌、布局和帧号不作为其他视频的固定模板。

## 色调与卡片

- 背景是暖米色，全片一套色调，颜色只从共享色板 `C` 取：蓝色是主色，用于卡片边框、重点和数据；铁锈橙是强调色，用于警示、错误和对比项；绿色只表示正确或通过；深色写正文，也做字幕底和当前章导航；灰色写次要信息。不另起颜色，不用大红、亮橙和纯黑。
- 需要卡片承载时，统一用共享 `card`：直角、3px 蓝色细边、无模糊的灰色偏移阴影，底色比背景更白。说明卡、选项卡、配图聚焦边框都是这一种卡片，只在语义需要时换边框颜色。人物、器具与过程动画可以直接放在主体区，不为统一样式给每个对象套框。便签式的结论卡可以略微倾斜。字幕底、导航胶囊、消息气泡和头像保持圆形。
- 外框用于表达真实的分组边界。例如系统提示词、项目规则、用户提示词是三组独立输入时，每组用一个整体外框，统一左右边界与内边距，高度随内容确定，连线从框边接出；组内关键词不必各套一框。保留发包、汇合与到达等过程动画。
- 卡内确实需要类别、页码等标签时用 `Kicker`，不为使用组件而补标签。英文数字用 Arial、中文回落苹方（共享常量 `LABEL_FONT`），不用等宽字体排中文、不加宽字距，否则中文显得发散；小标签按原文大小写显示，不自动转大写（Agent、Pi、arXiv 的大小写本身有意义）；等宽字体只留给代码、命令、路径；代码里方法和选中值用蓝色，键名和字符串用铁锈橙。讲耗时、命中、对比、排名时，优先用 `Cards.tsx` 的分格进度条、排行表和便签结论卡，换模型、改参数这类动作用打字机效果演出来。中文不用斜体，强调靠颜色。

## 字号与手机端可读性

常规自制图示以用户于 2026-10-28 确认的系统提示词发包场景为字号参考：分组标题 40px、字重 600，标签和文件名 34px、常规字重，避免大字与粗体堆满主体区。下表对应 1920×1080 画布，其他分辨率同比例换算。字幕独立保持 39px，不要求所有主体文字都大于字幕。此前的[高信息量场景样例](mobile-typography-1920x1080.png)继续用于检查布局关系与阅读顺序，常规标签不再固定为 44px。

| 文字用途 | 字号 |
| --- | --- |
| 左上本期主题 | 31px |
| 章节胶囊导航 | 27px |
| 分组标题 | 40px，字重 600 |
| 文件树、文件名、对象标签 | 34px，常规字重 |
| 编辑器页签、代码正文 | 44px |
| 完成、等待、归拢等状态 | 34px |
| 需要突出的关键数字、结果计数 | 64px |
| 底部字幕 | 39px |

- 看最终画面中的有效字号，不能设好字号后再把整个容器缩成小字。常规标签保持轻重层级，不整屏加粗；复用组件存在旧字号时，按本表适配。代码与实录按阅读需要取景放大，开场主题、整屏金句可按叙事需要放大，普通数值无需全部用 64px。
- 主体只留必要的术语、对象名、数值、单位和状态。完整解释由配音与字幕承担，不重复字幕整句，不另加“V8 · 并发示意”“Multi-Agent · 委派示意”等说明标题；删除标题后回收空间，让主体上移、居中或适度放大。
- 多个对象放不下时，优先减字、分组或依次聚焦，再用简洁总览归纳；不靠减小字号保留完整目录、长代码和重复说明。默认值、适用范围等影响理解的限定要随对象保留。
- 原图、源码截图和实录不改写文字。需要观众读懂的局部通过取景放大到至少接近字幕的可读尺度，并保留完整关系与阅读时间；全貌镜头只建立位置，不要求观众读完所有小字。
- **截图小字先用足纵向空间**。左右布局中，宽而扁的截图让原文难读、上下却留出大片空位时，聚焦完整相关段落；需要时从官网真实窄屏版式重新采集更高、更清晰的截图，增加有效字号。不能把低清截图硬拉大，也不改写原文或拉伸图片比例。取景边缘留少量余量，避免边框压到笔画；按最终成帧检查清晰度和完整性，不只看截图宽度。第二章的具体视窗尺寸是样例，不是固定模板。
- 用信息最密集的镜头检查手机观看效果，核对溢出、遮挡和阅读停留。样例只确定字号层级，不要求所有章节套用三栏；右侧字号标注仅用于审阅，不加入成片。

## 画面文字取舍

- 新增文字只用于辨认对象、区分选项或读取必要数据，例如系统提示词、工具定义、价格单位、Token 0。术语也按此判断，不因为短或字号合规就自动保留。
- 关系、原理与结论优先由动作和配音承载，不再补上“前缀一致”“当前块 + 前面块的哈希”“Token 前缀 → KV”“追加最新状态”这类解释短句。用实际的相同数据、父子依赖、路径命中、分叉与断开表达；提问句展示正在发生的问题，不默认画成两个框加箭头、问号。
- 交付前逐项列出主体区新增文字及其用途；配音和对象动作已经说清的删除，删后回收空间、重新对齐。随后才检查字号、遮挡与可播放性。此项验收写入项目 review.json，不能仅凭类型检查和开口帧通过就交片。

## 版式

- 短视频优先按手机端观看设计：突出关键对象、连接关系和状态变化。先确定主体中心、对齐基线与两侧视觉重量，再安排留白；并列对象宜等距或等重，移除说明列后重新居中主体，避免卡片零散错落和无意义的大块空位。必要术语保留并可读，配音和字幕承担完整解释，画面承担直观演示。
- **非插图场景也用足主体区**。消息序列、缓存、选择题、产品对比等画面主体偏小、偏上，下半屏大片空着时，优先调整对象大小、两排距离与整体位置，让对象、连线和状态变化共同占据可用空间。保持字号与字重层级，不靠统一放大加粗文字、增加解释句或撑大空卡片填屏；按场景内容安排留白，不要求每一帧都铺满。
- **主体与字幕留出阅读间距**。插图和自制场景都按主体最下沿（含边框、阴影、标签及运动范围）检查间距；1920×1080 下通常留约 48–64px，其他画布同比例参考，不以“没有重叠”作为合格标准。画面较满时先上移或重排底部对象，兼顾上方对象间距，必要时再适度收小主体。
- **放大后复查整组关系**。同时检查布局最密集的状态、运动中段和稳定后的结果：长标签按语义分行，选项徽章与图标留出间隔，连线接在对象边界且避开文字，底部提示与字幕保持间距。用户指出一处时检查本期其他同类场景，不批量修改旧视频；不因视觉重排改动确认稿、配音或字幕时点。
- **原文与少量对比项适合左右分工**。需要同时保留证据和两组数据时，可将原文放左侧，右侧上下排列对比项，标签、色块起点、单位与价格共用对齐线。分栏后仍要保证原文可读，不能为了保留全图而压成细长的小字条；数据和原文的视觉中心协调。此布局用于证据加对比，不套到所有场景。
- **默认不加画外小标题**。顶部导航、截图本身、图内对象和字幕已说明内容时，直接展示主体，省去“DeepSeek 官方 API 指南”“官方搜索语法”“官方模型与价格”“任务执行示意”这类额外说明。保留对象名称、单位、日期、对比项和原始截图内的文字，不能按字号或 `Kicker` 组件一刀切删除。开场建立主题或需要突出结论时仍可按叙事保留主标题。删掉标题后重新居中、适度放大或上移主体，保持图片比例与连线连接，避免留出原来的标题空位。用户指出一处时检查本期全部章节，不批量修改已交付的其他视频。
- **截图外不再加来源行**。不在顶部、底部或另造的窗口标题里添加网站、作者、发布日期、版本、“原文 / 定价例子”等出处文字；这些信息全部写入项目记录。不得把它归入“必要身份”而破例添加，用户明确要求时才加。原图和真实界面自带文字、状态栏与数据条件保持原样；口播字幕和章节导航照常保留。字幕之外也不堆制作说明或免责声明。
- 表达多条输入合并时，在可见区域接到同一个明确的汇合点，再连入目标；互为备选的路径按选择关系表达，不画成同时合并。线端与对象边界对齐，避免连接点藏进卡片、看似相交却没有接上，或多余线段穿过文字。
- 顶部是完整的章节胶囊导航 `ChapterStrip`：左侧本视频的简短主题名称，前半深色（`C.ink`）、后半蓝色（`C.blue`），沿用 Computer Use 的双色样式；主题文字按用户确认的用词，所有章节一致，不替换成固定栏目名、作者名或自行概括的新标题。右侧全部章节，当前章蓝底白字（`C.blue`，和底部进度条的当前章同色），已过章节浅灰。底部字幕条保持深色，不改蓝。章节名称和数量随内容变化，不用当前章编号代替完整导航。
- 画面底部画按章节分段的进度条：给 `ChapterShell` 传 `progress={CHAPTERS}`，每章一段，长度按章节时长比例，当前章逐帧填充，字幕自动上移让位。正文、开场和结尾都保留。
- 视觉表达优先于大段文字。信息密度来自对象、关系和步骤，不能用几个字母方块代替完整技术图。金句和术语可以用大字整屏。
- 画面不复述字幕。底部字幕已经有的整句、问句和结论，画面上不再写一遍。只有文字、没有图形的场景要改成图示，比如对象、箭头、状态变化或数值图表。画面上的文字只用关键词、数值和标签。
- 原稿信息图里的解释文字完整保留。自制图形保留理解所需的对象、标签、箭头和中间步骤。
- 问题导览卡用短标题、简短说明和语义 SVG 图标。缓存、书架、显存容量这类示意要保留读取、追加、匹配、增长或压缩的动作，不全部简化成文字卡。
- 机械结构和物理示意用 SVG 或 div，不用 emoji 代替。横向运动的图标朝向与运动方向一致。
- 面试对话主要靠角色和语义动画表达，避免和底部字幕整句重复。学习资料领取和自介按实际内容安排；相邻的王二讲 Agent 开源知识库介绍沿用下方固定布局，不硬拆场景，画面上的领取提示不重复字幕整句。

## 场景构思

- **一个完整意思共用连续场景**。镜头按语义转折安排，不跟着每句字幕重置；同一 beat 包含两个意思时，在转折处换载体，不因音频未分段而强行沿用前一个画面。例如知识截止与旧信息只承接引入句，开始讲时间戳失效就转入对应原图。解释连续机制时保持对象位置，用高亮、顺序和状态变化推进，给结果留出稳定阅读时间。源码核对负责保证准确，关键行适合当前讲解且能读清时才展示，不为每个术语强插源码。样板见已认可第一章和 multi-agent-file-conflict 第三章。
- **发送、合并与失效要有过程**。让观众看到内容按讲解顺序归组、收拢、沿通道移动、汇合与到达，再显示后果；动效不能只剩文字框淡入和静态箭头。通道上的“HTTP POST / JSON / 等待请求”等说明，仅在协议本身是讲解重点时添加。模型可用对应官方标志识别，在工程机制镜头中不额外拟人成动物或机器人；通用模型与具体品牌按稿子区分。Three.js、SVG 或实录按所需过程选择，场景复杂度不代表表达清楚。
- **代码操作在同一工作区演过程**。文件修改、查找替换、覆盖和交接，优先采用稳定的编辑器或终端布局，让光标、选区、行内差异、匹配数量和结果状态承载变化。例如 price 从 20 变成 30 后，oldText 匹配为 0，文件保持 30；另一案例只修改目标外的 title，随后价格替换成功，两处修改都保留。避免为输入、文件和结果分别堆框再用箭头连接；框图仍适合解释结构。真实录制与机制示意分别标明，不能把自制工作区当成产品实录。样板见 multi-agent-file-conflict 第四、五章。
- **机制工作区要有具体内容**。讲上下文、日志、摘要或缓存时，优先展示可辨认的用户任务、文件路径、命令、日志和摘要内容，让裁剪、覆盖、合并直接发生在这些对象上；只有“任务 / 对话 / 工具返回”等字加空框，不能代替具体过程。教学示例可构造，窗口内简短标明“机制示意”，品牌用现有正式素材；不要宣称是产品实录，也不把教学文件名、布局或角色标签当作真实存储路径和协议。示例边界写进项目来源记录。
- **检查变化后仍应成立的关系**。按当前机制核对被改变的对象和应保留的对象，既看中段，也看最后结果。例如工具调用与返回在切分、替换后仍需成对；事件日志只追加时，原条目继续存在；规则重新注入改变的是上下文副本，磁盘文件保持；合并新进展时，仍成立的目标、路径和待办不丢。移动文字会与源内容或目标内容挤在一起时，用移动选区、载荷标记和目标行更新承载过程，不叠放重复文字。
- **数值比较共用尺度，条件跟随对象**。比较容量、阈值或剩余空间时，使用同一起点、单位和比例的标尺，扣除、取小和重估用位置变化表达。保留“约”“默认”“缓存有效时”等成立条件，以及大于号、头尾保留范围等边界；示意消息行数不冒充真实 Token 比例，动画量条不冒充测量结果。需要逐项讲原图时通常只保留当前框选；共同对比所需的多处高亮可以同时存在。
- **连续过程的总结可以回到同一对象**。几步总结讲的是同一份上下文、文件或任务时，优先复用具体工作区，依次演出裁剪、落盘、填模板、合并和保留；对象位置与未变内容保持稳定，最后留出结果阅读时间。四张图标卡或序号卡适合独立分类，不默认用于替代已经能演出来的操作。成帧、实现入口与审片范围见[上下文压缩样例](APPROVED_COMPACTION.md)。
- **同类信息逐个加入，再同屏对照**。口播连续列举少量报告、案例或方法，且它们共同支撑一个意思时，优先固定各自位置，按起音依次加入；已出现的内容保留，当前项用颜色或边框突出。最后一项出现后，利用本段剩余口播保留完整对照，不立刻切走。例如 Kolibri → Google Gemma 2 → Anthropic 三份真实资料逐行加入，最后同屏。需要细读原文时仍可单独聚焦；同屏导致小字难读或对象过多时，分组展示，不强塞一屏。
- **一个主体面对多条选择**。讲“同一个新模型选择哪种学习方式”时，保留一个新模型，把互联网数据与顶级模型作为两条备选路径，随口播依次强调，并用问号或停顿保持待选择状态。只有确实比较两个不同对象或结果时才复制主体；不要把一个主体的选择画成两套重复流程，也不要在提问阶段擅自选定答案。
- **具体类比用过程动画承接**。口播出现可直观演示的实验、烹饪或机械类比时，优先考虑让观众看到过程，而非继续使用通用人物卡和箭头。先让对象可辨认，再演出连续因果：蒸馏实验可用加热冒泡 → 蒸汽沿管流动 → 冷凝 → 滴落收集，涟漪与液面增长跟着滴落发生。质感来自材料、流动和状态变化；文字只留必要术语，再接回技术主题，不把类比当作模型真实运行机制。是否采用取决于口播与时长，不为每个概念硬加实验镜头。

## 原稿配图

- 涉及官方公告、报告结论和测试结果时，优先展示真实官方页面、原文段落和官方图表，再聚焦证据。不要用模型标志加几张框图来代替真实出处；机制解释仍可用动画。采集与出处记录见 [官方证据素材](../../../../docs/src/ai/script/shared/WORKFLOW.md#官方证据素材)。

- **配图用足主体区**。按当前导航底边、字幕顶边和左右安全边距计算可用区域，再用 `fitBox` 等比完整放入原图；共享组件的默认区域不是尺寸上限。上下左右仍有可用空间时，优先扩大取景框、收紧留白，让原文更易读；把边框和偏移阴影一起计入安全间距。宽图优先用足宽度，高图受高度限制时允许两侧留白，不拉伸或裁掉原图来填满屏幕。
- 1920×1080 的布局参考：导航底边为 134px、字幕顶边约 935px、卡片阴影偏移 16px 时，可从 `{left: 72, top: 144, width: 1776, height: 720}` 计算取景框，含阴影下沿为 880px，与字幕留约 55px。数值只作参考，随实际导航、字幕和画布调整；同一期共用项目内的可用区域定义，不为单期布局修改共享默认值，也不批量改旧视频。
- **边框紧贴图片，不留空白**：配图要么不加边框，要么边框把图片包裹完整。带边框时用 `fitBox(原图宽, 原图高, 最大范围)` 得到和原图同宽高比的取景框；推近的焦点窗口也尽量取和原图相同的宽高比。`FigureFocus` 会保证图片始终铺满边框，但取景框比例不对时会裁掉边缘，所以先用 `fitBox`。
- 整图展示也套共享卡片外框（蓝边加偏移阴影），画面更立体，和蓝色章节胶囊是一套视觉。外框必须紧贴图片：用 `FigureFocus` 加 `focus={FULL}`，取景框用 `fitBox(原图宽, 原图高, 本期可用区域)` 按原图比例算，不要用固定区域加 `objectFit: contain` 的写法（`FigureCard` 的 `plain={false}`），那样窄图两侧会露空白。
- 不加无关的扫光和旋转，不重新生成图中人物。
- 同一张图能讲清当前机制时，连续使用原图，按口播依次框选、高亮、淡化无关区域，沿原图既有箭头添加流动标记或短转场，不重新挂载原图，也不另造一套重复的文字卡。保留原文、数字、限定与完整因果关系；原图表达不了的动作再单独做原理动画。

### 证据与原图衔接

- **先建立依据，再逐项讲图**。讲几道检查、几种机制且原稿已有清楚的对应插图时，优先在引出这些项目的口播中展示真实官方原文，标出对应条目；逐项展开时切回同一张完整原图，按口播依次圈选，保留到这组内容讲完。不再为每项另画一套命令框、关卡和箭头；原图无法演示的因果变化仍可单独做动画。样板见 multi-agent-file-conflict 第二章。
- **原文中的数字先框选，再展开图表**。先在真实原文内框住含完整对象、平均值、单位或范围的对应表述，再随口播在旁边展开比例或价格对比。相邻数据来自同一页面时，优先保留原图，连续聚焦下一段；图外数据等取景让出空间后入场。不把没有写在原文里的数字做成“来源支持的结论”；发现这种差异先说明，用户决定改稿后才重配受影响意群并重建时间轴。样例见[已认可第二章](APPROVED_CH2.md)。
- **英文证据配中文对照**。需要观众读懂的英文关键段落，先辨认来源，再聚焦完整段落；在原文旁边或下方另排简洁中文对照，划线强调少量英文关键词，并用对应颜色强调中文。译文保留条件、范围和限制，不把翻译改进官方截图里；较长内容随讲解分组，不靠缩小字号塞满屏幕。真实产品界面和终端输出仍照录制保留，不能用译文替换。
- **组内导航按需放顶部**。原图圈选已能标明当前项时省去额外导航；确实需要 A｜B｜C｜D 或同类短标签时，在主体上方等距、对齐呈现，只突出当前项，不在底部散放另一排步骤，也不为导航重复加标题。
- **让状态变化发生在真实对象上**。讲目录清理、文件出现或内容变化时，优先使用授权后采集的真实目录或文件前后状态，先给全貌，再聚焦变化对象；讲到清理时目录才消失，避免只剩“机器人＋无改动＋自动清理”文字。手动执行的 Git 清理标为演示，不能当作录到了产品自动清理；实际步骤、前后结果和验证范围写入项目来源记录。

### 配图镜头聚焦

原稿配图默认整图画框，只有满足下面条件才推近，用共享组件 `FigureFocus`。

- **推近的条件**：要讲的那一块是独立完整的一块，单独放大也能讲明白，并且能放大 1.5 倍以上、取景窗口不切到别的字。产品截图里看不清的菜单、按钮、终端输出照旧推近。
- **按完整关系决定是否推近**：流程图、分层图和多栏图默认整图展示；若聚焦会切断当前讲解所需的因果、对比或连接关系，就保持整图圈选。若能包住独立完整的一组关系，且放大有助于阅读，可以先全图建立位置，再连续推近、平移，讲完后按需回全图。例如先完整展示语义冲突图，再看左侧两份修改，最后平移至右侧“合并 → 检查 → 运行报错”的完整结果链，不逐个孤立放大节点。

- 先整图出现，让观众看到全貌；讲局部时先判断原图内框选是否足够，需要细读才平移放大，讲完或进入总结时按需回全图。
- 只移动取景窗口，不裁剪、不重绘原图。焦点用原图的归一化坐标 `[左, 上, 右, 下]` 写在关键帧里，切换点由逐词对齐的时点决定，每次缓动约 26 帧。
- 聚焦窗口要包住完整的一组内容，不切断文字和箭头。窗口下方紧挨着通栏文字时，宁可拉回全图，也不要切半行。
- **优先在真实对象上直接标注**。讲输入框、按钮、页签或原文位置时，在截图或录屏内框出实际区域，其他部分加遮罩淡化，区域旁直接贴简短标签，例如“用户提示词”；标签按屏幕有效字号 34px 放置，避开被读内容并随取景跟随，不把标注做成产品原生 UI。原图内标注与字幕能讲清时，主体居中，省去重复的右侧说明卡。
- 只有需要额外译文、独立解释或对照时，才用左图加右侧 `FocusNote`；说明不能重复原图或字幕。聚焦时保留图片边框（`FigureFocus` 默认 `framed`），取景按 `fitBox` 保持比例；不需要说明列时采用居中取景。
- **对照退场后回收空间**。右侧中文对照或标签讲完后，若要继续读图或源码，先让它们和不再适用的框选退出，再把取景框平滑展开到主体可用区域，不保留空说明列。放大过程保持原图比例和完整的相关句子、代码行与关系，检查全貌、运动中段和稳定后的画面，尤其避免标签在退场途中叠到正在展开的原文上。
- 一张图聚焦两到四处为宜，不来回晃。
- 并列多栏、表格需要同时比较时，保持整图，讲到哪一栏就用 `FocusRing` 框哪一栏，需要时贴小标签；当前比较不再需要上一栏时撤掉旧框。需要细读局部时按完整关系取景，保持容器稳定，避免邻栏切出半截或卡片忽宽忽窄。图外中文对照与标签优先等镜头稳定再入场，运动中段也要检查遮挡。
- `FocusRing` 的颜色取被框区域自己的颜色（蓝框用 `C.blue`，橙、红框用 `C.rust`，绿框用 `C.green`，色板里没有的颜色就近取），不统一改成深色。框和原图同色边框重叠也没关系，观众能看到框出现的动作就够了。
- 产品截图可以叠加鼠标指针、点击圆环这类操作示意，放在 `FigureFocus` 的 children 里，按原图百分比定位，随镜头一起移动。

## 真实录制演示

单窗口交互样板是 agent-user-interjection 第一章；双终端对照样板是 multi-agent-file-conflict 第一章的 Claude Code 与 Pi 段落。

- **具体操作优先真实终端**。讲 Claude Code、Pi 等产品的操作和结果时，优先复用本期实际录制；没有素材时按主 Skill 取得授权后录制。画面直接展示真实命令、工具调用、差异和文件结果，机制解释再接简洁动画，不用通用机器人框图承担全部产品交互。
- **先完整窗口，再聚焦**。先让每个终端的完整可见区域入镜，辨认产品、会话、输入和输出；保留可辨认的停留，再随口播平滑推近关键操作。双窗对照时两窗一起建立全貌、一起推近；聚焦目标固定在完整的一组关键输出，不追着逐帧重排抖动，完整保留要读的代码或数值。
- **短句保持同屏，结果留出阅读时间**。比较两个会话或工作目录时，固定 A、B 的位置，优先共用一个连续场景、一次缓慢推近。避免几秒内反复“看 A 全貌、推近 A、切 B 全貌、再推近 B”；按实际口播安排全貌、推近和停留，结果出现后稳定保持到本句讲完，再换产品。若时间不足，减少镜头动作，不把所有动作加速塞完。本次约 6.8 秒的 Claude 句子采用约 2 秒全貌、1.8 秒共同推近、最后约 3 秒结果对照，仅作节奏参考。
- **独立录制分别标明**。两边按实录 A / B 或真实会话名称标注，保留各自内容与先后顺序；并排剪辑不表示两次操作具有同步时钟，更不能合成一次共同会话。原始帧、时间映射、哈希和文件结果保存在项目记录；终端字符帧采集回放与原生屏幕像素录屏如实区分。
- 单窗口任务需要额外展示进度时，可用左侧深色终端加右侧白色状态栏（文件改动 N/6、测试）；双窗比较直接并排呈现，不强套一侧终端一侧状态栏。关键数字或修改结果按口播聚焦。
- 用户操作要演出来：插话在输入框里逐字打出、回车后进入排队；按 Esc 时弹出键帽。界面提示照录制原文显示（`ctrl+x ctrl+s to send now`、`Interrupted · What should Claude do instead?`），不翻译。
- 正反对照：讲“这样做不行”时切到对照录制（终端标签铁锈橙，状态栏列出没改的文件和失败的编译），讲“正确做法”时回到主线（标签蓝色），把结果跑完（测试通过）。
- 配音里的产品名和画面一致，画面换了产品就改稿重配那一句。

## 开源知识库展示

- 介绍二哥的「王二讲 Agent」开源知识库、视频原稿和 Agent 题库时，默认沿用 Kimi K3.1 Pro 第一章已认可的布局：左侧放本期主题名称（深色与蓝色区分层次），下方放二哥头像及名字；右侧用较大的真实飞书知识库录屏，保持共享卡片边框和原始比例。换视频只替换左侧主题，不固定成 Kimi，也不把这个模板套到所有第三方开源仓库上。
- 自介和相邻的资料介绍共用一个连续场景。先展示真实页面全貌，让标题、目录可辨认；讲到视频原稿与题库时再缓慢浏览相关内容，最后稳定停留。按本期真实音频定位动作，不照搬旧片的秒数，不随字幕重置镜头，也不加速滚动来塞满动作。只保留必要名称，不另外叠加整句口播、巨大题数卡、长链接或底部说明。
- 复用 [共享知识库录屏](../../../../docs/src/ai/script/shared/WORKFLOW.md#开源知识库录屏复用)，不重复录制未变化的页面。录屏里的题数和内容是实际采集快照；原稿与页面有出入时先告知用户，必要时更新录屏，不改写网页，也不为迁就旧素材改动已定稿脚本、配音或字幕。

## 转场与动效

- 场景切换用短淡入、轻位移或展开。元素在起音前入场，之后稳定显示。
- 连续讲解中的字幕切换不重复触发转场。按语义需要安排，不按每章固定次数填满效果。
- 入场与装饰效果保持克制，优先短入场（`SceneEntrance`）、语义图标和少量提示音；解释过程所需的冒泡、流动、滴落、训练状态变化等连续动作按语义制作，不受此装饰效果清单限制。
- 机制镜头验收同时看起音、运动中段和稳定结果，核对内容保留、配对、连线与字幕间距；类型检查和开口不空只是基础检查，不能证明机制表达正确。新增文字的用途、实际删减、示例边界及检查结果记入项目 `review.json`，不用每轮重复生成完整视频。
- 主体区不能空着等关键词，也不能只剩标题。先放这句话说的对象，再按配音展开：讲“这条消息也不是单独发送的”，先单独放出那条消息，讲到“同一条”再补外框；讲“并不全是用户发的”，先放来源打问号的消息，再按配音顺序揭开。选项卡、列表第一个入场之前的提问句，配一张表达本句含义的示意图。

## 闯关稿

- 段位口播一开始就直接进入阶梯，让头像登阶；30%、50%、70% 与最终段位等同类镜头统一处理，不在阶梯前再插入“头像 + 旗帜 + 学习闯关 / 继续闯关 / 最后一关”提示画面，也不为最终通关另加同类过渡。用户指出一处这类冗余时，检查本期其余段位镜头一并调整。口播、章节时长不因删除视觉过渡而改变；自介或结尾有实际讲解作用的头像照常保留。
- 稿子是“击败 X% 的学习者”加选择题的闯关结构时，关卡提示用段位台阶，二哥头像逐级上升；台阶的级数和百分比按稿子里实际出现的“击败 X%”来定（给 `LevelStairs` 传 `levels`），稿子没有的档位不画，台阶整体水平居中；选择题用选项卡，答案揭晓时正确项变绿，讲到“打在弹幕”时飘过几条弹幕。弹幕在画面上方两条轨道上，出现时错开铺开、逐条淡入，然后整体慢速匀速左移（共享 `Quest.tsx` 每帧 4 像素、坐标取整，快了播放时会重影看不清）。
- 选择题不显示“第 N 题”标签。提问时只放题目示意图，接着是选项卡。
- 段位台阶和选项卡用共享组件 `shared/remotion/components/Quest.tsx` 的 `LevelStairs`、`QuizBoard`。

## 人物

- 默认人物是 `shared/assets/ergo-avatar.jpg`，用户提供的黑框眼镜、黄衬衫、黑领带形象。用户指定素材优先。
- 科普示意里已经有学习者、老师或讲解者时，用二哥代表学习者，豆包代表老师或讲解者，替换通用线条小人。角色标签与稿子含义一致，不写成真实人物或产品的事实陈述。普通科普不因此增加面试情节，也不修改原稿配图里的人物。
- 角色素材用 `shared/assets/interview/` 的 `ergo-facing-left.png` 和 `doubao-facing-right.png`。人物面向互动对象或画面中心，这两张无文字头像可以镜像调整朝向。按视觉大小统一容器，保留脸、头发和识别特征，不遮挡文字、字幕或语义标记。沿用当前场景版式，不因为用了头像就套用面试布局。
- 圆形头像用 `objectFit: cover`、`objectPosition: center top`，保证脸和头发完整。完整人物图用 `contain`。
- 自介和结尾优先用 `HostCard`（圆形头像、铁锈橙细边、深色姓名胶囊），旁边放主题大字、结论和少量标签。二哥自介按稿子来，不加 `HOST` 之类的英文标签。

## 字幕

- 一次只显示一行，`whiteSpace: nowrap`。长句按完整语义分组，依次显示，保留原文顺序。不因为有逗号、顿号或“地”就切换字幕。
- 例如“英文全称 Reinforcement Learning，也就是强化学习”作为一组连续显示；“可以自信地、大方地、光明磊落地帮你搞清楚这三件事”不在“地”和“帮你”之间拆开。超过单行宽度时在自然语义边界拆分，不缩成难读的小字。字幕分组不要求重拆配音。
- 字幕可以隐藏 `——`，但不改实际朗读内容。
- 切换点由真实配音的逐词对齐定位，不用单独重合成的分句时长拼估。能量检测和 ASR 转写不能证明精确起音。
