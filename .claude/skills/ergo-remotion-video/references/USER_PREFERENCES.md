# 二哥呀视频用户偏好速查表

> 这是从 B19 → B44 迭代中沉淀出的用户偏好血泪教训。
> Claude 每次开工前**必须先读这份**，避免重复踩坑。

## 🚨 B27 最新沉淀（挨骂过 · 优先级最高）

<a id="anchor-A"></a>
### A. 字幕永远单行

**用户原话**："字幕我希望一行表示，实在表示不下就再另起一行，但画面只显示一行内容。"

- 画面**只显示一行**（`whiteSpace: nowrap`）
- 长句按中文标点（`，。？！：；、`）切成子行 · 按 beat 时长均分依次显示
- **`——` 破折号从字幕剔除**但音频保留破折号做停顿
- 实现：`shared.tsx` 的 `Subtitle` + `splitToLines(text, maxLen=28)`

<a id="anchor-B"></a>
### B. 默认按原文念；明确的数字读法通过 ttsText 指定

**2026-08-15 用户明确**："数字按规则改了中文读法，这个规则取消掉，按照文本内容来，我已经检验过我自己的文本了。"

- 默认按原文朗读，不批量转换数字或单位；用户明确指定的读法优先。
- **评论口令例外（用户明确纠正）**：「需要的可以来个222」中的 `222` 读作「二二二」，不能读作「两百二十二」。只在 `ttsText` 中写「二二二」，`text`、口播稿和画面继续显示 `222`。
- **数量读法例外（用户明确纠正）**：「288 道」读作「二百八十八道」，不能读作「两百八十八道」，也不拆成「二八八」。在 `ttsText` 中明确写「二百八十八道」，字幕与口播稿仍保留 `288 道`。
- 数量与评论口令分开处理；用户指定某个数字的读法后，必须显式写入 `ttsText`，不能继续交给 TTS 自行选择「二 / 两」。其他未经指定的数字不因本例而批量转换。

```json
{
  "text": "在这梳理了一份 AI Agent 开发学习路线和 288 道配套八股，需要的可以来个222。",
  "ttsText": "在这梳理了一份 AI Agent 开发学习路线和二百八十八道配套八股，需要的可以来个二二二。"
}
```

- 修正已合成片段的 `ttsText` 后，仅用 `gen_audio.py --only <id> --force` 重生成受影响片段；普通运行会复用旧 raw 音频。之后重跑 `gen_cues.py`，同步时长、合并配音和相关动画时点。验证朗读修正时同时检查字幕仍为原文。

<a id="anchor-C"></a>
### C. 「3 分钟」是 B 系列宣传话术（B44 沉淀）

- 口播稿里二哥自介一律说「今天用 3 分钟」，是统一宣传话术，不是硬性时长约束
- 实际视频长度看 beat 总数 × atempo 1.10 后的 TTS 真实跑出时长（B44 = 68 beat 约 4 分钟）
- 严禁为了凑「3 分钟」硬砍 beat 拼凑，该多长就多长
- 字幕也按原文显示数字，不做中文↔阿拉伯转换
- 用户自己会校验文本，Claude 不要擅自改写数字/单位

<a id="anchor-D"></a>
### D. 逐格填入 · 不要整块 stagger

**用户原话**："九个维度分别是，再一个个出现。而不是全部一下都出现。"

- ❌ 把 9 宫格一次性 stagger 全出场
- ✅ 分三层：
  1. 先讲数字（"9 个维度"）· 不出容器
  2. 空骨架容器登场
  3. 音频念到哪 · 一个一个填 label（spring 弹入 + 红脉冲）
- 相邻 beat 无缝动画时**后一个 beat 必须绕过 `wrapWithTransition`**（否则 crossfade 会让画面"重新出场"）

<a id="anchor-E"></a>
### E. 机械动画不用 emoji

**用户原话**："在压缩的时候丢了，压缩对应的图标能不能换一个，不够真实。"

- ❌ `🗜️` emoji + `scaleY` 挤压
- ✅ 自己画：两块厚黑压板 + 中间橙红被挤扁的卡 + 两侧红色 ▶ ◀ 箭头
- 通用规则：**涉及机械 / 物理 / 空间感的都要自己画结构**（div/SVG）· 不要用 emoji + CSS 变形凑合

<a id="anchor-F"></a>
### F. 硬节点纪律

**用户原话**："在 remotion 打开，你怎么直接渲染了，我还没有逐章验证。"

- 每章做完立刻起 `npx remotion studio` 让用户在 `http://localhost:3000` 逐 beat 走
- 起 Studio 直接 `npx remotion studio > studio.log 2>&1 &`（macOS/Linux）
- 用户明确回复"继续" / "chX 通过"才做下一章
- **绝对不能自己 render mp4 交差**（除非用户明确说"渲染"）

<a id="anchor-G"></a>
### G. 火箭方向要水平

**用户原话**："🚀 火箭应该水平飞过去。"

- 🚀 emoji 默认朝**右上 45°** · 想水平朝右必须 `rotate(-45deg)`（复合旋转要注意起点角度）
- 想朝任何方向前先在纸上画一下 emoji 原本朝向再算 rotate

### H. 项目路径 = 当前项目目录，不要另开 ~/Documents/video-projects/（B44 沉淀）

- 所有项目产物（稿子 / 音频 / Remotion 代码 / 配图）都在项目当前目录里（如 `docs/src/ai/script/kv-cache/`），**不另开工作区**
- 项目目录里建 `config/` 软链接指向 skill 根目录的 `config/`，单点维护 TTS 参数
- **禁止**在 `~/Documents/video-projects/`、`~/Documents/video/`、`~/Documents/GitHub/PaiVideo/projects/` 另开副本（历史遗留，不要再开）

## 🎯 铁律 · 违反必挨骂（B19-B27 通用）

<a id="anchor-1"></a>
### 1. 动画 > 文字
- **只有**这三类内容允许全屏中文字：
  - 金句 / 口诀（如"回家等通知"、"stateless · 无状态"）
  - 面试对话（微信气泡里的话）
  - 术语强调（`messages` / `undefined` / `1M tokens`）
- 其它一切都要用图形 / 动画 / 数据可视化 / 代码卡表达

<a id="anchor-2"></a>
### 2. 音频正常合成，不要为情绪加戏
**用户 2026-08-15 明确纠正**："豆包 TTS 的情绪，不要加情绪，就正常调用生成对应文本的音频就行。"

- 稿子按原文正常拆句，写什么念什么
- ❌ 不要为了"情绪起伏"往稿子里硬塞语气词（啊/嘞/你猜）、反问、破折号、感叹号
- ❌ 不要按"情绪曲线"改写陈述句
- TTS 自己会处理朗读，加戏反而不自然
- 调 TTS 时只传 text + speaker（+ 恒为 1.0 的 speed_ratio），不传 emotion 参数

<a id="anchor-3"></a>
### 3. 设计要克制，不要花哨
用户原话："**设计的不行呀！**" —— 通常是因为：
- 元素太多（满屏问号、放射线、舞台幕布）
- 意象不对（emoji 大脑、SVG 手绘脑、emoji 假装机械）
- 过度炫技（多层特效叠加）
- 反直觉（用户看不懂含义）

**克制的正确姿势**：
- 单个焦点元素 + 1-2 个辅助
- 沿用已有卡片模板（白底黑边框）
- 一个 beat 只讲一件事

<a id="anchor-4"></a>
### 4. 一次做不对，试 3 版找边界
用户不会一次告诉你想要什么。规律：
- 第 1 版：往往过头 → 用户说"不行"
- 第 2 版：往往还是不对 → 用户开始描述方向
- 第 3 版：命中 → 用户说"可以"

**教训**：不要一次到位，做完立刻让用户看。

<a id="anchor-5"></a>
### 5. 卡片风格必须统一
所有 "金句卡片" 沿用同款：
```
white background
border: 10px solid #0a0a0a
border-radius: 32
box-shadow: 14px 14px 0 rgba(10,10,10,0.3)
padding: 48px 80px
font-family: Noto Sans SC
font-weight: 900
```
入场：`scale 0.5→1 + rotate -8°→0°`（spring）

## 📏 视觉细节铁律

| 项 | 规则 |
|---|---|
| 底部留白 | ≥ 100px（B20 铁律，Scene 强制） |
| 顶部下移 | 元素被 ChapterStrip 遮挡 → 立即整体下移 80-100px |
| 字号上限 | 大字不超过卡片宽度 40%，避免撑破 |
| opacity 动画 | ❌ 无限循环脉动 → ✅ 一次进场 + 稳定显示 |
| 阴影 | 卡片阴影用 `Npx Npx 0 rgba()` 无扩散风格（B16 硬阴影） |
| 圆角 | 大卡 32, 中卡 20, 胶囊 999, 小卡 14 |

## 🎬 5 章模板（可按文本长度调整）

**核心原则**：章节数不固定为 5，beat 数完全由文本意群决定，不是硬性 71 个。

一个 beat = 一句口播 = 一个意群 = 一个视觉焦点，通常 1-5 秒。

| 视频总时长 | 参考 beat 数 | 建议章节 |
|---|---|---|
| 1-2 分钟 | 20-30 | 3 章 |
| 2-3 分钟 | 40-55 | 4 章 |
| 3-4 分钟 | 55-75（B25 就是 71） | 5 章 |
| 5-6 分钟 | 90-120 | 5-6 章 |

以下是 B25 用的 5 章结构参考（长文本适用，短文本可并章）：

| 章 | beat 数 | 基调 | 典型内容 |
|---|---|---|---|
| 1 | 6-8 | hook + 打脸 | 面试翻车 + 红章 "回家等通知" |
| 2 | 5-7 | 自介 + 预告 | 二哥出场 + N 分钟承诺 + 考 X 层预告 |
| 3 | 12-17 | 知识密度最高 | 底层原理，最多结构化动画 |
| 4 | 8-10 | 物理约束 | 窗口填满、Lost in Middle |
| 5 | 25-30 | 干货 + 收尾 | 3 种策略对比 + 口诀 + CTA |

## 🧠 用户口头禅词典（回复语气校准）

用户原话（B19-B25 中的原话）：

- "不行" / "笑死了" / "不好看" = 需要重做
- "算了" = 前面方向错了，回退
- "可以" = 通过，继续下一个
- "认真点" = 用户觉得设计敷衍，需要更用心思考
- "直接了当告诉我" = 用户想要结论，不要过程
- "**太单调了，很枯燥**" = 旧反馈，曾指引"加语气词/反问/破折号"；**2026-08-15 已废止**，TTS 正常合成即可，不要为情绪加戏
