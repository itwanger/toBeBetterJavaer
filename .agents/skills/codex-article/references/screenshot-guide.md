# 文章截图与配图占位指南

截图不是装饰。每张图只服务一个明确的证明目标：让读者看见原始证据，或者把纯文字难以讲清的关系画出来。

## 两类图片

### 证据截图

用于证明“这件事确实发生了”或“这个数字确实来自这里”，例如官方公告、模型页、价格表、状态页、源码、提交记录、测试结果和真实产品界面。

- 优先截一手来源，不用二手文章的自制图代替官方页面
- 保留能识别来源、时间、指标名称和比较口径的区域
- 一张图只承担一个主要结论；图后立即解释它能证明什么、不能证明什么
- 厂商基准和厂商案例仍标为官方口径，不因截图存在就升级为独立验证
- 文末把占位符名称映射到精确来源 URL；需要登录或自行操作时明确写出
- 类型固定写 `证据截图`，风格固定写 `evidence-crop`；只做必要裁切和标注，不重绘原始数据

### 解释配图

用于解释机制、流程、层级、取舍和决策，例如 Harness 如何影响模型、Agent 成本如何构成、A/B 测试怎样执行。

- 只从当前论点抽取必要元素，不把全文和无关历史塞进提示词
- 不重新绘制来源不明的精确数字；涉及数字时在正文保留来源
- 优先使用最小可用结构：关系用 `whiteboard`，卡片用 `skill-card`，数据比较用 `data-board`，层级用 `three-layer`，流程用 `swimlane`，行动边界用 `checklist-card`

## 固定格式

```text
【截图：<名称>；类型：<证据截图|解释配图>；风格：<evidence-crop|whiteboard|skill-card|data-board|three-layer|swimlane|checklist-card>；截图目标：<只写一个要证明的结论>；关键词：<关键词1>、<关键词2>、<关键词3>】
```

- 名称必须唯一且能和文末来源清单对应
- `截图目标` 写证明任务，不写“好看”“丰富页面”等装饰目标
- `关键词` 至少 3 个，只保留当前图直接相关的信息
- `证据截图` 只能使用 `evidence-crop`；`解释配图` 只能使用六种信息图风格

## 密度与位置

- 导语包含发布、价格、故障或结果钩子时，安排 1 张核心证据截图
- 每个承载核心论证的二级章节通常安排 1 张；只有存在多个独立证据块或认知转折时才增加
- 不为三级、四级标题机械配图；短小子节可由所属二级章节中的图片覆盖
- 超过 900 个中文字符且包含多个独立论点的章节可安排 2～3 张，全篇通常保持每 350～700 个正文中文字符 1 张图
- `参考资料`、`参考来源`、`截图来源链接` 等纯附录不安排占位符
- 截图紧跟它所证明的事实或紧邻解释起点，不把一章的图统一堆到结尾
- 连续两张图之间保留有信息量的正文解释；不要用多张图重复证明同一件事

## 来源清单

文末使用：

```markdown
## 截图来源链接

- <占位符名称>：<精确 URL>
- <解释配图名称>：基于正文已核验信息整理，无外部截图
```

官方页面会动态变化时，在正文或清单中保留核验日期。无法提供公开 URL 的真实操作截图，写明“需在 `<产品或页面>` 登录后自行操作”，不得虚构链接。

## 成稿检查

运行：

```bash
python3 .agents/skills/codex-article/scripts/check_article.py <文章路径> --min-chars 4000 --require-screenshots
```

机械检查会排除代码围栏、截图占位符和来源附录后统计正文，并检查类型与风格、二级章节覆盖、来源映射、编号标题和全局图片密度。最后仍需人工逐图确认：来源是否一手、截图目标是否被正文兑现、边界是否写清、图片是否放在真正的认知转折点。
