## 共同写作引擎

### 1. 具体事实

不要从行业背景开始。优先使用页面中的小变化、当天事件、反常识数字、可验证的亲历场景或原始声明中的关键词。开头 3～6 个短段内说明发生了什么，以及为什么与读者有关。

### 2. 一手证据

按官方资料、可复现实测、口径一致的第三方数据、社交媒体线索排序。截图出现后，下一段立即指出图中哪一处支持当前结论。原图不便比较时可以重绘，但保留来源和计算口径。

### 3. 人话解释

常用四种方式：

- 官方定义 → 日常语言 → 真实使用场景
- 它不是什么 → 实际做了什么 → 为什么得到这个结果
- 概念 → 旧做法的问题 → 官方案例 → 工程例子
- 数字 → 熟悉参照物 → 对成本或能力的影响

### 4. 作者判断

证据后回答：改变了什么旧认知、真正重要的变量是什么、它处在同行什么位置、对不同读者意味着什么。观点文先准确复述对方最强论点，再提出质疑，不要先嘲讽再找材料。

### 5. 边界与选择

主动说明比较限制、未知信息和替代解释。最后给出适用人群、模型分工、职责地图、风险防护或下一步行动。读者选择是文章交付，不是附带总结。

## 六种结构

### 单模型评测

`细节发现 → 新旧纵向对比 → 旧旗舰对比 → 同档横评 → 口径限制 → 价格 → 适用场景`

逐层回答提升是否真实、行业位置如何、值不值得用。不要只贴排行榜。

### 行业快评与价格战

`事件连击 → 核心数字 → 旧认知 → 反例 → 成本—能力关系 → 工作流分工 → 行业信号`

多个新闻必须服从同一个中心命题，不能做资讯拼盘。

### 故障与账号治理

`当前故障 → 官方错误定义 → 状态时间线 → 历史稳定性 → 不同用户影响 → 深层治理风险 → 口径限制`

先回答发生了什么、为什么、影响谁，再讨论信任问题。

### 行业观点评论

`原始材料 → 准确复述对方主张 → 最强支持理由 → 核心疑问 → 利益与替代解释 → 反证 → 关键词拆解 → 回扣开头`

生活故事用于建立分析框架，不能当证据。主动寻找反例，防止确认偏误。

### 官方方法论解读

`官方强事实 → 读者疑问 → 核心概念定义 → 每章解决一个冲突 → 工程例子 → 职责地图 → 安全边界`

不要逐段翻译，重组为“以后什么应该放在哪里、为什么”。

### 热点与安全事件

`事件时间线 → 常见错误解释 → 客户端 → 服务端 → 外部系统 → 状态机 → 因果链 → 已确认/推断/未知 → 防御`

只保留理解机制所需的细节，删除账号、脚本、参数和操作步骤等可用于滥用的内容。

## 段落与情绪

- 一段承担一个主要信息点，大部分段落一到三句话
- 关键事实、判断和边界可以独立成段，但不要把所有句子切碎
- 主体用连续叙述，列表只放条件、价格、步骤、职责或归纳
- 评测和方法论保持低情绪，行业快评用中等情绪，事件现场可以短暂提高，技术分析必须降温
- 转场要推进问题，优先写“真正的问题在这里”“这个比较有一个限制”，少写无信息的目录式过渡
- 图放在版本对比、成本曲线、状态时间线、信任边界、状态机和完整因果链等认知转折点

## 事实边界

- 模型横评的版本、harness、推理强度、超时和上下文不同，只能看大致位置
- 账号数量不能换算为真人数量
- 员工个人签署不等于公司官方参与
- 评论截图只能证明存在这种声音，不能代表整体舆论
- 前端可观察行为不能证明后端内部实现
- 同期发生不等于存在因果关系
- 标题中的主体、动作与数字必须和原始来源逐项一致

## 不可复制的表层特征

- 公司昵称、固定自我介绍、固定三连和结尾口号
- “杀疯了”“笑死我了”“赚麻了”等高频情绪词
- 虚构“测了一夜”“朋友刚好遇到”的亲历
- 没有来源的损失数字、百分比和“全网舆论”
- 连续感叹号、省略号、问号和游戏黑话
- 为传播效果把相邻概念偷换成热门词

保留沉默王二自己的作者身份、经验与幽默。六篇样本提供的是调查和表达方法，不是另一个人的声音皮肤。
