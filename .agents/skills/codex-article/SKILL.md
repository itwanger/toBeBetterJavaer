# Codex AI 文章写作

这是一套独立的 Codex 工作流。不要读取、修改或依赖 `.claude/skills/ai-article`；所有规则和资源都从本 Skill 目录获取。

## 默认交付

用户只需提供工作标题和素材。自动完成：

1. 整理素材并展示映射
2. 联网或读取源码核验事实
3. 选择文章结构并形成内部大纲
4. 连续写完 Markdown 正文
5. 做事实、文风和素材覆盖检查
6. 成稿后生成 5 个标题并推荐 1 个

除非核心命题存在两种互斥方向，不要求用户选择风格。除非用户明确说“先看大纲”，不在大纲处暂停。

## 作者与输出

- 作者身份：沉默王二（二哥），程序员
- 开场第一句：`大家好，我是二哥呀。`，独立成段
- 默认保存目录：`docs/src/ai/codex/`
- 除非用户明确指定其他路径，不要把 Codex 文章保存到 `docs/src/sidebar/itwanger/ai/`
- 默认 Markdown 正文不少于 4000 个中文字符；这是提交底线，不是注水目标
- 正文以短段落为主，一段表达一个主要信息点；列表只放简短并列信息
- 二级标题使用 `## 01、标题`，标题只写名称
- 技术事实用准确书面表达，个人感受用自然口语

## 步骤 1：读取素材并建立映射

把用户给的标题视为工作标题，不直接锁定为最终标题。读取当前消息、附件、链接和用户指定的本地文件；只有用户明确指向时才读取 `sucai.md`。

先展示简洁的素材映射表：

| 素材项 | 类型 | 核验状态 | 计划落点 | 使用方式或不用的理由 |
|---|---|---|---|---|

素材是需求和调查线索，不是事实来源。每一项都要有去向；不能静默遗漏，也不能为了覆盖而把未核验说法写成事实。

## 步骤 2：先调研，再确定观点

联网调研时调用 `$web-access`。微信公众号链接优先使用 Playwright 读取完整正文。项目相关主张必须检查真实源码、测试或运行结果；时效性信息必须查询当日来源。

先列出 3～6 个调查问题，覆盖：

- 发生了什么
- 一手证据是什么
- 为什么会这样
- 哪些信息仍不能确认
- 对目标读者意味着什么
- 读者该怎么选或怎么做

按以下顺序取证：

1. 官方公告、文档、状态页、定价页、论文、源码与提交记录
2. 可复现的实测、日志、页面行为与截图
3. 口径可对齐的第三方基准或行业数据
4. 社交媒体、群聊与评论，只作线索或个例

核心主体、动作、数字和命题没有查清时，不进入全文。非核心问题无法确认时，将其标为未知并继续，不得脑补。

调研结束形成证据包，分开记录：已确认事实、厂商口径、第三方数据、作者实测、合理推断、未知事项。

## 步骤 3：选择结构

通读 `references/six-article-style.md` 的共同写作引擎，再按选题选择其中一种结构：

- 单模型评测
- 行业快评与价格战
- 故障与账号治理
- 行业观点评论
- 官方方法论解读
- 热点与安全事件复盘

安装教程和面试文章不强套六种结构，但仍执行证据纪律、短段落和事实边界。

内部大纲必须包含：核心命题、证据顺序、章节递进、事实边界、素材覆盖。多个新闻只能在服务同一个中心命题时放进同一篇文章。

## 步骤 4：按五拍写正文

默认使用这条推进链：

`具体事实 → 一手证据 → 人话解释 → 作者判断 → 事实边界与读者选择`

- 从页面变化、当天事件、反常识数字、真实场景或原始声明中的关键词切入，不从宏大背景起笔
- 截图或数据出现后立即解释它证明了什么
- 把英文术语翻译成真实工作流里的影响，不做词典式释义
- 证据讲完后给出鲜明判断，不能只做资料搬运
- 主动写清比较口径和未知信息，再给选型建议或行动方案

文风细则：

- 大多数段落用一到三句话，关键事实和判断可以独立成段
- 情绪只负责节奏，不能替代证据；进入技术分析后降低情绪强度
- 可以吐槽、反问、自嘲，但不得虚构亲历、朋友故事或测试时长
- 比喻只在确实降低理解成本时使用，避免连续造梗
- 技术断言必须有来源，推断必须出现“我的判断”“更可能”“目前无法确认”等边界词
- 不复制样本作者的公司昵称、固定 CTA、粗口、游戏黑话和标志性口癖

默认给文章安排截图与配图占位；用户明确说不需要配图时才跳过。配图前完整读取 `references/screenshot-guide.md`，区分证明事实的证据截图与解释机制的说明配图，把占位符放在对应论点附近，而不是章节末尾：

```text
【截图：<名称>；类型：<证据截图|解释配图>；风格：<evidence-crop|whiteboard|skill-card|data-board|three-layer|swimlane|checklist-card>；截图目标：<证明什么>；关键词：<关键词>】
```

## 步骤 5：落盘与自检

文章使用以下 frontmatter：

```yaml
---
title: # 成稿后回填
shortTitle: # 成稿后回填
description: # 50-120 字
keywords: # 5 个关键词
tag:
  - Agent
category:
  - AI
author: 沉默王二
date: # YYYY-MM-DD
---
```

用户明确不要配图时运行：

```bash
python3 .agents/skills/codex-article/scripts/check_article.py <文章路径> --min-chars 4000
```

默认运行：

```bash
python3 .agents/skills/codex-article/scripts/check_article.py <文章路径> --min-chars 4000 --require-screenshots
```

随后人工检查：

- 标题、主体、动作与数字能否回到一手来源
- 事实、厂商口径、实测、推断和未知是否混写
- 横向评测的版本、harness、推理强度、上下文、超时与计价口径是否可比
- 同期发生是否被误写成因果，账号是否被误写成人，员工签署是否被误写成公司表态
- 评论截图是否被错误扩大成整体舆论
- 每个核心判断前面是否有证据
- 每个核心二级章节是否有必要的占位符，是否避免为短小三级、四级标题机械增图
- 证据截图是否能回到一手页面，解释配图是否只使用当前论点所需信息
- 截图是否紧邻其证明的事实，是否避免集中堆在章节末尾
- 素材映射表是否逐项更新为已使用、核验后改写或未使用并说明理由

文末整理关键一手来源和截图来源。交付时附精简版素材覆盖与自检报告。

## 步骤 6：成稿后起标题

全文和事实检查完成后，读取 `references/title-guide.md`。生成 5 个角度不同的候选标题：直接新闻型、数据结果型、反常识判断型、读者收益型、克制专业型。

推荐其中 1 个，并说明它兑现了正文中的哪条证据。工作标题只保留为候选，不因用户先给出就直接采用。
